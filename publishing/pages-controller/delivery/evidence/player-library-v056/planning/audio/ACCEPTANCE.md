## Three bounded first slices, in order

### 1. Close the shared-master gap at the Studio preview boundary

Implement a small adapter from the existing session sound authority to Studio's audition element and quick master control. Start with Solo + Studio, preserving player volume/position, intentional music Pause, native audition controls and the f639 first-open focus correction. Do not replace the player or add a second persistence format. Make master Off dominate every output even when native preview controls change; enabling remains an explicit gesture with a truthful blocked result. A preview's local volume is multiplied by master state rather than rewriting stored music/SFX volumes.

Likely files: `game/ui/soundtrack-panel.mjs`, existing `game/ui/audio.mjs`/player mix interface only if necessary, `game/app.mjs`; relevant Studio/audio skill guidance after behavior is settled. Add actual host regressions for master zero/mute before preview and during delayed Play; resolve/reject after Pause, Mute, Close, hide and dispose. Prove no late unmute, surviving URL/voice, position loss or focus theft. Extend `soundtrack-panel`, `soundtrack-host`, `soundtrack-gain-leases` and relevant `published-audio`/`victory-story-ui` cases rather than duplicating their implementations. Then use one audible fixture for ordinary browser proof. This closes a bounded gap, not all-mode P02.

### 2. Adopt the same session/library contract in Versus and Team

Reuse `createSoundtrackPlayer`, Soundscape and the shared media-store adapter through small host bindings; remove the deliberate Versus custom-storage exclusion only when its read-only library adoption and cleanup are real. Add Team's explicit audio entry without modifying co-op simulation, independent progress, input latches or save authority. Preserve P01 boot/readiness notices and allow sound controls without leaking Confirm into flight. A full-page mode change must retain saved preference/library identity and obey browser activation; seamless cross-document song continuation is not implied.

Likely files: `game/couch/couch.mjs`, `game/couch/relay-rescue.mjs`, their existing HTML/CSS and finite host helpers. Target `couch-navigation`, `couch-shell`, `coop-host`, and a small shared host-audio regression as needed. Start with built-in plus two custom MP3s, lobby → Start → Pause → Options → Resume → result/Next. In each host verify independent master mute, music-only Pause, delayed completion, blur/hidden/re-entry, one active song and unchanged game state. Keep exact pack/theme music selection explicit; do not manufacture Solo ownership for Team. Audible browser checks are required in all three hosts before claiming consistent session audio.

### 3. Qualify one complete audible custom-library transfer and offline loop

Use two short, distinct owned recordings, one built-in synth, one duplicate entry and a corrupt copy. Record provenance, original byte lengths/SHA-256 and decoder facts before import. Exercise ordered/shuffle/repeat/seek and transitions, then a saved `.rlsound` and guided five-file set. Confirm actual native files, strict coverage verification, new-origin deliberate import/Undo/Save, re-exported original equality and cached offline Play/transition/export. Stay below existing media/staging budgets; do not load the 24-track album to prove this seam.

This slice starts as verification with the current serializers and UI. Make production fixes only for retained reproducible failures. Focused source regressions are `mp3`, `soundtrack`, `soundtrack-store`, `soundtrack-player`, `soundtrack-panel`, `soundtrack-host`, `backup-set` and `scripts/test-check-backup-set.mjs`; run affected whole files on Node 20 and 22 against the integrated successor. ## Evidence to retain for each slice

Record exact source/build/version/origin, browser/OS, fixture provenance and hashes; chosen playlist with duplicate entries; input method; storage state before/after; expected intent versus observed sound; delayed operation and failure sequence; actual downloaded filenames/hashes; offline preparation and disconnected state. Capture source tests and browser observations separately. A media clock/`paused=false` or decoded first frame is not proof that audio was heard throughout. A screenshot cannot prove silence, output routing or finished-track quality.

The existing `game/test/helpers/soundtrack-audio.mjs` explicitly models Web Audio/media events, and `soundtrack-fixtures.mjs` injects a structural probe. Its tiny coded-silence original has independent historical CoreAudio decode evidence, not browser/device/music-quality certification. Use those efficient fixtures for deterministic failure/interleaving tests; use owned audible media for the complementary native path.

Native chooser/download automation can prove selection and disk bytes where permissions permit. Audible audition requires an actual listening observation or captured output reviewed for that purpose. A desktop viewport or modeled pad does not qualify a real phone/controller. Do not claim Safari/iPhone, Bluetooth interruption, OS lock/background behavior, physical output routing or an album's final mix from the Node suite.

Retain existing limits: 32 MiB/12 minutes per MP3, 128 total tracks, 32 total playlists, 128 entries per playlist, 256 MiB managed bytes including staging, and the unchanged 64 MiB core offline budget. Use explicit optional installs and recovery; a 24-track collection plus all pictures need not fit resident storage simultaneously.

## Source-preservation details for P01

`createOperationStatus` owns status DOM only, not task cancellation, focus or writes (`6cfe:game/ui/operation-status.mjs:18`). Keep current-generation and cached-play observer identity: an old finally cannot clear a new notice. Keep the Studio's busy/abort/commit owner, top notice/Cancel, separate non-live music clock and audition token. `beforeAudio`/Play remain within the activating gesture before awaited reads. Delayed published cue decode stays cosmetic; its earlier event already used fallback and must never be replayed late.

Library's new task context exposes `signal`, `check()`, `phase()` and `commit()` (`6cfe:game/ui/library-panel.mjs:486`). Precommit Cancel aborts its candidate and releases that owner's UI. During commit, “Stop waiting” detaches observation while durable changes remain locked until the real result. P02 export/import work must not wrap these in a generic cancellation promise that reports rollback or enables a competing writer. Preserve prepared-vs-requested download wording, original filename/URL ownership and first-Back filename disclosure handling.

## Guidance and remaining phase boundary

The parent reviewed [MDN Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices) and [autoplay guidance](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay): retain media-element streaming for full tracks, bounded decoded buffers for short cues, gesture-bound start/retry and deliberate mute/volume. These support the proposed architecture; they are not playback evidence. [Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/ensure-no-essential-information-is-conveyed-by-sounds-alone/) supports retaining visual warning/impact/ability feedback when sound is off.

P02 remains open until shared controls, actual custom media, playlist behavior, persistence/transfer/offline use and the applicable campaign listening gates pass. The 24 finished-track target, physical-device matrix and later P18 full regression remain explicit. Keep the readable roadmap and current delivery register aligned when a slice is actually accepted; old `soundtrack-studio.md` 22/8/105 counts are historical component checkpoints, not the current full suite total.
