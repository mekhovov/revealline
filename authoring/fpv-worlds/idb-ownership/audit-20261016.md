## Current source findings

- World/region/record database names are fixed. Mode, input, language and the main
  entry path do not select another database name or factory.
- WorldStore closes on `onversionchange`, its explicit returned `close`, and a late
  successful open after the opening promise has already rejected. Region Library
  closes its owned store on disposal or a late result after disposal.
- WorldRecords closes on `onversionchange` or its returned `close`. WorldApp's
  whole-app disposal sets `disposed` before its final store cleanup; its generic
  error reporter ignores a disposed host. Normal flight disposal releases flight
  resources and does not close the World/record stores.
- Pause can asynchronously save recovery through `recordStore.saveSession`.
  Generic error routing retains only the message, so this is a candidate
  transaction in the recorded sequence, not an identified original stack.
- Current WorldStore listing waits for readonly transaction completion, projects
  `getAll()` and, if requested, the complete retained-revisions cursor. Failed
  reads reject. Regional refresh keeps the previous records and reports failure;
  it does not intentionally convert a failed read into an empty list.

The [IndexedDB specification](https://w3c.github.io/IndexedDB/#closing-connection)
distinguishes explicit closing from abnormal-close events. Passive close listeners
cannot identify ordinary explicit close calls. No observed native versionchange,
explicit closer or backend-close cause is attributed to the public failure here.
No production repair is justified by the current evidence.
