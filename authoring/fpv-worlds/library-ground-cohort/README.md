# Library cohort for supported ground movement

Players with actor `groundMotion: 'support-v1'` and surface-coating support now
request `published/ground-motion-v1/index.json`. The readable Library endpoint
and dedicated worker accept the same fixed first-party URL. Their checked
generated projections carry the change; all other request, hash, cancellation,
installation and service-worker behavior remains unchanged.

The new feed is empty. Both older feeds remain byte-exact, so this adapter does
not republish held Reservoir or Festival content, add a Harbor row, deliver
demonstrations, or update a cached player. The prerequisite movement runtime and
Harbor content remain separately owned changes. The human main-merge hold still
applies; no publication is claimed here.

When Reservoir's first row is approved, its exact reviewed row must populate
both the surface-coating and ground-motion feeds. Adding it only to the former
would omit it from discovery in newer players. Proof archives remain separate
explicit imports. See [the catalogue contract](../published/README.md).

The manual source contract passes 40 checks: exact readable-source change,
unchanged older feeds, unchanged closed row schema, old/new serialized worker
endpoint isolation, fixed immutable pack URL/hash validation and failed-response
refusal. This uses Node with an in-memory worker scope and stubbed responses;
it is not a native Worker, HTTPS, UI, storage or offline observation. The first
run stopped because the new empty JSON had a different whitespace encoding;
that observation is retained, and the file now uses the exact existing encoding.

The source measurement has 95 inputs and 16,744,040 bytes, leaving 33,176 bytes
under the unchanged 16 MiB ceiling. Only the generated reaction module (−18 B)
and worker template (−2 B) change in that inventory. No file policy or admitted
slot is added. Both projection checks, scoped lint and formatting pass. Fresh
full validation, all-three/two-build admission and actual native worker/cache
qualification remain pending; the source measurement is not their substitute.

The prospective native check should reuse the existing Library ownership/fault
fixture with exact admitted old/new players, prove each fixed index URL and
immutable download contract, cancellation/retry retaining installed content,
and separately observe the actual published feed. A verification-only catalogue
reply before publication must stay explicit. Root owns the browser and the
stopped-origin cached-player check; no device-wide outage or performance claim
is planned.
