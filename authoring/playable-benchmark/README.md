# Playable comparison

Serve the repository and open `/authoring/playable-benchmark/`. This source authoring tool runs one actual `createRun` / `stepRun` simulation through native `attachInput` and two independent `BoardPainter` instances. The second pane defaults to the approved FPV appearance with reduced effects. Both panes share the exact run; switching presentation cannot change movement, collisions, pressure, captures or results.

The current queryless Solo resolver chooses the route. The bounded cohort resolves `first-return`, `return-in-reserve` and `crossed-bands` from that exact source at standard difficulty. Before `createRun`, the benchmark applies the same pure `resolveGameplayTuning('standard')` / `applyGameplayTuning` path as ordinary fresh Solo play, exactly once. Retry reuses the owned effective level; personal admin overrides and saved preferences are not read. The page separates the authored mission revision/simulation identity and artwork pin from `setup.runtimeRevision`, `runtimeLevelIdentity` and the resolved tuning version. The level hash identifies the effective level, not a full run or cryptographic artwork pin. The original artwork loads through `acquireCandidatePicture`, which verifies byte length, digest, dimensions and decode before accepting a replacement. The reference always uses the same approved FPV lease and Journey identity adapter as the ordinary default view; the separate appearance pin shows its loaded revisions. Actor appearance goes through the renderer's dedicated option, preserving the mission scene palette and original. A failure leaves the previous run paused and visible. No procedural substitute is admitted for a missing original or approved actor lease. Artwork metadata's candidate review status is preserved; this tool grants no art or publication approval.

In **Mission setup → Second view**, explicitly choose the source-only **reference-v3** body-detail study, **reference-v4** battery-contrast study, or **reference-v5** optical-body study, each at native 32 px, native 64 px, or the renderer's automatic treatment. The approved appearance remains the default. Each named cohort loads only after selection:

- **V3:** `authoring/library/fpv-body-detail-candidates/manifest.json`; three fingerprinted construction modules (`rotor-body-detail-art.mjs`, `rotor-candidate-art.mjs`, `pixel-art.mjs` under `game/presentation/`). Its retained manifest describes Scout and Carrier; this option fetches only the two Scout PNGs.
- **V4:** `authoring/library/fpv-body-contrast-candidates/manifest.json`; the same three modules plus `rotor-body-contrast-art.mjs`. Its manifest contains exactly two Scout PNGs: **288 + 550 = 838 encoded bytes**. V4 composes the immutable v3 native recipe and changes only central battery-face colours. The old source, PNGs and manifest remain exact.

- **V5:** `authoring/library/fpv-body-optical-candidates/manifest.json`; the v3 construction modules plus `rotor-body-optical-art.mjs`. Its two Scout PNGs total **295 + 573 = 868 encoded bytes**. V5 broadens central equipment while retaining the camera, arms, motors, outer occupied bounds and moving-part rig. Earlier studies remain exact.

All three manifests use `revealline.rotor-body-detail-candidates.v1` and `source-candidate-not-runtime-default`, with separate construction and asset identities. The loader bounds the requests, verifies exact PNG lengths and SHA-256 hashes, checks header and decoded dimensions, validates the asset records, and requires the original reference-v2 pivot, hub positions, radii, blade counts, phases and directions. V4 also retains v3's occupied bounds and every silhouette pixel. It displays the observed manifest hash and candidate provenance separately from the approved appearance pin. A frozen image-only wrapper changes only the two Scout slots; all other actors delegate to the approved lease. The runtime renderer supplies the moving rotors. No registry, source PNG, mission binding or approved pin is changed. The current full-board observation is that v4's amber face is brighter, but its slim central silhouette remains weak at small play sizes. Neither brighter pixels nor successful loading establish art approval.

Candidate selection pauses the run and clears steering. Its previous accepted comparison stays visible through verification; failures, cancellation and stale results cannot replace it. Cancel returns to its visible Mission, Load or Actors opener; otherwise it uses the native setup summary or enabled Start/Resume without opening details or overriding unrelated focus. Resume is explicit. Retry retains the accepted comparison and resets its visual phase with the reference. Selecting approved actors releases candidate images; scene replacement and final departure do the same. Reduced effects is independent of body choice. The comparison-only **Capture pulse** and **Extra event flashes** toggles control those named accents; threat, active trail, contact, local loss, recovery and result information remain. They do not add audio, haptics or new simulation mechanics.

Batch 6 adds **Mission setup → Second view → Contact outline → Fine outline study** as an explicit comparison option. It narrows only the dark backing stroke from 3 to 2 in each renderer's existing units; the bright line keeps its existing width, and the complete circle's true centre, radius and foreground position stay unchanged. Solo uses logical renderer widths, so its 3/2 backing and 1-unit bright line scale with the board. Team divides by the CSS cell size, giving a 3/2 CSS-pixel backing and a 1 CSS-pixel bright line. The two paths do not imply the same physical stroke width. In this playable page the option affects only the second painter. The reference and production style default retain **Standard**. Changing the option pauses, clears steering and resets measurements without advancing the run; Resume is explicit and Retry retains the selected outline. Unknown style values fall back to Standard. This is an opt-in source study, not a saved player setting or production approval.

The accompanying prepared-Team correction draws its contact circle once in the final foreground pass. It removes the later duplicate filled centre dot that covered the prepared body and cue; the separate pilot identity badge and exact contact radius remain. This intentionally corrects Team's default prepared rendering as well as the optional style. Legacy fallback actors keep their existing contact drawing.

The existing outcome status now changes on meaningful core events. A `player.failed` event supplies its actual cause to the shared localized reason/tip helper; an ordinary life loss describes recovery within the current attempt. `player.respawned` replaces that explanation with a recovery confirmation, and `cells.claimed` replaces it with the captured-cell count and current reveal percentage when available. `run.completed` takes precedence over other events in its batch: a win remains a win even if the core retains an earlier failure cause, and a terminal loss offers Retry instead of promising recovery. Unknown causes receive fixed plain advice; raw cause codes are not displayed. Empty or unrelated batches leave the message alone, and unchanged text is not rewritten each tick. These messages use the one existing outcome status node and add no control, focus, timing, audio, haptic or storage behavior.

Start, Pause, Retry, native keyboard steering/boost, the default D-pad, an explicit optional canvas Swipe mode and the existing basic gamepad input reader operate the real core. Continuous steering and the input reader's fresh-gesture checks are retained. Terminal results announce once and offer Retry focus after 600 ms only if focus still belongs to the same play control. Intervening navigation cancels the focus offer. A deliberate fresh Retry press/release recreates the same mission and seed with Scout/immediate turns, resets both painters' visual phase, and clears held controls. Its 600 ms ready cue advances no simulation, then starts automatically; held steering still requires release and a fresh press. Pause cancels the cue. A long browser frame pauses instead of skipping simulation time. Hiding/departing cancels pending work and the RAF. BFCache return remains paused with one RAF; final departure releases the original picture, approved actor lease, painters and input listeners. This isolated host imports no profile, awards, save or replay recorder and writes no persistent/session storage. Locale initialization may read the existing language preference.

**Local performance comparison** is an opt-in, in-memory diagnostic. Both painters still run when the second pane is hidden. The intervals include the complete two-view host and browser scheduling; draw CPU measures submission only, not GPU completion, end-to-end latency or the ordinary game's FPS. No universal performance score is inferred.

Pauses, loading, the ready cue and background suspension end the timing segment; the first interval on return is omitted. Appearance, effects, size and setup changes reset the window, as does **Reset measurements**. Nothing is stored or transmitted.
