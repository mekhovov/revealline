# Playable comparison

Serve the repository and open `/authoring/playable-benchmark/`. This source authoring tool runs one actual `createRun` / `stepRun` simulation through native `attachInput` and two independent `BoardPainter` instances. The second pane defaults to the approved FPV appearance with reduced effects. Both panes share the exact run; switching presentation cannot change movement, collisions, pressure, captures or results.

The current queryless Solo resolver chooses the route. The bounded cohort resolves `first-return`, `return-in-reserve` and `crossed-bands` from that exact source at standard difficulty. The page shows route, project SHA-256, mission/revision, simulation identity, setup and original artwork pin. The original artwork loads through `acquireCandidatePicture`, which verifies byte length, digest, dimensions and decode before accepting a replacement. The reference always uses the same approved FPV lease and Journey identity adapter as the ordinary default view; the separate appearance pin shows its loaded revisions. Actor appearance goes through the renderer's dedicated option, preserving the mission scene palette and original. A failure leaves the previous run paused and visible. No procedural substitute is admitted for a missing original or approved actor lease. Artwork metadata's candidate review status is preserved; this tool grants no art or publication approval.

In **Mission setup → Second view**, explicitly choose the source-only **reference-v3** body-detail study or **reference-v4** battery-contrast study, each at native 32 px, native 64 px, or the renderer's automatic treatment. The approved appearance remains the default. Each named cohort loads only after selection:

- **V3:** `authoring/library/fpv-body-detail-candidates/manifest.json`; three fingerprinted construction modules (`rotor-body-detail-art.mjs`, `rotor-candidate-art.mjs`, `pixel-art.mjs` under `game/presentation/`). Its retained manifest describes Scout and Carrier; this option fetches only the two Scout PNGs.
- **V4:** `authoring/library/fpv-body-contrast-candidates/manifest.json`; the same three modules plus `rotor-body-contrast-art.mjs`. Its manifest contains exactly two Scout PNGs: **288 + 550 = 838 encoded bytes**. V4 composes the immutable v3 native recipe and changes only central battery-face colours. The old source, PNGs and manifest remain exact.

Both manifests use `revealline.rotor-body-detail-candidates.v1` and `source-candidate-not-runtime-default`, with separate construction and asset identities. The loader bounds the requests, verifies exact PNG lengths and SHA-256 hashes, checks header and decoded dimensions, validates the asset records, and requires the original reference-v2 pivot, hub positions, radii, blade counts, phases and directions. V4 also retains v3's occupied bounds and every silhouette pixel. It displays the observed manifest hash and candidate provenance separately from the approved appearance pin. A frozen image-only wrapper changes only the two Scout slots; all other actors delegate to the approved lease. The runtime renderer supplies the moving rotors. No registry, source PNG, mission binding or approved pin is changed. The current full-board observation is that v4's amber face is brighter, but its slim central silhouette remains weak at small play sizes. Neither brighter pixels nor successful loading establish art approval.

Candidate selection pauses the run and clears steering. Its previous accepted comparison stays visible through verification; failures, cancellation and stale results cannot replace it. Cancel returns to its visible Mission, Load or Actors opener; otherwise it uses the native setup summary or enabled Start/Resume without opening details or overriding unrelated focus. Resume is explicit. Retry retains the accepted comparison and resets its visual phase with the reference. Selecting approved actors releases candidate images; scene replacement and final departure do the same. Reduced effects is independent of body choice. The comparison-only **Capture pulse** and **Extra event flashes** toggles control those named accents; threat, active trail, contact, local loss, recovery and result information remain. They do not add audio, haptics or new simulation mechanics.

Start, Pause, Retry, native keyboard steering/boost, the default D-pad, an explicit optional canvas Swipe mode and the existing basic gamepad input reader operate the real core. Continuous steering and the input reader's fresh-gesture checks are retained. Terminal results announce once and offer Retry focus after 600 ms only if focus still belongs to the same play control. Intervening navigation cancels the focus offer. A deliberate fresh Retry press/release recreates the same mission and seed with Scout/immediate turns, resets both painters' visual phase, and clears held controls. Its 600 ms ready cue advances no simulation, then starts automatically; held steering still requires release and a fresh press. Pause cancels the cue. A long browser frame pauses instead of skipping simulation time. Hiding/departing cancels pending work and the RAF. BFCache return remains paused with one RAF; final departure releases the original picture, approved actor lease, painters and input listeners. This isolated host imports no profile, awards, save or replay recorder and writes no persistent/session storage. Locale initialization may read the existing language preference.

The authored six-second [feedback sequence](../game-feel-lab/) remains a separate diagnostic. This playable comparison does not replace a campaign, saved attempt, recorded replay, player setting or artwork binding. Workshop, Poltava and Synevyr artwork directions are future candidates, not the displayed mission originals. Full product shell, settings, audio/haptics, physical-device controls and player-study acceptance remain separate.

The distribution explicitly includes both candidate manifests, their four Scout PNGs and all four fingerprinted construction modules. The candidate files and rotor study modules remain optional Workshop tooling, with no expansion of any mode's core closure. The shared pixel-art module was already a core dependency. Packaging makes the optional study usable in the shipped tool; it does not register or approve the candidate as a runtime appearance. Carrier PNGs and generated concept images are not added by this option.

On small viewports the single-view layout preserves the complete primary board and touch controls. The optional second view is a review layout and may require scrolling; it is not a two-board handheld layout qualification.

**Local performance comparison** is an opt-in, in-memory diagnostic. Enable **Measure active play** to keep a rolling window of at most 120 active-play frame intervals, with p50/p95/worst intervals and synchronous JavaScript draw durations for each painter. Both painters still run when the second pane is hidden. The intervals include the complete two-view host and browser scheduling; draw CPU measures submission only, not GPU completion, end-to-end latency or the ordinary game's FPS. No universal performance score is inferred.

Pauses, loading, the ready cue and background suspension end the timing segment; the first interval on return is omitted. Appearance, effects, size and setup changes reset the window, as does **Reset measurements**. Nothing is stored or transmitted. Candidate memory lists encoded PNG bytes separately from a **20,480-byte lower-bound RGBA payload** for both retained 32×32 and 64×64 images, even when one native treatment is forced. The estimate excludes shared/approved images, mission artwork, browser decoders, canvas backing stores, GPU copies and other overhead; those costs remain unknown, not zero.

Serve the complete repository or distribution with these original mission assets available. A Workshop tooling download alone does not certify the three missions or their original artwork for offline use; this tool does not promote those assets into the core offline pack.

Focused checks: `node --test game/test/playable-benchmark*.test.mjs`. They exercise the actual standard-difficulty missions at `FIXED_DT = 1/120`, including capture/win, actual self-contact/loss, pursuit warning/commit/impact, heading interception and deterministic Retry. Host tests exercise native D-pad/swipe input, fresh steering/confirmation gates, delayed focus ownership and the ready cue. Resource tests verify the actual approved release transport, original/candidate digest checks, source fingerprints, geometry compatibility, visual phase reset, replacement rollback, cancellation, stale decode disposal and final release. A modeled canvas/decode host invokes the real BoardPainter for all seven approved/v3/v4 comparison choices at compact/desktop widths, standard/reduced effects and paused/running poses, preserving the original backdrop, contact radius and core checkpoint. The focused host checks also cover cancellation return targets and finite local measurement/reset boundaries. These source tests are not native browser pixel decoding, visual acceptance or human-play evidence. Full-board browser review remains necessary before any proposed production adoption.
