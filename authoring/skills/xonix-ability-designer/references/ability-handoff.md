# Ability and world handoff

Record the requested scope and actual runtime before writing accepted JSON. This is a review checklist, not a schema.

| Dimension | Record |
|---|---|
| Identity | Stable class/equipment ID; cosmetic IDs remain separate |
| Reference | Named model or category, source and date, maker/origin/operator distinction, narrow claim and uncertainty |
| Intent | Player decision and Xonix connection, not a list of real weapon capabilities |
| Trigger | Primary/contextual action, edge/hold policy, input mapping and focus/reset cancellation |
| Resources | Fictional units, capacity, pickup location/proximity, spend/refund order and cooldown |
| Targets | Ground/air/signal/objective domains; permanent/temporary change and legal misses |
| Movement | Selected turn policy; any explicit relocation must use authoritative state and defined bounds |
| Presentation | Body, parts, effects, trail/tether distinction, icon/sound; compact and detailed view |
| Lifecycle | Pause, lost focus, class/equipment changes, missing art and duplicate input |
| Theme | Equivalent role in FPV, Ukraine Atlas, 1994 and fictional business family |
| Integration | Reference-only, planned rule, working toy preview or real game adapter |
| Evidence | Validation, state tests, browser interaction, actual sprite inspection; physical-device tests separately |

For data changes use the existing format, then validate. For a new primitive provide the rejected unsupported request, the smallest registry extension, event semantics and a test level. Keep production capture, damage, objectives and collection results outside renderer callbacks.

For military personnel describe role and allegiance explicitly. Friendly medics, engineers, logistics and operators can be protected/delivery objectives; military adversary roles can become telegraphed patrols. A nationality or a civilian appearance is not an enemy behavior.
