# Session music and original MP3 libraries

Read `docs/soundtrack-library.md` for the versioned model, transport, byte preservation and actual limits; `docs/soundtrack-studio.md` for UI authoring. Resolve these paths from the project root. The runtime modules, not this guide, define accepted data.

- Use Settings → Music library & playlists for batch import, audition, metadata/provenance, editable playlists and Save & use. Imports stay drafts until the atomic save succeeds. Built-in genre playlists are synthesized recipes; they are not the planned 24 finished tracks.
- An MP3 import passes frame/hash inspection and a real media probe. Test fixtures with injected decoding establish structure only. Keep the original bytes, source records and any production master; never silently transcode a rejected upload.
- Library selection is explicit or Automatic. Automatic resolves map → campaign → theme → global, then authored track/built-in fallback. Automatic changes wait for song end; explicit selection fades now. Metadata edits do not restart the currently playing song. Use one transport owner and one Soundscape update per frame.
- Full transfer uses `.rlsound` and includes originals. Prepare the last loaded/saved generation, then use its visible **Download prepared backup** action; preparation alone must never download or dirty the library. Preserve retry without another export, one bounded Blob/URL, disposal/change invalidation, cooperative adapter cancellation, and explicit exclusion of draft edits. Game/profile JSON does not include uploaded audio. Check generation conflicts, rollback on quota errors, shared hashes, missing media and offline operation separately. A storage estimate is not proof of offline playback or indefinite retention.
- Music-only Pause retains effects and does not pause flight. Gameplay Pause retains music. Blur/inactivity suspends audio, and restoring listening never resumes gameplay. MP3 and synth both honor independent master/music gains; cues keep the master/effects bus. Audition restoration must retain intended playback through interruptions without starting a hidden tab.

Use the shared prompt CLI IDs `soundtrack-01-local-library`, `soundtrack-02-mixed-playlist`, `soundtrack-03-audio-production`, `soundtrack-04-continuity-check` and `soundtrack-05-backup-recovery` for applied examples. Render only the relevant template. Generated prompts do not create files, prove decoding or certify composition quality.

Run applicable model/store/player/panel/host tests; retain separate evidence for real file selection, MP3 decoding and playback, exact backup restoration, server-stopped offline operation, interruption recovery and listening quality. A completed content matrix must count actual auditioned tracks rather than rendered prompt variations.

## P02-A shared master candidate

Read [shared master audio](../../../../docs/shared-master-audio.md) for the current source contract. Master mute/volume are output policy; music Pause explicitly stops intended playback while retaining the selected track and position. Suspension handles focus/visibility or child ownership without turning a deliberate Pause into Play. An explicit host gesture may activate audio, but a queued completion must not enable master sound. Studio master controls remain available during library operations; Play/audition can change transport while muted and must explain that output is muted.

The page owns one injected `audioMaster`. Its optional media binding composes local volume × shared volume and local mute OR shared mute, also silencing zero volume. Native media controls cannot bypass that policy: explicit audition sliders call `setLocal`, and queued `play`/`volumechange` notifications only reassert current output. Preserve each audition's local fader when master volume changes. With an injected authority, stories ignore legacy master scalars for attenuation; callers without injection keep their existing behavior. Closing/replacing one preview must not dispose the page authority or the other preview's binding.

The host persistence adapter saves only `{ muted, volume }` under `revealline.audio-master.v1`; retain the existing profile/library/pack versions. It applies intent before saving, protects newer intent from late profile seeding, and checks storage key, storage area and current raw value before remote adoption. Refused storage leaves a truthful session-only setting, not a failed mute. Sharing this preference across pages does not transfer a playlist or authorize autoplay.

This candidate does not establish public P02 acceptance, new audio content or full device support. Keep model tests, native file decoding, actual audible mute/volume, navigation/history recovery and physical-device checks separate. Use the [cross-mode prompts](../../../prompts/cross-mode-delivery.md#qualify-shared-master-audio) for bounded race and multi-preview journeys; do not expand album production as part of this output-policy change.

Apply `soundtrack-05-backup-recovery` with this concrete test brief: “Use an owned MP3 fixture and a mixed playlist. Prepare a saved-generation backup while an unsaved playlist edit exists; confirm preparation leaves the draft and storage unchanged. Explicitly download, retain its byte hash, and import that file in a fresh profile. Verify original MP3 bytes and both ordered/shuffled queues, then test server-stopped playback. Exercise Prepare cancellation, discard/retry, old held Confirm, library-change invalidation and a refusing native adapter. Separate modeled activation, observed browser file creation and actual offline playback; do not diagnose the historic download timeout without evidence.”

For the explicit prepared-download flow, local browser evidence now includes real keyboard downloads, different-origin import/save/re-export, identical original bytes and a packaged cold offline restart. See `docs/verification/round-41/v031-media.md`. Repeat the applicable checks for the exact release and public host; coded silence and transport progress are not finished-music audition evidence.

## Optional licensed music collections

For public-source music, retain the creator's actual source page, license, original archive/file hashes, track titles and credits. Keep original RevealLine compositions distinct from licensed third-party recordings. An archive can contain both MP3 and OGG versions of the same song; count compositions once, not each encoding. Check ZIP integrity before extracting only the intended regular audio files into a bounded staging folder. Never execute bundled links or unrelated archive files.

A complete `.rlsound` import is a **replacement draft**, not an additive pack install. Two separate volume files do not automatically coexist. To offer a combined collection, explicitly author and validate that library and its playlists, then verify its exact original-byte bundle. Keep each optional theme/chapter collection near the existing 64 MiB target; the separate 256 MiB complete-backup ceiling does not guarantee device capacity. Shared committed-plus-staging accounting still applies during replacement. Do not add a large album to automatic offline preparation.

Verify native import and a settled `playing` state for each distinct song. Read metadata only after the import's actual codec probe, and retain ordered transition evidence. A saved assignment can leave the old song playing until the next boundary; do not mistake an immediate screenshot for the new song. Transport progress and short playback are not a full listening pass: assess loudness, clipping, loops, musical fit and cue masking separately before approving final content.

Applied request: “Prepare a CC0 retro-wave candidate library with exact original bytes, creator credits and an ordered playlist. Count alternate encodings once. Export one bounded `.rlsound`, import through the game's visible review/save controls, and observe every song starting with Next. Preserve the current song across library edits. Report archive, codec, transport, offline and musical assessment independently; keep these candidates out of the finished-track total until their production review passes.”

For level balancing, keep full-file decode, sample RMS/peak, perceptual loudness and listening as separate evidence. A low sample peak does not establish matching perceived volume between songs. Use proper loudness/true-peak analysis and a reviewed game-mix target; preserve original hashes and put any playback gain in an explicitly versioned runtime contract. Do not add unsupported gain properties to the strict existing audio-track format. [Primary loudness guidance](https://tech.ebu.ch/publications/tech3343).
