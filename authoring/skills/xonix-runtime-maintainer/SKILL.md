# Xonix Runtime Maintainer

Locate the project from the current workspace or this source skill's project path. Read [development.md](../../../docs/development.md) and the relevant code before editing. The playable application is `game/`; the historical `authoring/motion-lab/` is a separate study. A preview class or catalog reference is not automatically implemented in the game.

## Choose the real contract

- `game/core/index.mjs` exports the simulation API and `validateLevel`. Keep DOM, Phaser rendering and authoring-file concerns outside that core.
- `game/content/campaign.json` contains explicit `xonix-level.v1` levels inside `xonix-campaign.v1`. Use the actual validator; do not substitute the older game-pack, media or collection schema.
- `game/content/classes.json` configures registered ability primitives. Preserve class revision and the core's `loadoutHash` in result identity; use `campaign.classRecipes` when validating custom campaign recipes. Never derive that identity from a body or reimplement the core hash in the UI.
- `game/content/themes.json` and declared presentation bindings own appearance. A body image, rotor count, material or theme does not silently change movement, collision, enemy behavior or class statistics.
- `game/build-config.json` owns the static build allowlist. Include required modules, assets and licenses when adding dependencies. Preserve relative imports so source, `dist/` and a nested saved version can all load.

Read the exported functions and current data before selecting names or fields. New primitives, enemy types, save migrations or targeting domains require implemented behavior and tests; arbitrary JSON strings cannot create them. Preserve authored `immediate` and `grid-center` turning, and test both for changes affecting movement, input buffering, dashes or contact order. Cosmetic replacement must leave those mechanics unchanged.

For the finite staged encounter, read [Sentinel Relay](../../../docs/sentinel-relay.md) and `game/core/versions.mjs`. Preserve the exact legacy level-v1/core-v2/replay-v3 branch; level-v2/core-v3/replay-v4 owns the new encounter state/checkpoint section. Never add empty encounter defaults or new checksum fields to old runs. Resolve the selected campaign's actual version pair rather than globally changing `RULESET`. Pack-v3 requires empty `masteries`, scenario-v3 requires null `masteryDefinition`; this is not a new optional-goal predicate.

Use `game/core/encounter.mjs` for phase, fresh-trail counting and isolation authority; the renderer only reads them. Preserve contact-before-closure, repeated openings, safe/no-cut recovery exclusion for isolation, sole field seed and centered stationary actor. A short ordinary closure keeps its captured cells; automatic isolated release must not emit a fake `cut.closed`. Run `sentinel-playthrough.test.mjs`, relevant `encounter-*.test.mjs` and `compatibility-v0100.test.mjs`, preserving old proof files. The [ten finite authoring prompts](../../library/sentinel-relay/prompts.json) and source recording helper require legal input traces, not state assignments. Portable replay/session/backup and current catalog adoption must share version dispatch; theme effects and music cannot advance simulation.

For controls, read `docs/controls.md` and `game/key-bindings.mjs`. Keep mappings separate from simulation rules. Preserve Escape pause, browser/editing shortcuts, unconditional key release, cancellation without partial adoption and visible hints. New preferences require bounded validation, additive migration and portable-backup tests. Archived release profile channels must remain isolated from incompatible new schemas.

For solo controllers, read [controller navigation](../../../docs/controller-navigation.md), [controller practice](../../../docs/controller-practice.md) and the [Round 15 implementation status and remaining plan](../../../docs/round-15-controller-plan.md). Maintain these responsibilities:

- `game/ui/controller-router.mjs` reads one fresh pad snapshot per app update. It owns standard mapping, deliberate neutral-then-join assignment, connection generation, scope gates, button edges and bounded time-based menu repeats. Only the exact `flight` scope emits gameplay. Preserve selected-pad loss detection when another controller remains; a reused index or replacement cannot silently take over.
- `game/controller-bindings.mjs` owns the exact complete `xonix-controllerbindings.v1` document; [its contract](../../../docs/controller-bindings-contract.md) and [router adoption](../../../docs/controller-router-bindings.md) describe the required maps, axes and thresholds. Validate/compile once at adoption, not per frame. A rejected candidate leaves the current configuration and input history intact; an accepted candidate clears history and gates on both contexts' mapped controls, enabled sticks at/below release, and fixed join buttons. Keep current equal 0.35 defaults, digital precedence and vertical analog ties.
- `game/ui/controller-settings.mjs` edits a complete draft, allowing temporary conflicts but rejecting them at Apply. Preserve Cancel, defaults-in-draft, source-change invalidation and focus restoration after controls are enabled. The host adopts synchronously; an asynchronous host must honor the provided signal/isCurrent guard before side effects. Use configured text labels in help and editor prompts. Explicit select/slider editing is not physical capture or automatic calibration.
- `game/ui/controller-navigation.mjs` operates the existing enabled, visible DOM controls within the active scope. Select/slider browsing is a draft; Confirm commits once through the existing handler, Back cancels. A stale scope, node, value, option list or range cancels its draft. Keep protected transaction cancellation, logical gallery focus restoration, keyboard/pointer handoff and visible focus inside the open dialog. Its explicit reader API accepts only visible, named first-party `data-game-reading` regions with valid origins. Handle reading before ordinary focus/activation, clamp vertical scrolling, consume exits/invalidation and preserve native keyboard/pointer handoff. Back/Confirm/Menu end reading without also invoking the parent action.
- `game/ui/input.mjs` accepts the app's cached canonical flight command through `readControllerCommand`. That mode must not poll hardware or own another disconnect observer. Preserve keyboard/touch arbitration, held ability semantics, one-shot pause/Stop, recorded release boundaries and both steering policies. The app consumes Hangar once through the existing switch UI before polling flight input.
- `game/app.mjs` selects the current scope, samples once, routes UI, then polls input. A scope transition clears cached flight commands and requires neutral. Inactive handlers must unconditionally clear commands and navigation, including ready, results and celebration states where `pause(true)` can return early. Blur, hidden pages and native inactivity also clear preview input. Resume remains explicit. History-cache return must retain a usable UI while respecting the released profile-writer lease.

For reading integration, `game/ui/controller-reading.mjs` binds exactly `overlay-reading` and `mission-brief-reading`, retaining the full authored brief and seal explanation. Keep stable entry/Done controls and mapped local hints outside scrolling text. Register Done through the navigation adapter's optional `beginReading({region,origin,label,exit})` field: its primary pointerdown preserves the reader for normal click-based focus return, never activating on pointerdown; cancellation and other native input still relinquish. The host pauses a running flight before entry; exits never resume. `onReadingChange` must clear input through the narrow `clearInput({preserveNavigation:true})` path, which skips only navigation reset. Ordinary clear/blur/hidden/disconnect/pagehide still cancels reading. Do not clear the preview bridge on each reader transition: the router must observe neutral before accepting another gesture. Test real pointerdown→click order on Done, stale region/text removal, all exit actions, native scrolling, paused live cuts and terminal result surfaces. Read [the reader plan](../../../docs/round-22-controller-reading-plan.md) for the bounded scope; other long-form surfaces and controller hold/toggle remain separate work.

The [Controller practice lab](../../../game/controller-lab/index.html) uses actual game UI, not a second simulator. Its validated scenario handoff and `controller-preview=1` flag are required; `game/ui/controller-preview.mjs` additionally requires a same-origin iframe with a nonopaque origin. Current input/status formats are `revealline.controller-preview.v2` and `revealline.controller-preview-status.v2`, distinct from settings v1. Both envelopes require a per-load `session` of exactly 32 lowercase hexadecimal characters matching the iframe's `controller-session` query. Reject another load's session before advancing any sequence counter, even when its queued message comes from a reused WindowProxy. Input has exactly four finite axes in −1…1 and up to sixteen dense boolean buttons; the returned virtual device always has four axes/sixteen buttons. Retain strict source/origin checks, monotonic sequences, the 1200 ms lease and owned data. The bridge-produced `readSequence` acknowledgement proves a snapshot was sampled; parent Apply-stick must observe the neutral acknowledgement before sending its draft. Never manufacture that acknowledgement in the parent or extend its two-second pending deadline indefinitely. Do not add game-state, reward, storage or executable commands. Keep bounded status labels as text.

The lab now offers base, Fieldcraft, canonical Sentinel and one local Reading practice choice through normal preparePack/prepareScenario handoffs. The reading example is original local data, not a new installed expansion or an iframe mutation command. Retain all seven class choices, both steering policies and requested-versus-actual viewport reporting. Practice isolation lasts for the whole preview session, including campaign/map selection, completed-campaign navigation and leaving the original scenario. Do not derive it solely from a mutable `scenario` reference or let a completed saved campaign turn practice flight into overview routing. Preserve the non-writing profile lease and suppress progress, gallery, score and unlock awards. The lab may write the explicit `revealline.playground.current` session handoff; it must not install packs or replace the player's library. Existing stored data may still be read/exported through the ordinary UI.

Use `controller.clear()` for UI scope changes; do not call `preview.clear()` for every transition, because the router must observe the real held/released virtual controls. Preview clearing is a lifecycle operation. Parent virtual controls focus the iframe before sending, distinguish pulses from held toggles, clear timers on release/disconnect, and disconnect on hidden/history-cache transitions without treating ordinary parent blur from iframe focus as device loss.

## Make the requested change reviewable

Use `node scripts/game-cli.mjs serve --port 8768` for source inspection. `npm run validate` checks campaign, theme and class data through actual validators plus copied JSON and literal browser resources. Navigation links outside the distribution appear separately as warnings. `npm test` runs the core, tooling and existing lab test files. Run the relevant checks after the edit; complete the full required checks for a release. Do not describe tests as physical-device, visual or production-save validation.

For a candidate map, run `node scripts/game-cli.mjs generate --seed sunflower --out generated/sunflower.json`. It delegates to the same browser-safe `game/generator.mjs` as the playground, writes an explicit validated 48 × 36 level and refuses to replace an existing file. Import it through the playground's level import and inspect real play; structural validity is not a solvability or balance proof. Keep reviewed level JSON and revisions when repeatability matters.

Use `npm run build`, then `node scripts/game-cli.mjs serve --root dist --port 8769` to inspect the distribution. Check the resulting capture, input, local assets and UI at the requested sizes; generated screenshots or contact sheets do not prove playable behavior. Literal-reference checks cannot find all dynamic asset paths. Preserve source images and provenance when adjusting presentation.

For controller changes, run the relevant `game/test/controller-*.test.mjs` suites plus `ui-input.test.mjs` and `gallery-focus.test.mjs`. Preserve couch, replay, session, writer and backup regressions when touching those paths. Tests cover actual router/normalized-core logic plus injected DOM/device behavior; their count alone is not a complete session test. Exercise practice through join/start, pause/resume, remap cancel/Apply, hangar, full-brief/result reading, finish/picture and return. Reach the last line of the actual long reading choice at compact dimensions, exit with remapped controls and require a separate gesture before flight resumes. Check both axis pairs, hysteresis boundaries, both-context release, imports/Undo and session-only reload/export. Record actual browser/viewport outcomes separately from physical-controller/OS/native evidence. Use [P0 journey prompts](../../prompts/round-15-controller-journeys.md) for original default controls and [P1 layout prompts](../../prompts/round-16-controller-layouts.md) for current remapping. These prose guides add no CLI catalog entries.

## Save or distribute only the authorized result

Read [versioning.md](../../../docs/versioning.md) for `release-snapshot --ref REF --version LABEL`. The ref must already exist. The command archives the selected trusted revision and runs its frozen CLI, without switching the checkout; saved labels cannot be overwritten. Use separate server ports for independent origin-scoped saves. A generated archive is local output, not a deployment or off-device backup.

Follow the user's existing authorization for edits and local artifacts; do not add redundant approvals. Git commits/tags, external publication, store uploads and destructive replacement still follow the scope actually requested. If publication is not yet authorized, finish and verify the local artifact so the approval concerns a concrete result. Never invent a remote, app ID, credential or supported platform.

Read [deployment.md](../../../docs/deployment.md) when delivery matters. Browser builds are implemented; only claim PWA/offline or native readiness after testing the corresponding actual files and target. Capacitor, Electron and Steam packaging require their own configured projects and validation. Record the exact commands, version/source revision, observed results and remaining limitations in the handoff.

For the implemented Electron/Capacitor wrappers, use [Native Packager](../xonix-native-packager/SKILL.md) and [native distribution](../../../docs/native-distribution.md). Keep host exports/lifecycle in the shared platform adapter and preserve deterministic replay behavior.
