# Ukraine Atlas body and wing prompt contract

These seven separate built-in imagegen requests produced unchanged source bodies. No input image was uploaded. Existing project Atlas art informed broad palette and invented craft direction; no source pixels or named traditional composition were copied. Actual dimensions and prompt deviations belong in each provenance record. This document is an authoring example, not a runtime schema.

Create one isolated north-facing body at a time. Request real alpha, broad readable mass, a centered pivot and absent moving wings. Keep complete default outputs and effective prompts. Choose the two source-coordinate shoulder sockets after visual inspection, then check the existing wing envelope and actual-size render. Do not ask imagegen to invent an animation atlas, collision map or ability state. If correcting an original, use a separate imagegen edit and retain its parent; no stretching or destructive background removal.

The source recipe uses the existing fields `id`, `type`, `anchors`, `span`, `chord`, `frequencyHz`, `speedFrequencyGain`, `amplitudeDegrees`, `foldFraction`, `color`, `tipColor`. Anchors are `[x,y,side]` in the complete contained original, with left side -1 and right +1. Body fields retain `src`, `widthCells`, `heightCells`, `sampling`, `headingOffsetDegrees`, `animationRecipe`, empty `rotors`, and current `compactMinimumCSSPixels:20`. Class IDs stay `scout`, `bomber`, `carrier`, `interceptor`, `fiber`, `impact`, `trapper`; decorative names never change gameplay semantics.

Reuse the Asset Creator, Character Collection and Animation Director workflows. A source image, working wing loop, actual-size review, runtime selection and completed compact/detailed production are separate facts. Later selection goes through existing declarative catalog registration; never change old theme/reward/save identities simply to recommend new art.
