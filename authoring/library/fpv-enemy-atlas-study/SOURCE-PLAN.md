## Size, motion and image replacement contract

Those final caps mean a very narrow canvas can still render below the intended CSS minimum; do not certify a guaranteed phone size from constants alone. Physical contact radius remains the core radius times the 16-unit cell size and is drawn as a luminous center ring, independent of the larger illustration.

`sample` retains previous positions and cosmetic clocks only. Heading follows observed displacement, smoothing at a bounded turn rate; there is no predicted chase or simulation mutation. Pause, frozen/stunned state, dormant/idle modes stop phase/travel progression. Reduced effects stop cosmetic phase, bank and tail while preserving heading, shape, labels and physical state. Body image overrides currently rotate/bank as a whole, but replace the vector interior and therefore lose its rotor/tread/auger/radar details. A static PNG alone will not preserve those internal animations.

Preserve that override behavior and all existing serialized scenario formats.

## Smallest useful source feature

1. Author exactly seven immutable FPV originals under a new `authoring/library/fpv-enemy-presentations` cohort, with manifest SHA/bytes/dimensions/alpha provenance and a source-only contact sheet. Preserve originals. Require native review at measured 16/24/32 CSS pixel equivalents before runtime adoption. Transparent content must be verified, not inferred from checkerboard-looking RGB pixels.
2. Add a closed data registry keyed by the seven existing core type IDs and exact existing `*.fpv.v1` skin choices. Do not append enemy bodies to the player character presets. A record binds a stable presentation ID, exact original and explicitly identified runtime derivative, common local canvas envelope, optical center/nose, and optional finite rotor/wheel/auger/radar/relay component anchors. No gameplay/action fields, timers, arbitrary remote paths or owner aliases are accepted. New metadata goes through the existing immutable metadata-history discipline if it revises a previously pinned source document.
3. Reuse `createActorPresentation` frames and add a body-only painter/adapter. Selection order remains explicit uploaded role image first, then exact registered FPV per-type body, then the current theme vector fallback. Explicit existing non-FPV skin overrides must remain non-FPV even inside the FPV campaign. Existing `boss` upload continues to override both bosses; the new default per-type registry separates them without changing the legacy transport. Add a separate versioned per-type upload transport only in a later requested feature.
4. Load the small runtime derivatives with the existing stale-token discipline. Use authored occupancy bounds/proportional contain fit so a narrow scout and a wide emitter remain distinguishable without stretching every image into a square. Keep existing actorDiameter initially; expand sizing only after measured native evidence. Source originals need not all enter the offline core. Set a finite total derivative budget before adoption and measure the actual 64 MiB core inventory; final bytes are unknown until art exists. Optional presentation bundles are a later pipeline if measured headroom is insufficient, not a silent cap increase.
5. Keep ability cues outside the replacement artwork. Rotor travel, rolling wheels and auger/radar idle motion consume frozen/reduced cosmetic frame values. Relay shield apertures may reflect a read-only, validated actual encounter phase, but must not open early from an independent animation timer. Do not paint a permanent attack lane into the body, animate false target acquisition, cover the current cut with large fins, or enlarge the collision ring.

Likely production scope: new registry/model/body adapter; bounded additions to BoardPainter asset selection and `drawPresentedActor`; a small validated encounter-phase presentation argument only if the relay rig needs it; existing build/source allowlist updates and new finite authored metadata/original/derivative paths. `game/core`, core replay, level recipes, enemy types, random state, collision, scoring and all old player presets remain outside this feature.

## Minimum qualification before source adoption

- Pure registry tests: seven exact type/skin bindings, no duplicate or foreign type/path/shape, bounded components/envelope, immutable detached input, old player presets unchanged.
- Painter tests: all seven bodies resolve differently at identical palette/size; no asset cross-type fallback; uploaded role precedence; non-FPV skin preservation; failed/late loads show the current fallback and cannot swap a later look.
- Existing actor presentation tests plus a small new adapter test: observed heading, normal phase progression, pause/freeze/dormant hold, reduced-motion hold, distinct travel and idle clocks; source simulation object and replay checkpoint unchanged before/after painting.
- Functional overlay cases for bouncer pressure, rover warning, erosion target, lane warning and relay opening: existing labels/targets/rings remain at exact coordinates and order. No full route replay matrix is needed for a body-only change unless a failure exposes a state contract problem.
- Native side-by-side recognition on actual game backgrounds, moving/frozen/reduced poses and measured narrow/wide canvases. Include an active unfinished line and boss warning so art does not obscure critical information. Physical phone/controller qualification remains separate.
