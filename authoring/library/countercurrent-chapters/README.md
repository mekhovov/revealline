# Countercurrent optional chapter sources

This source-only candidate packages the three accepted Countercurrent layouts with twelve original reward illustrations in four independent owners: `countercurrent-fpv`, `countercurrent-ukraine`, `countercurrent-retro`, and `countercurrent-coupa`. It does not add a runtime catalog entry, production-register binding, release version, or quality approval. The current twelve-entry catalog ceiling remains a separate capability decision.

The geometry comes from [Countercurrent](../countercurrent/README.md), and every original PNG comes unchanged from the separately accepted [art batch](../countercurrent-art/README.md). [Editions](editions.json) map each source cell to its exact level ID, original path/hash and display text. [The builder](build.mjs) pins the geometry source, retained proof, themes, manifest and full provenance before preparing the four pack/media pairs. It decodes full PNG CRCs and pixels through the existing decoder; the review JPEGs never enter these packages.

Each owner retains all three level IDs, Standard revisions, seven class recipes, seeds, geometry, actors, warning timing, bonuses and capture rules. Only the campaign owner and approved name/theme/display metadata change. Gentle execution revisions are derived normally from the new authored campaign key. These three maps remain three geometry families across all four themes, not twelve new maps. Artwork is scenery, not collision or warning-lane geometry; all recorded visual deviations remain in the art provenance. The FPV stills depict fictional harbor service and observation scenes; future FPV artwork can broaden the military context.

The paired `.rlmedia` contains three exact originals with `contain`/`nearest` posters and null stories. No new movie, animation or music is authored. The chapter descriptor authenticates both complete bodies, the source pack, owner key and each original. Pairs are cache-only outputs and are never silently written by imports.

## Qualification scope

[The verifier](verify.mjs) authenticates the complete retained 198-record base proof, then selects its exact 54 Scout records: 48 Standard/Gentle × immediate/grid-center route/loss/recovery contexts and six separate Standard game-over controls. It executes each selected base trace once per invocation and shares those read-only comparison snapshots across the four new owners. It does not rerun the other 144 base records or the base mechanics recorder.

For every selected new-owner trace it checks exact physical checkpoint sections, level identity, outcome, event/capture metrics and recorded inputs against the authenticated base result. Only the owner-derived Gentle revision and approved display metadata are normalized. Each retained saved boundary becomes an actual new v4 session: restore uses that owner's execution catalog, unchanged input suffix, exact original and null story, and must reproduce the final checkpoint and replay. This is a bounded Scout presentation proof; unchanged seven-recipe bytes do not constitute a new all-roster replay matrix.

[Focused tests](test-chapters.mjs) exercise exact original round trips, malformed edition and crossed-body refusals, all five procedural/still owners' saved and first-earned isolation, missing-original unavailability, immutable prior receipts, request snapshot ownership, and exclusive ordinary cache output. A missing original never falls back to another theme or the procedural source. The single Node 22 recorder passed with 192 route contexts and 24 game-over controls across four owners: 545,664 recorded ticks and 848 actual saved-boundary checks (800 nonempty suffixes, 48 endpoint restores). All twelve originals total 31,692,501 bytes; the eight paired bodies total 31,768,658 bytes. The six focused tests passed on Node 22.22.2 and Node 20.19.5 without skips. These results establish source identity and replay/restore behavior; native play, human balance/fun, runtime adoption and public delivery remain separate.

## Reproduce without overwriting evidence

Use the repository's pinned Node runtime. First authoring recording requires absent destinations; normal verification checks the retained descriptors and proof without rewriting them:

```sh
node authoring/library/countercurrent-chapters/verify.mjs --record
node --test authoring/library/countercurrent-chapters/test-chapters.mjs
# Later independent reproduction, only when needed:
node authoring/library/countercurrent-chapters/verify.mjs
```

The initial source qualification used one recorder invocation plus the focused file on Node 22 and Node 20; the cross-runtime focused run includes actual saved/first-earned Scout completions, without duplicating the full presentation matrix. Existing recorder outputs refuse replacement. Preserve any failed attempt and its log before fixing a source defect.

For an explicit payload export, create the parent cache directory, then use a new destination for each theme:

```sh
mkdir -p .cache/countercurrent-pairs
node authoring/library/countercurrent-chapters/build.mjs ukraine .cache/countercurrent-pairs/ukraine
```

The other accepted theme arguments are `fpv`, `retro` and `coupa`. The writer refuses existing outputs, paths outside this worktree's cache, and symlink parents. It produces `descriptor.json`, `pack.json`, `media.rlmedia` and `inputs.json`; this ordinary-file contract does not claim protection against a hostile concurrent filesystem rename.

## Replacing a reward later

Generate a new original under a separate source-art identity, retain the full effective prompt and actual output, inspect it at the wide reward aspect, and verify the PNG with the existing source-art toolchain. Update only the intended edition's exact source/provenance/image pins, regenerate its paired descriptor, and requalify its new owner. Never substitute a thumbnail or edit a prior saved/first-earned pin in place. Follow the art batch's replacement guide for provenance and layout caveats; registry admission and production assessment remain separate reviewable work.
