# Saved-flight workflow prompts

These five prose examples guide work on the existing runtime. They are separate from the shared CLI's 124 prompt templates. Read the [Runtime Maintainer](../skills/xonix-runtime-maintainer/SKILL.md), [player guide](../../docs/library-and-packs.md) and [finite export plan](../../docs/round-28-save-export-plan.md) before editing. Preserve original fixtures and earlier releases.

1. **Returning-player export.** “Use a disposable browser profile and public game controls to install Homeward Skies and load an existing legal unfinished save. Reload to Ready, select a different available mission, then export the saved attempt. Compare the whole portable session with the retained checkpoint. Verify that export did not switch campaigns, resume flight or change the complete backup. Record the source revision, actual file hashes and visible status.”

2. **Missing-pack rescue.** “In a disposable profile with an unfinished expansion checkpoint, remove its expansion through Library. Export the checkpoint and verify the explicit replay-only warning. Confirm Load requires the exact campaign; reinstall it through the normal pack flow and verify the exported file opens paused. Do not edit stored JSON or treat a same-name retuned pack as equivalent.”

3. **Cancellation and stale results.** “Exercise the actual export helper and panel using a legal long recording. Cancel by the visible control and Escape; verify the previous copy remains, the dialog stays open and flight does not resume. Cover a source change while verification is pending, then a successful fresh export. Use real replay inputs for timing; never fabricate tick counts or checkpoints. Distinguish source tests, browser observations and physical-controller evidence.”

4. **Recovery across rulesets.** “Use an existing legal live-cut save and ordinary fixed simulation steps to produce a new recovery fixture, keeping the old fixture intact. Test current and Ready exports with both ordinary and staged-encounter rules where applicable. Preserve the original replay, release markers, run identity and saved date for stored export. Reload the exported file paused, explicitly Resume and verify continued simulation through the actual replay verifier.”

5. **Release verification.** “Pin the final source and version metadata, run the applicable source gates, and build an isolated distribution. Verify ordinary offline installation and a fresh Ready export with its server stopped. Record actual cache counts and page logs; a verified inventory alone does not prove browser offline behavior. Keep Cancel verification separate from a native download request. Archive a new Git-tagged version, compare its independent rebuild, and preserve all prior releases and evidence.”
