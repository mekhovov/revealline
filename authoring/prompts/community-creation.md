# Community edition requests

Use these with the [community authoring guide](../community/README.md). Replace bracketed inputs before sending a request. These are prose prompts, not new CLI template IDs. Each output remains a candidate until its required checks pass.

## Create a small campaign candidate

> Create a Reveal Line candidate for [community name] using Content Studio's supported ContentProjectV1 contract. Inspect the current source and start from authoring/community/example-project.json. Assign unique project, map, mission, campaign and pack identities deliberately; preserve the example and existing saved work. First deliver one mission with an objective, introduced skill, route decision, threat and counterplay, capture consequence, mastery opportunity and realistic playtest notes. Use only supported primitives. Compile Solo and Versus for Gentle, Standard and Expert explicitly; unsupported Team must fail rather than silently becoming Solo. Play an ordinary legal capture, loss/Retry and a full clear before expanding. Keep practice separate from earned progression. Export the actual project, import in a clean workspace, reload, re-export and compare normalized project content. Report exact source and commands, completed checks, failures and remaining production work. Do not count different pictures as new geometry or call authored pacing ratings enjoyment evidence.

## Produce a complete community presentation brief

> Design [community name]'s Reveal Line presentation from [authorized brandbook and original asset paths] for [supported modes and content identities]. Record which references are accessible, their rights and which details remain unknown. Preserve supplied originals. Keep global interface appearance distinct from the complete game theme. Inventory every applicable actor, HUD, terrain, effect, objective, reveal picture, font, sound and shared component slot. For each specify exact dimensions/geometry, native play scale, palette and contrast, alpha, pixel construction, pivot/rotor anchors, animation or procedural recipe, budget, dependencies and output names. Preserve player number/shape identity and warning counterplay. Include English/Ukrainian glyph requirements and reduced-effects variants. Use original artwork consistent with the approved pixel field-kit style; community-specific threat meanings must match its Support/Combat or noncombat framing. Produce slot-specific generation/edit prompts and a mode/screen review matrix. Do not invent access to inaccessible brand assets, treat a palette change as a complete theme, or mark uninspected artwork reviewed.

## Replace one asset without losing history

> Replace [stable slot ID] in [exact theme/collection revision] using [source image or requested variation]. Read the Studio's resolved slot contract and inspect the current original at native size. Preserve locked silhouette/features, collision-independent geometry and procedural rotor ownership. Save original bytes, creator/source/rights and the effective prompt. Prepare a derivative at the required dimensions; changing a crop requires preparation again. Validate and stage, inspect every affected mode/screen, then save a new immutable revision. Geometry-only edits must retain image bytes but start as produced with empty review evidence. Exercise Undo/Redo, reload, export .rltheme, import in a clean Studio workspace and verify every retained payload hash. An imported manifest may receive new namespaces; compare payloads and bindings instead of assuming whole-bundle byte equality. Invalid or stale work must leave the accepted collection usable. Report actual downloaded filenames and evidence, not just a clicked Export action.

## Test a Team export and recover a bad import

> In Content Studio inspect and apply a Team-compatible source for [mission]. Confirm both spawn locations, geometry, objective and supported preset. Export exact Team test missions for each advertised Gentle/Standard/Expert preset. Do not claim custom artwork, catalogue installation, awards, a complete clear or physical-device acceptance from this geometry/rules workflow.

## Qualify a community release

> Qualify [candidate source SHA, version, content identities and presentation revisions] against the original community brief and whole-game plan. First enumerate missing production assets, route/fairness checks and mode/input coverage. Verify ordinary discovery/download/play without a file picker, retained Retry and saved/earned originals, clear Next/campaign endings, all selected offline dependencies, backup/restore and recovery after failed preparation. Test keyboard, touch and physical controllers separately; include portrait, short landscape, handheld, Large/Plain text and reduced effects. Keep simulation identities separate from cosmetics. Run all six source gates and applicable build, production and artifact checks on the exact committed source. Freeze and deploy through the established release workflow, verify public bytes and actual play, then record acceptance with precise limitations. Do not close the community phase on source tests, a greybox export or a theme manifest alone; do not overwrite existing frozen releases.
