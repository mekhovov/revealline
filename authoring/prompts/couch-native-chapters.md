# Couch installed-chapter and viewport requests

These three prose examples use the current [installed-chapter contract](../../docs/couch-installed-chapters.md) and [shared delivery workflow](../../docs/feature-delivery-workflow.md#couch-shell-and-accepted-input). They add no CLI catalog entries or skills. The [older menu requests](round-29-couch-menus.md) remain a historical increment; the separate native-edition/audio prompt catalog is unchanged.

Use `game/couch/couch-installed-chapters.mjs` and its existing `refresh`, `select` and `confirm` API. The host owns race identity, selection and cancellation. Reuse the existing chapter authority, shared DB4 manager and exact descriptor registry; do not invent another media store, profile writer or fallback. Source uses `dev`; a built Couch page uses `release-${buildInfo.version}` from its actual build metadata. An original at a matching level name or another version channel is not interchangeable.

1. **Install, race and return to solo.** “In one exact edition, install or explicitly recover the named chapter in solo More worlds. Preserve a real paused solo cut. Open Couch, use Refresh installed chapters, choose the exact owner and wait for its original. Confirm Start separately. Play an embedded Immediate series and an external Grid round with independent directions and life loss; verify both painters use the selected original. Return through the normal leave confirmation, reopen the exact solo saved cut and Resume without supplying a new direction. Record actual scores, lives, continuation and pictures. Keep missing-original or writer-contention attempts, and distinguish one round from a completed series.”

2. **Cancellation, ownership and unavailable media.** “Using the actual Couch host and existing finite IndexedDB/image test models, defer chapter preparation, replace the selection and press Back from setup and the main lobby. Join the cancelled operation before its successor; keep the executing decoder's signal separate from a queued request. Check post-decode media generation and the current pointer/index/journals again before Start. A stale snapshot, mixed journal, missing index or original must disable Start and show Retry/recovery guidance without generic-art fallback, profile writes or first-earned rebinding. Check Retry/Refresh focus after cancellation and deliberate user navigation. Preserve the failing case before the correction, then test only affected boundaries.”

3. **Whole arenas at actual viewport dimensions.** “Open the same-origin viewport lab with Couch and keep its real iframe running across the five documented sizes. Enable Always separately for both players through the actual game menu; do not inject game state or emulate a device by relabelling desktop input. Inspect every arena edge, 44 px pads outside the boards, actual Tactical encounter/action rows, long labels and visible focus. Include a stacked tablet viewport near 931 × 967 to check the side-pad layout, plus compact portrait and landscape for comfort. Record intrinsic dimensions and any clipping or tiny pictures without scaling the page to hide them. Report keyboard/pointer observations separately from real touch/controller hardware and release/offline checks.”

Keep independent input, capture-stop, explicit Resume, original bytes, saved/earned ownership, existing storage caps and frozen releases unchanged.
