# Authored story model examples

Use the [implemented binding contract](../../docs/authored-story-bindings.md) and [typed transfer](../../docs/story-bundle.md). These examples exercise the isolated model; they do not authorize changing published hosts, old receipts or schemas.

1. **Saved A after selection B.** Prepare two immutable descriptors for the same exact retained picture. Explicitly bind A through `stageBinding` and commit its reviewed generation. Call `createAuthoredStoryPin` once, then deliberately bind B. Resolve the earlier pin and require A's complete canonical descriptor/source hash, while a new pin selects B. No execution or first-earned authority is inferred.
2. **Null remains null.** Read a strict logical-v1 store and require no selected story despite available history. Persist an explicit-null v2 binding, save the returned null choice, then add/bind a later descriptor. Resolve the old null without consulting current history. Keep every existing v1 presentation/session/receipt interpretation unchanged.
3. **Missing original and retained owner.** Freeze a pin, detach its original and resolve an unavailable result with the same descriptor. Do not substitute another source or current assignment. Restore exact bytes through `.rlstory` only after the required owner/poster context and originals are recovered through `.rlmedia`; then acquire again through native inspection. Keep removed-pack ownership separate from installation and awards.
4. **Transfer selection policy.** Export/import v2 using `RLSRB2`, with the same existing framing/byte bounds. Default restore retains the destination's explicit null; `restoreBindings:true` applies only supplied full-picture keys. A v1 import must never clear a v2 choice. Require whole-transaction refusal on immutable history conflict, stale generation or cancellation.
5. **Shared capacity and truthful evidence.** Construct a valid retained still document plus only explicit-null story bindings whose combined bytes exceed 2 MiB. Require selected metadata read, commit and binary export to refuse without raising limits or evicting originals. Separately qualify actual native win/Skip/Replay, paired download/fresh-origin recovery, focus/audio cleanup and offline behavior when the coordinated host is implemented.

Keep SHA-256's role precise: it binds exact validated descriptor/original bytes. It does not prove a playable codec, a game's result, a creator's rights or permission to publish. Preserve source-license/provenance records and the original MP4/PNG bytes. A compatible current v4 manager must recover old exports; old v3 readers may receive `VersionError`, and earlier v4 story adapters may reject logical v2.
