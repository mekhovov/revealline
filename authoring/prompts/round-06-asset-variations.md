# Round 06 — source-preserving asset variations

This supplement contains **16 new templates** for optional background styling and interchangeable object art. It leaves the existing 56-template catalog unchanged. No images have been generated by creating these templates.

Use [xonix-background-stylist](../skills/xonix-background-stylist/SKILL.md) to inspect a supplied source, choose the appropriate mode and record the result. **Keep-source plus a separate game overlay is the default.** A photograph, painting or existing pixel scene does not need conversion to become a reveal background. Requested conversions are separate derivatives with their own IDs and a link to the original.

The machine-readable records are in [round-06-asset-variations.json](round-06-asset-variations.json). Each record includes variables, reference requirements and a realistic example request. `template_not_executed` means the template exists; it does not claim a media asset was created.

## How to use them

1. Inspect the real source image and read the intended role before selecting a template.
2. Use review or planning for a request to use an image unchanged. Use an image-edit template only when the user requested a correction or variant.
3. Replace the declared `{{VARIABLE}}` placeholders with actual supplied context. If a necessary reference is unavailable, identify that missing source rather than inventing it.
4. For requested generation, use the built-in image tool with its supported reference mechanism. Do not upload to public image hosting, use an external styling service or switch to an API/CLI automatically.
5. Preserve the original, inspect the output and record the full effective prompt, parent asset and measured output dimensions. Follow [the variant-record guide](../skills/xonix-background-stylist/references/variant-record.md).

The shared `authoring/prompt.py` CLI now loads both the main catalog and this supplement (72 total templates). For example: `python3 authoring/prompt.py show asset-variant-03-pixel-derivative`. The skill can also read records directly. To inspect a template without executing a model:

```python
import json
from pathlib import Path

catalog = json.loads(Path("authoring/prompts/round-06-asset-variations.json").read_text())
prompt = next(p for p in catalog["prompts"]
              if p["id"] == "asset-variant-05-photograph-preserve")
print(prompt["variables"])
print(prompt["prompt"])
```

## Project-specific identity and geometry

For current **FPV FRONT** concepts and variants, use **no Z markings anywhere**. Ukrainian assets never receive hostile markings. Record Ukrainian, hostile-military or neutral allegiance explicitly from the brief; ambiguous identity remains unconfirmed. Mixed scenes use separate entity annotations. Preserve the original file for provenance even when its markings need correction in a derived version.

A placeholder `X` or `^` may represent an object to be skinned. It does not automatically dictate a literal glyph, allegiance or behavior. Replacing a drone, terrain tile or marker changes artwork only. Logical anchors, colliders, movement domains, objectives and fill behavior remain governed by the level and primitive definitions. Missing behavior belongs in an extension proposal, not invented pack fields.

Keep pixel sprites and smooth picture textures separate where filtering differs. A painted checkerboard does not prove transparency; an attractive sprite sheet does not prove equal frames, correct pivots or playable animation. Full artwork in a victory gallery does not change the recorded captured percentage.
