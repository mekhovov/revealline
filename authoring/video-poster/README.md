# Standalone video poster workshop

This source-only preview makes the [owned video acquisition API](../../game/video-poster.mjs) reviewable before story/schema integration. It opens no profile, media database, pack library, game or audio engine. It never saves an assignment or awards a picture. The existing still workshop and released game remain unchanged; this new directory is not yet in the build allowlist.

From this worktree, run the repository server and open the explicit authoring URL:

```sh
node scripts/game-cli.mjs serve --port 8930
```

Open `http://127.0.0.1:8930/authoring/video-poster/`. File URLs and failed module imports show local-server guidance with disabled source controls. Do not substitute a browser automation surface or inject application state to make a check pass.

Choose an owned MP4/WebM, inspect its dimensions/duration/hash, and select a time using the numeric field or slider. **Capture poster** is explicit. The preview displays requested seek, the reported frame timestamp (when available), approximate playhead, PNG dimensions/bytes/SHA and source SHA. **Download exact PNG** is a visible native link; asynchronous capture does not click it. The prepared Blob URL stays available for retry until source replacement, successful recapture, Clear, page exit or disposal.

Capture failure/cancellation retains a previous poster from the same source. Changing source clears old preview/download authority immediately; a late old decoder cannot adopt into the new source. Native file-dialog blur only neutralizes controller input. Hidden/page-exit cancellation prevents late publication; BFCache return requires choosing a source again. No video `play()` is called. A silent fixture cannot establish audible-track behavior.

Keyboard Tab/arrows/Enter use the shared game navigation; text/number/file controls retain native browser editing. The controller can edit the time slider and activate Capture/Download; its ordinary neutral gates prevent held input reclaiming focus after native input. File selection and text entry still require browser/OS keyboard or touch support; this page does not provide a virtual keyboard or claim controller-only OS file picking. Escape/East cancels pending work or uses the visible Back route. Phone and physical-controller comfort need actual testing.

## Owned diagnostic MP4

```sh
node authoring/video-poster/generate-fixture.mjs --out .cache/owned-video-fixture-1
```

The generator refuses to overwrite an output directory and never installs dependencies or downloads source media. When an existing ffmpeg is available, it creates a six-second 640 × 360 / 10 fps H.264 clip with color/test patterns and a burned frame number. On macOS without ffmpeg, it writes an owned Swift source into the cache output and uses the existing AVFoundation SDK to generate six colored cards, a moving white bar and explicit frame/time labels. Both routes omit audio. Generation logs, encoder/tool version, exact command, source-script SHA and resulting MP4 bytes/SHA are recorded. Encoder output can differ across systems; generated bytes have their own recorded identity.

Actual local fixture generation used **Swift 6.3.3 / AVAssetWriter**, because ffmpeg was unavailable. The result in `.cache/video-poster/owned-fixture-1/` is **75,767 bytes**, SHA-256 `5abb074b8a740a3305b1d8c6b84466e46eb51d853e2faacad592182999b2c1ea`. Native AVFoundation inspection reports **6.0 seconds, 640 × 360, one video track and zero audio tracks**. A separately extracted native frame at requested/observed 2.0 seconds shows a blue card, “FRAME 20 / 60”, “TIME 2.0 SECONDS” and the moving bar. Its PNG was inspected visually. This native fixture check does not qualify the browser adapter or promise the browser will choose the same frame.

## Browser smoke still required

Use the normal in-app browser skill/client and actual file chooser. Preserve original generated MP4 and each downloaded PNG; write the browser observations alongside file hashes.

1. Open the source URL, choose the owned MP4 and confirm metadata. Verify no playback starts. Capture time 0, 2.0, a fractional time such as 2.13, then repeat 2.0. Record requested, observed callback and playhead values as shown; do not invent frame accuracy from the numeric input. Check full picture/aspect and labeled color/frame content.
2. Press Enter on **Download exact PNG** and verify an actual disk file, MIME/dimensions/SHA and the displayed PNG hash. Repeat the visible link to confirm retry behavior. The OS download event and filesystem bytes are evidence separate from a modeled anchor click.
3. Capture again, cancel pending work, clear/change source, navigate away/back, and inspect for stale images or URLs. A failed new capture must retain its prior same-source result; changed source must not show the old source’s download. Keep a corrupt file and over-limit source rejection explicit.
4. Use keyboard throughout the in-page journey, then a real controller for the slider/Capture/Download. State any browser/OS file-picker/text-entry limitation. Check a real narrow layout plus large text/zoom and focus visibility; desktop resizing is not device certification.
5. Observe real frame callbacks first. Where a browser lacks them, the displayed fallback must explicitly say timestamp unavailable/approximate. A paused-frame timeout in a supported browser is a concrete finding to investigate; do not silently play the video or fabricate metadata to avoid it.

Actual browser checks have not run for this page yet. Existing [primitive tests](../../game/test/video-poster.test.mjs) and the [14 workshop cases](../../game/test/video-poster-workshop.test.mjs) use modeled DOM/media boundaries. They establish code ordering, native-control contracts, cancellation and exact Blob handoff, not codecs, physical controls, screenshot quality, browser downloads or complete video-story delivery. The broader [integration contract](../../docs/video-poster-acquisition.md) keeps still schema, originals/PNG inventories, shared media budget and optional story work separate.
