# Company Studio

Serve the repository and open `/authoring/company-studio/`. The seven steps edit the same data formats used by the edition compiler: identity, artwork roles, actors and atmosphere, campaigns, learning, preview, and delivery.

The browser keeps changes in memory. JSON editor buffers survive step and campaign changes; apply them before export. Export creates a complete `revealline-company-source-draft.v1` packet containing the catalog and every declared JSON source. Declared retained presentations are immutable recovery data: their draft entries keep the original JSON text in `data`, including whitespace. They have no editable mission/lesson panel. Import, export and preview verify their registered byte count, SHA-256, receipt and selected audience; missing or changed originals are rejected. Binary media remains in the source workspace. Asset Studio prepares original media; the source catalog records its exact bytes, SHA-256, ownership dependencies and publication decision.

Import the packet into a new directory and compile an edition:

```sh
node scripts/company-studio.mjs import-draft --file coupa-adventure-draft.json --workspace .cache/coupa-source
node scripts/company-studio.mjs validate --workspace .cache/coupa-source --edition coupa-adventure
node scripts/company-studio.mjs preview --workspace .cache/coupa-source --edition coupa-adventure --out dist/company-previews/coupa-preview
```

The CLI copies only approved media whose actual bytes match the catalog. Use `--media-root PATH` when the original assets are in another source workspace.

Import the new v2 `dist/company-previews/coupa-preview.report.json` in step 06. Regenerate older reports with the current CLI. The report pins `edition-build.json`; the Studio checks that manifest, every admitted file’s byte count and SHA-256, and the compiled catalog and selected JSON against the applied draft before opening the full Solo game. The compiler’s ordinary theme projection is applied to both views, so focused editions omit unrelated campaign themes while edits to selected themes remain detectable. Only selected current media, exact media required by declared retained presentations, and the repository’s declared shared engine assets are admitted. Historical-only originals count in the report’s media totals and are not incorrectly labelled excluded. Changed report totals, exclusions, files, edition identity, invented review approval or an external preview URL are rejected. The “Source reference” link always opens the saved repository game and is explicitly separate from the draft preview. Preview output must use a visible directory: the development server intentionally does not serve `.cache` or other hidden directories.

An imported report remains visibly unverified until the artifact check succeeds. Verification reads at most six files concurrently, limits a file to 64 MiB and the complete artifact to 256 MiB, and cancels after one minute or when the applied draft/report changes. This establishes consistency of local files, not an independent publisher signature or human approval. The report lists admitted files, excluded companies/editions/campaigns/assets, and checks still requiring review. Schema validation does not prove a new route is playable or that a lesson is factually correct. Route proofs, visual/accessibility checks and human playtesting remain release evidence; the studio does not publish a release.

For a new company, start with the neutral workspace:

```sh
node scripts/company-studio.mjs init --brand acme --edition acme-public --name 'Acme' --workspace .cache/acme-source
```

The neutral starter uses the current Journey trail-impact policy, actor and difficulty catalogs and all seven standard class recipes. It therefore supports the shared Solo host and First Flight without a company-specific gameplay path. Its opening map is still an unqualified draft.

Import that workspace’s `source-draft.json` to work entirely from its JSON. A catalog-only import is also supported when its declared source paths are available from the development server.

The Identity step shows the selected brand’s recorded official/licensing references. Artwork cards expose dependency and derivative provenance. “Media admitted for compilation” refers to the recorded bytes only; final illustration review, trademark permission and recorded human playtesting are separate. Optional learning runs after victory and never gates arcade progression. No final artwork or human-review result is generated by this workflow.

After a whole-game artifact verifies, step 06 enables **Mission artwork and content observations**. Choose a mission, record the observer, actual viewport, motion setting and scene state, and describe only the checks you observed. The panel shows that mission’s exact current picture revision and SHA-256, its fictional-content notice and available brand/lesson sources. Use the game’s normal Missions selector and controls; the Studio does not start, win or modify a game. A full-art diagnostic is recorded separately from initial, partial and result scenes. Studio-launched whole-game previews carry an explicit preview marker and use fresh, in-memory storage. They never read or save the player’s Journey, rewards or active flight, claim its writer lock, or install an edition. Temporary progress resets when the preview reloads; preview Journey/reward backup transfer is disabled.

Import the relevant generation receipt to see its original/export inspection prose and composition warnings. These notes must match the selected mission, picture revision, PNG path, dimensions, byte count and hash. Unrelated missions in the same receipt are omitted; old pictures cannot supply notes for current ones. Only bounded plain text and public HTTPS reference links are displayed. No generated master is fetched, and imported prose remains a provenance lead rather than an independent review decision.

Export creates `review-<edition>-artwork.json`, a `revealline-company-art-observations.v1` packet bound to the verified build-manifest hash and exact picture descriptors. This is manual observation evidence, **not** a promotion receipt, asset approval, or replacement for reported formative playtesting. No check is pre-passed. Imports and exports are limited to 2 MiB and 512 observations; stale artifacts, changed pictures, duplicate observation keys and approval fields are rejected. Saving the same mission/viewport/motion/scene updates that observation; other scene states can have separate records. Generation notes themselves are not included in the exported observations: record any warning’s disposition explicitly in the additional-findings field and retain the original generation receipt separately.

Observations stay in memory. Draft, report or edition changes disable new observations but leave the previous packet exportable under its original hash. A different verified artifact requires explicitly discarding the old observations before beginning its review; they are never silently rebound. Export before closing the tab. Source JSON fetches also now stop at 4 MiB before decoding and cancel stalled body reads; immutable retained JSON keeps its exact whitespace and UTF-8 bytes.

## Discovery authoring

In **Learning & rewards**, a campaign without lessons now offers **Add a lesson sidecar**. This adds an empty declared source file; it does not invent a completed lesson or change arcade requirements. Choose a mission and use the guided fixture fields for the objective, worked-example evidence, a different application situation, decision options, corrective feedback, authoritative sources and review date. Supply both English and Ukrainian. A new fixture starts with two evidence records and one two-choice decision; advanced JSON remains available for the schema's other bounded structures. Changed teaching content requires new lesson and fixture revisions. Applying lessons checks existing exact reward requirements rather than silently rebinding them.

**Stage lesson draft** validates the fields and updates the advanced JSON. **Validate & apply lessons** then includes the change in the exported source packet and advances affected edition revisions. The wrong/alternative, supported/reflective and incomplete previews use the actual workbench and action verifier without player storage or gameplay evidence. **Resume current preview** retains only the current local attempt; changing its source or selection resets it. Reflections have no correct personal value: both alternatives show their authored consequences. Preview completion cannot grant a reward or arcade clear.

The shared atlas editor also has guided bilingual objective, evidence, source and application fields. **Add a later-application question** adds an incomplete local draft with two choices; the author must supply both languages, useful feedback and an explicit supported choice before staging. Up to four questions use the existing recipe limit. Exact image hashes, source IDs and diagram coordinates survive text edits. Use the existing diagram panel for a deliberate image/coordinate change. Staging does not apply or earn anything; preview and Apply use the existing shared viewer, revision binding and dependency checks.

In **Learning & rewards**, add a reward sidecar and explicitly choose one mission, every mission, or a checklist of required missions. A checklist is a campaign reward with exactly those requirements; reaching its last mission does not imply the others are complete. Enter English and Ukrainian knowledge and teaser copy, review the generated definition, then validate and apply it. The sidecar remains the authority for exact gameplay bindings, payloads and sources.

In **Campaigns**, choose a mission and open **Discoveries, pacing and campaign exhibits**. Assign a pacing beat, its exact first-win reward revision, a route/gallery/mosaic layout and an optional campaign finale. The route preview shows the current draft's landmarks, decisions, teasers and declared finale requirements; it neither plays a run nor writes progress. Changes apply only after **Apply discovery design**. Unapplied campaign JSON must be resolved first. An unavailable or changed reward revision fails validation instead of silently choosing newer artwork or requirements.

The same controls appear in Content Studio. Import the reward JSON sidecar there before binding references, and keep that original file alongside the ContentProject backup. Company Studio source packets include both automatically. Importing a sidecar does not install it in a player edition; export qualification still validates exact selected campaign ownership, gameplay bindings, dependencies and publication eligibility.

Optional `mission.design.pacingBeat` uses `discover`, `choose`, `combine`, `breathe`, `mastery` or `resolve`; `mission.design.rewardRef` stores `{id, revision}`. Optional `campaign.discovery` stores `exhibitLayout` and `finaleRewardRef`. These fields affect presentation only. Discovery edits preserve mission/campaign gameplay revisions while changing the authoring project revision; edition compilation still needs a new immutable presentation revision. Duplicating a mission or campaign retains pacing/layout but removes reward links scoped to the old identity. Author new explicit promises for the copy.

For the four built-in learning showcases and an end-to-end acceptance sequence,
see the [discovery author guide](../../docs/discovery-rewards-author-guide.md) and
[verified learning discoveries](../../docs/discovery-learning-rewards.md). The
showcases keep their six-win finales while separate optional bonuses require
selected exact lessons. Review the actual compiled result and Collection in an
isolated player profile as well as the ineligible Studio previews.

Flight courses use the separate [FPV Course Studio](../../docs/civilian-fpv-authoring.md).
Its bundle is not a Company source draft: it contains one course, a knowledge reward
and an optional exact demonstration. Company source import cannot turn that bundle
into an admitted simulator package or a verified player completion.

## Selected campaign languages

A campaign can declare `localizationPath` and `localizationSha256`. The versioned `revealline-campaign-localization.v1` sidecar pins each complete campaign or mission source record, the original English field and its Ukrainian translation. The SHA-256 is over canonical JSON, so formatting does not change its identity. Translation data never replaces strings inside engine inputs or replay records.

Use Campaigns → Campaign languages to edit or preview both languages. Give changed translations a new sidecar revision before applying. Apply repins the canonical data and increments the revisions of editions containing that campaign; it leaves gameplay records untouched. New sources can be prepared with `createCampaignLocalization` and `campaignLocalizationSha256` in `game/editions/localization.mjs`, then declared in the catalog. English fields must match the selected source exactly. Changing a mission requires reviewing and regenerating its stale translation bindings.

Source packets, whole-game previews and standalone builds include only the selected sidecars. Import/export and compilation verify their selected ownership and pins. Retained presentations retain their original sidecars. The running host installs a presentation scope only after admission and removes it on departure. An edited record with a familiar name or ID cannot borrow the translation of a different level.

The initial curriculum sidecars cover campaign and mission names, ready briefs and route descriptions. Reward discoveries have their own bilingual payloads. Other authored design prose and brand text may still use English; these partial sidecars do not certify that an entire edition has been translated.
