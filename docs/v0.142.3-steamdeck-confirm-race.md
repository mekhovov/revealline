# v0.142.3 Steam Deck Confirm race

## Reproduced defect and repair

The actual Solo host reproduced Sound changing on native Enter-down, then changing
back on a release click. The Gamepad A state was already pressed, but no render
frame had sampled it. Native navigation cleared the router before the transaction
could capture its target. The earlier native-first test used a click without the
preceding key/pointer down and therefore missed that handoff.

The release-committed guard introduced in v0.141.8 omitted its live Confirm probe
from native-event ownership. The affected behavior remains in v0.142.2. This is a
verified regression boundary for this specific race, not proof of the first
historical Steam Deck failure; v0.106 remains the first reported failing release.

One Confirm lifecycle now reconciles read-only native-event snapshots and regular
render-frame snapshots. Native capture does not call the full router sampler or
consume unrelated direction, Back, Menu, or flight edges. Observable A-down captures
the target before native navigation can clear it; observed release commits once.
A native-first winner remains the sole activation through its entire hold and menu
transition. Cancelled holds drain to neutral without activating. Hard device/focus
loss releases ownership. The existing 250 ms association and 1.25 s alias/tail
windows have not been increased.

Valve documents mixed keyboard/mouse/gamepad bindings and release activators. The
browser Gamepad API exposes snapshots, not a shared native-event sequence:

- [Valve activators](https://partner.steamgames.com/doc/features/steam_controller/activators)
- [Valve legacy bindings](https://partner.steamgames.com/doc/features/steam_controller/legacy_mode)
- [W3C Gamepad API](https://www.w3.org/TR/gamepad/#dom-navigator-getgamepads)

## Diagnostics and acceptance

`?controllerTrace=1` and the temporary Controller settings checkbox enable the same
memory-only diagnostic. It shows the actual build, native event observations,
raw/selected controller identity and buttons, sample intervals, focus/fullscreen
state, transaction decisions, and cancellations. Repeated held samples coalesce.
The trace follows the active modal rather than sitting behind its browser top layer.
Disabling it removes the panel/listeners and clears the buffer. No input text,
persistent records, or network telemetry are collected. Installed-app launch keeps
the selected edition and preserves only the diagnostic query option.

Regression coverage includes trusted native-down before RAF, taps wholly between
render frames, Enter/Space and mouse/touch/pen paths, native-first menu transitions,
five-second holds and cancellation, unrelated targets, custom mappings, alias echoes,
rapid deliberate repeats, and immediate native recovery after disconnect. Home Sound,
Start, Settings/More, Home, and every primary Pause action are exercised through the
real Solo host. The minimal DOM harness now models stopImmediatePropagation correctly;
separate tests distinguish it from stopPropagation.

The local browser fixture serves packaged files without modifying them, adding only
an input driver to the served game HTML. It couples real Chrome keyboard/pointer
input with scripted gamepad state and can hold render callbacks to reproduce the
between-frame ordering. This is browser evidence, not physical Steam Deck evidence.

Real Chrome acceptance exposed a second defect that synthetic events had masked:
primary mouse pointer-down/up events had `isPrimary: true`, while their trusted
release `click` had `isPrimary: false` and `button: 0`. The guard skipped this click,
so it reversed the release commit. This matches
[Pointer Events §4.2.12.1](https://www.w3.org/TR/pointerevents3/#event-attributes):
click-specific pointer fields other than identity/type use their defaults, including
`isPrimary: false`. A click must therefore be classified by its activation button,
not rejected for this pointer field. The fixture and opt-in trace now expose pointer
identity, primary status, and button so this browser distinction remains visible.
The fixture also accepts `--archive distribution.zip`, serving unmodified STORE
members directly without extracting another full site copy.

Physical acceptance remains outstanding until the same public build passes on the
Deck: short taps and long holds, all listed menus, Chrome Game Mode shortcut,
ordinary fullscreen Chrome, installed-app launch, and touchscreen recovery. Use the
stable `/game/` entry and verify the displayed version. If input still fails, retain
that build's trace and compare one Regular Press → Gamepad A binding. If no pressed
snapshot is ever exposed, normal native input remains available; the implementation
does not guess that two arbitrary native clicks are one physical gesture.

No save, content, public API, or portable schema changes are included.
