# v0.130.0 Steam Deck Confirm transaction repair

Repair baseline: public v0.116.1. The first reported failing public build was v0.106.0; the exact
last working release remains unknown.

## Remaining failure

Physical Steam Deck testing showed the same action changing on A-down and changing back on A-up.
The v0.116.1 guard still had two gaps:

1. It allowed a direct `pointerType: touch|pen` sequence immediately after Gamepad A was released,
   unless `sourceCapabilities.firesTouchEvents` identified it as a compatibility stream.
2. It allowed every untrusted click while the controller owned Confirm because
   `HTMLElement.click()` is untrusted. That classified unrelated compatibility or script-generated
   clicks as controller navigation's intended click.

Chrome documents `firesTouchEvents` as metadata for mouse compatibility events derived from
touch-like input, not as a complete physical-device identity:
<https://developer.chrome.com/blog/inputdevicecapabilities>. MDN confirms that
`HTMLElement.click()` emits an untrusted click:
<https://developer.mozilla.org/en-US/docs/Web/API/Event/isTrusted>. Valve documents that Steam
Input may mix emulated gamepad, keyboard and mouse bindings, and that activators can run on press,
hold or release:
<https://partner.steamgames.com/doc/features/steam_controller/legacy_mode> and
<https://partner.steamgames.com/doc/features/steam_controller/activators>.

## Repair

Controller navigation now activates a control through an explicit guard transaction. Only the
synchronous click inside that transaction is authorized. Once the transaction commits, all other
primary click representations remain suppressed through the A release grace period, regardless of
`isTrusted`, pointer type or `firesTouchEvents`. A trusted native activation that wins before the
Gamepad frame still suppresses the matching controller transaction.

South and the optional West menu alias now form one Confirm family transition. If Steam Input
exposes those aliases on adjacent frames, the second alias cannot create another Confirm edge until
the whole family returns to neutral.

## Verification boundary

Focused tests cover Gamepad-first and native-first order, trusted and untrusted click-only echoes,
touch and touch-derived pointer releases, missing `sourceCapabilities`, a five-second hold, release
grace expiry, alias overlap, home Sound/Settings/More, Start mission, and every primary Pause action.
Controller help remains collapsed and absent during gameplay. A separate touch gesture remains
usable when there is no controller-owned activation; after a controller activation, the release
grace expires after 1.25 seconds.

Automated tests model the reported browser event order but cannot reproduce the Steam Deck's
physical Steam Input stream. Final acceptance still requires Chrome launched as a Game Mode
shortcut with its Gamepad layout: tap and hold A on Sound, Start mission, Home and every pause-menu
action, then verify the touchscreen after the release grace period.
