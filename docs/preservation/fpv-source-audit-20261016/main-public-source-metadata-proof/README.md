The exact13,537 declared public source prerequisite commit IDs in the published additional815-object manifest were fetched from GitHub into the new recovery repository. This metadata-only pass read and raw-SHA1-verified every commit and its recursively referenced55,647 tree objects (549,991,485 tree-body bytes). It records65,071 typed public blob leaf IDs without reading their bodies. The set SHA256 is `28e1ae2e2ef89dd8cd86983c3bb70729180d00c4691ab3e138041920c95f2c7b`. Each leaf identity is derived from a verified Git tree reached from a declared public source input; unrelated local-store object-header membership is not the proof. The commit-to-tree map, exact typed-leaf set, helper and receipt are preserved here. Full per-tree hash journal is reconstructible from these GitHub commit/tree inputs; its exact digest is retained in the receipt.

The declared public input IDs remain bound to the accepted original public ancestry/pin receipts (3854/be46 and independently retained269refs), plus the nine existing-public source parents anchored by a3e920. A single umbrella alone never substituted for the independent refs. Accepted original and additional source bundles are separate allowed identity sets for source versions not already public in those prerequisite trees. Captured working-file bytes must compute to the same typed Git blob identity before this graph can back them. A matching filename or unrelated header set is insufficient.

The first native filtered traversal timed out after600 seconds; its partial output is explicitly rejected as a membership proof. The successful replacement directly traversed verified recovered commit/tree metadata with remote invalid, lazy fetch disabled, no original source stores and no alternates. It did not read public tracked module/blob bodies.

The separate main captured-source LFS/Gitlink receipt covers all present source trees and every blob no larger than1024 bytes in the GitHub-only recovery store:62,519 trees and4,966 small blobs, all raw-SHA1 verified, canonical LFS pointers0/Gitlinks0. Metadata checks across all23 main common stores found no local LFS object copies or custom LFS storage settings. Git LFS specifies pointer files under1024 bytes, including extension lines (https://github.com/git-lfs/git-lfs/blob/main/docs/spec.md). Legacy pointer aliases and index-only source versions remain an explicit final supplement gate; this canonical pass does not silently cover them.

These are source identity/metadata receipts. Index-only staged/conflict versions, private app-family histories/assets, additional live working payloads and whole-volume completion remain separate. No physical drive-unmount, player persistence/offline/endurance or full pre-boundary ancestry claim is made.
