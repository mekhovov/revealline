## Proposed next order — awaiting user reprioritization

1. **Reliable entry and delivery (M1/M2/M10/M14):** verify the corrected deployed menu after authorized access; fix first-entry input/language gaps; follow the existing Demo-stall investigation and compatible releases.
2. **Preserve and read (M3/M4/M5):** save/restore safety, important menu readability and the first installed-iPhone upgrade if that audience matters now.
3. **Visible improvement (M6/M7):** a bounded phone performance baseline and one convincing layered background/portrait demonstration before a larger rollout.
4. **Audience-selected expansion (M8/M9/M11):** chosen new edition, creator workflow, audio review or target-device breadth.
5. **Broader completion (M12/M13 and remaining M7/M9):** historical references, remaining art/media/locale/device coverage; formal human review stays last under the existing instruction.

M1–M14 definitions and completion criteria are in the [decision guide](native-menu-review-2026-10-01.md). This proposal promotes a visible background demonstration above exhaustive references. It does not cancel any original layered/sprite, Solo-portrait, edition, tool or native-device requirement. The user has not yet selected player-ready, visual-showcase or creator/partner emphasis.

## Constraints and completion

The current delivery instruction defers extended production/device review and the current test policy waives automated suites. Do not change these policies, run waived suites or block independent source work merely because this guide recommends eventual qualification. Deferred/skipped checks remain not passed. Current build, source integrity and publisher safeguards retain their own authority.

Releases remains the sole integrator/publisher. No independent version allocation, frozen-donor rewrite, historical snapshot changes or broad recovery republishing. Main Pages delivery is distinct from formal v0.150.0 publication. Source-only art stays source-only unless separately admitted and budgeted; a gallery is not a new gameplay feature.

Use the [inventory](native-menu-inventory.json), [menu contract](native-menus.md), [scene catalogue](menu-scenes.md), [updater evidence](offline-pwa/updates-and-communities.md) and per-tool receipts. No prior result becomes current whole-build acceptance automatically. The overall plan remains incomplete until the supported input/routes, state safety, accessibility/locales, intended art/motion, meaningful tools and actual device/public contracts are satisfied or explicitly revised by the user.
