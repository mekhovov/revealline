**The overall plan is incomplete.** Most shared implementation and many local workflows exist. There is no defensible single completion percentage: a source implementation, a virtual-controller test and a shipped hardware-qualified feature are different milestones.

## Scope and evidence rules

- Three main hosts: Solo, Versus and Team; current Journey, supported legacy and custom-content routes remain in scope. Custom Solo has a separate capability-backed host.
- **18 Solo-only editions**, each with default-package and standalone launch routes. The original 14 have mapped edition scenery. Social Drone UA, Victory Drones, Ukraine: Living Culture and FPV Learning currently use the shared FPV fallback.
- Four base worlds, two independent menu palettes, English and Ukrainian. **18 scene identities means four base worlds plus 14 original edition identities**, not 18 unique edition backgrounds.
- **16 active authoring/tool routes**, including the now-present Demo recorder and moderation; 16 reference routes; player support and actual Community directory/friendly entry routes. Some routes appear in more than one functional category; counts are not additive.
- Historical snapshots, save identities, user content, accepted Confirm ownership and publisher provenance remain protected. Source-only reference art stays source-only unless separately admitted and budgeted.

“Source implemented” means the code exists. “Automated” means the stated cases ran at the recorded revision. “Browser-qualified” identifies the exact route, input method and workflow; virtual pads are not physical controllers. “Device-qualified” requires the real device/runtime. “Published acceptance” requires the actual public package and metadata. Skipped, waived and canceled jobs are never passes. Old evidence transfers only through explicit source attribution or a relevant fresh check; overlapping test cohorts are never summed.

### Landing contract and immediate regression

The normal landing may contain **title; one Start/Continue; Select Mission; Settings; Sound; supported mode names/icons; passive song/version; Fullscreen**. Loading, cancellation and recovery are temporary exceptions. A host without an audio capability must not gain a dead Sound control.

The September 30 public default and DroneAid check found extra Play music, Next song, Collection, How to play, FPV flight simulator and Flight practice actions. Boot, titles and keyboard Settings/Back passed, but the whitelist failed. [Correction #854](https://github.com/mekhovov/revealline/pull/854) has local default/DroneAid keyboard and virtual-pad evidence and **merged at 18:48:15 UTC**. Its automatic deployment was running at the 18:51 update; public acceptance remains open. Keep every moved feature reachable through Audio, Progress & Collection and Help & Extras; controller configuration remains in Controls. Do not solve clutter by removing features.

### Background creative gap

Current ambient motion animates regions of flattened artwork, with brief entrance/receiver effects. It does **not** provide the full planned separated scene layers, sprite sequences or independently animated actors. Only FPV Solo has a distinct portrait original; the other 17 Solo profiles use deliberate focal crops. All four base-world multiplayer portrait compositions are independently drawn.

These are retained **P3 creative deliverables**, not silently marked complete or removed from scope. First validate the current motion's performance/comfort and release the player fixes. Then implement the remaining approved layered/sprite animation and separate Solo portrait scope, with per-scene review choosing the execution and preserving approved source art. Any reduction of this original scope requires an explicit user decision. The current largest documented active image-plus-atlas payload is 2,085,129 bytes, just below 2 MiB; this is an asset budget, not measured browser memory. See [scene catalogue](menu-scenes.md).

## How to close this plan

Each batch updates the inventory and its source/browser/device/public evidence, identifies failures separately, and is committed/pushed with a small reviewable PR and coordinator allocation. A documentation or compiler pass does not close a user workflow.

The full plan closes only when the allowed landing and relocated features work on supported integrated routes; every application-owned action and meaningful creator workflow is reachable and escapable with each required input; EN/UK/accessibility layouts and state preservation pass; intentional scenes, including the remaining approved layered/sprite animation and separate Solo portrait compositions, cover supported variants with static/offline fallbacks and measured performance; supported native/physical targets are qualified; and the real published default/DroneAid and edition routes are verified with release provenance. Browser/OS pickers and permission/install surfaces remain explicitly documented platform handoffs.
