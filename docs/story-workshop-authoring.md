# Optional story authoring in Picture Workshop

This source extension builds on [authored bindings](authored-story-bindings.md) at `8a6e5460fd3eb7d01fb07fa10549e131d718fa69`. The existing Picture Workshop can receive an explicit compatible story store and author a video segment for one exact retained poster. It uses the same dialog, task cancellation and controller navigation. The original isolated UI slice did not adopt its host or change game/session/earned formats. The current successor now injects the shared v4 store through [story runtime integration](story-runtime-adoption.md); native browser and release acceptance are separate.

## Injection contract

`attachStillMediaPanel` keeps its existing arguments and accepts these optional capabilities:

| Argument                                | Contract                                                                                                                                                                                                                                                           |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `storyStore`                            | Current `createStoryMediaStore` adapter, borrowed from the **same explicit v4 manager** as the still and audio stores. The panel never opens, upgrades or closes that manager. No capability means no story controls or story store access.                        |
| `storyInspection`                       | Trusted native `createVideo`, `createCanvas`, `decodeImage`, timeout/timer hooks accepted by existing acquisition/storage modules. Omit for native defaults. These are host code, never imported JSON. Panel `URLImpl` owns its acquisition/preview/download URLs. |
| `makeStoryId()`                         | Optional stable-ID generator; default `story-${crypto.randomUUID()}`. New stories are new immutable IDs at revision 1. Captured PNG asset IDs also use this generator.                                                                                             |
| `onStorySaved({generation,document})`   | Optional notification after a successful native commit. A thrown or rejected notification reports **saved, notification failed**; it cannot roll back the completed transaction or leave the panel's generation behind.                                            |
| `requestStoryDownload({blob,filename})` | Optional native-wrapper download request. Called synchronously by the explicit visible download action, before awaiting anything. It does not run during asynchronous preparation. Native href/download remains available when this capability is absent.          |

The panel adds `back()`: with story capability and an active task, first Back cancels pending work and requires Reload; later Back closes. `close()` remains unconditional Close/lifecycle cleanup. The existing native dialog cancel event uses `back()`. The integrated host routes its existing navigation `onBack` to `panel.back()`; it does not create another controller router. Keep native file-picker blur separate from actual hidden/pagehide/Close cancellation. The initial standalone UI receipt still describes its original unadopted host scope.

## One exact picture, one explicit story choice

Select a saved picture revision in the existing history field. The story section identifies its description/revision and whether it is the current assignment or a historical revision. Unsaved picture drafts cannot be bound. Matching requires the complete validated still pin: authored identity, presentation ID/revision, poster asset ID/hash. The current assignment does not substitute for a selected historical poster.

Choose an owned MP4/WebM, then **Inspect chosen video**. Inspection is silent and preserves exact original bytes. Enter segment start/end as numbers or use the controller-editable sliders; no out-of-range value is silently accepted. **Prepare new story** validates its immutable descriptor, original and full picture binding, then stages one complete store update. It checks the loaded story generation and current installed-context ticket. **Save prepared story** is a separate action that commits the original, descriptor and binding in **one CAS transaction**, or none. Preparation and slider editing award nothing and do not save a selection.

**Prepare saved story** stages a deliberately chosen history entry for that same full poster. **Clear story binding** stores explicit null while retaining all descriptor history and source originals. Missing/v1/null selections never search for a matching story. Changing picture owner/revision, file, segment, description, history or restore policy invalidates prepared work; a concurrent store writer makes the reviewed generation stale. Binding changes do not reinterpret saved attempts or old first-earned receipts.

## Optional frame capture uses the existing still save

**Capture picture draft** uses the inspected original and the requested frame time. The existing acquisition adapter validates and hashes the actual encoded PNG; the ordinary still preview stages that PNG without saving it. The caption separately reports requested time, observed frame timestamp (when supplied), playhead and timing evidence. A requested 2.05 seconds can yield observed 2.0; an approximate fallback has no observed frame timestamp. The image preview is explicitly a draft, not a new stored story or a promise of frame accuracy.

Use existing **Save assignment** to retain the exact captured PNG as a normal still with `story:null`, unchanged schema and ordinary provenance fields. This is the only intended selection transition permitted during capture publication. The owned original video remains in the open workshop so a subsequent story can bind the newly saved full poster. Closing releases this unsaved video handle; only an explicit story save persists its original. A failed/cancelled same-context candidate preserves the prior accepted preview. No source video is re-encoded and no accepted PNG bytes are rewritten.

## Separate native story transfer

**Prepare story download** verifies the exact available video inventory and exports `.rlstory` through the existing versioned binary adapter. It retains one bounded Blob URL; **Download story originals** is the separate native activation, remains available to retry, and does not claim disk completion. An edit, cancellation, Close or disposal revokes it; a URL allocated during cancellation is revoked before publication.

Choose a `.rlstory` file, select **Keep current bindings** (default) or **Restore incoming bindings**, then **Review chosen story backup**. The whole file's bytes and native metadata, exact retained target posters, immutable history and shared capacity must pass before **Restore reviewed stories** becomes available. The second explicit action uses the reviewed file/policy/context and one generation CAS. Default keep preserves destination explicit null. Explicit restore applies only incoming full-picture keys, retaining destination keys absent from that file. Old v1 imports never clear v2 choices. A corrupt second video, missing target poster, stale review, quota refusal or cancellation cannot partially import the first story.

Restore exact picture originals via `.rlmedia` first when missing. `.rlstory` includes story history/video originals and a retained picture context for validation, **not** the actual poster originals, audio, packs or game progress. Game JSON, `.rlmedia`, `.rlstory` and `.rlsound` remain separate formats. Source-license/provenance handling is unchanged; possession of a hash or successful import does not assert rights.

## Limits, lifecycle and remaining integration

The panel retains existing bounds: one source at most **64 MiB**, video at most **120 seconds / 1920×1080**, PNG at most **4 MiB**, binary file **256 MiB**, and shared **256 MiB committed plus staging / 2 MiB still+story metadata / 512 physical original rows / four leases**. No cap is raised and no second database bypass is added. Complete-inventory native preparation can refuse a binding change (including null) if another declared available video is missing, corrupt or unsupported. Conservative incoming reservations can refuse repeated imports near capacity despite final deduplication fitting. Lease cleanup is best effort when storage is unavailable; retained reservations expire within 15 minutes.

One parent work serial and AbortController guard every decode, preview, staging and commit. Close/hidden/context invalidation releases candidate URLs and cancels staged reviews; late callbacks cannot publish into a new context. A transaction already committed stays committed even if cancellation races its result: the existing status tells the user to Reload to verify. Native number/file editing stays native; the existing controller editor handles the paired ranges and selects. This does not establish physical controller text entry, file selection, focus reflow or native download behavior.

## Original isolated-slice adoption checklist

The following checklist records the original UI slice before host adoption. Shared-manager wiring and versioned attempt/first-earned authority now exist in the successor source described above; native journey, original-transfer and release qualification remain separate.

Before adoption, wire all current ordinary/practice/course/workshop audio, still and story domains to one compatible manager together. Old v3 readers may receive `VersionError`; use compatible current recovery and exact original exports, never database deletion/downgrade. Add explicitly versioned attempt and first-earned story authority before any automatic post-win story or Collection replay. Then qualify one real win → optional Play/Skip → exact poster → Collection Replay, paired fresh-origin backups, missing-original recovery and cold offline playback. Existing v1 `story:null`, picture pins and earned receipts remain strict; a source binding alone is not a reward.

Focused tests exercise real Blob/hash/store/CAS/transfer data through the actual panel handlers. Native metadata, frame callback/Canvas, DOM defaults and controller samples are modeled and labeled. No actual browser, physical device, shared-host migration, disk download, offline or public release qualification is claimed for this optional extension. The [authoring examples](../authoring/prompts/story-workshop.md) keep these boundaries explicit.
