## Reproduced native range discrepancy

On 2026-09-15, root observed that Studio correctly retained the shared record while Settings displayed a different value. Settings used a `0.05` step and Studio used `0.01`: Settings snapped `0.11`/`0.12` to `0.10`, and `0.13` to `0.15`. This was a step-grid display mismatch, **not evidence that Studio persistence was broken**. The separate `change` event fallback has its own modeled regression; no captured native event sequence establishes that it caused the original observation.

After aligning shared-master steps to `0.01` and freshly reloading the source preview, root used Studio Home → Right to obtain `0.01`; closing showed Settings `0.01`. Reopening and pressing Right twelve times obtained `0.13`, and closing showed Settings `0.13`. The retained [accessibility text](native/settings-master-13.txt) and [screenshot](native/settings-master-13.jpg) show the latter value with the playlist paused. Their exact hashes and root-reported journey are in [native-range.json](native-range.json). This is a source-preview keyboard observation; reload/cross-mode persistence beyond that stated journey, audible output and physical devices are not inferred.

Root subsequently observed `0.13` after a full Solo reload and in [Versus Options](native/versus-master-13.txt), [Team Options](native/team-master-13.txt) and [Asset Studio](native/asset-studio-master-13.txt). Both saved/draft **procedural** auditions visibly started while muted, followed by explicit unmute/mute and Stop both; the [final capture](native/paired-preview-stopped.txt) retains two stopped statuses. These later observations extend the earlier range checkpoint without implying audible listening or a simultaneous native-file audition pair.

Two [owned MP3 test signals](fixtures/README.md) were generated with `lameenc` 1.8.4, imported through the UI and natively verified at 2.0375 seconds each. Root observed one attached audition with `muted:true`, `paused:false`, `currentTime:0.038984`, `readyState:4` and `duration:2.0375` while master sound was muted; those scalar values are attributed to root, not an independently retained DOM dump. The saved library reached generation 2 with two MP3s and one playlist. [Transport observations](native/owned-mp3-transport.json) then show falling-chime playing while muted; explicit Pause/seek `0.2`; and Unmute then Mute preserving that same paused track and position. Decoder readiness and native state do not establish audibility, loudness, composition quality or iOS volume behavior.

Both current and draft native previews decoded; after clicking both Play controls, [the direct DOM record](native/paired-native-mp3-muted.json) shows both `paused:false`, `muted:true`, `readyState:4`, duration `2.0375`, with times `0.102795`/`0.035372`.
