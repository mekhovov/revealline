# Copying an earlier saved flight into an indexed profile

The public v0.57.2 recovery journey successfully reviewed a real suspended First Signal flight from v0.42.0, but Copy refused with “Replacing indexed chapters requires explicit backup.v2, including an explicit empty index.” The older release had no saved player profile, packs or external index. The destination had imported an authentic backup.v2 with an explicit empty external index. Before/after observations retained every localStorage value and IndexedDB store digest; the failed Copy changed neither profile.

The transfer assembler previously converted a verified absent source index into backup.v1. Its own current target correctly rejects that incomplete replacement once an index exists. A transfer reviewed through the trusted, source-locked external snapshot reader now produces backup.v2 with an explicit empty index when that reader proves absence. The raw null source still participates in the second read and fingerprint; nothing is written back to the earlier release. The callback-omitted legacy transfer path remains backup.v1, and ordinary backup.v1 files still cannot strip an indexed target.

The regression constructs a real 20-tick suspended First Signal flight with no saved profile, verifies it, then copies into targets with both empty and populated indexes. It exercises the actual external backup companion and commit/Undo path, including retained original media and unchanged source storage. The initial fixture incorrectly supplied an already-enveloped snapshot to a callback that expects ordinary contents; its failed output is retained separately. After that fixture correction, the old runtime reproduces the exact public refusal.

All 77 focused tests pass with no failures, cancellations, skips or todo; scoped lint and formatting pass. Independent review found no concrete blocker in the candidate-only adaptation.
