# Restore preserved original FPV package archives

This is a preservation record. It does not publish a player release, change immutable pins, qualify a new combined package, repair player storage, or convert a failed native attempt into a pass.

All original paths, byte lengths, SHA-256 values, release asset IDs, server digests, full-download verification and source-before/after checks are in `release-assets-manifest.json`. The 17 originals cover both regional-family qualifiers (81c0d658 and 8ab04b8d), including their original GitHub artifact containers, six source/distribution ZIPs and Company containers, plus the exact metadata-listing FPV Worlds distribution with SHA-256 `90d2cabcebd8c4647f6abced993dfb5c40f4a19bd5829a0e15c0b5bfc321f692`.

The storage location is preservation release **414505790**, tag `fpv-development-preservation-20261016`. It remains Draft and authenticated. Its temporary browser URL is [the draft preservation release](https://github.com/mekhovov/revealline/releases/tag/untagged-9a5982b8261a24c31535). Draft by-tag REST reads may return 404; restore uses numeric asset IDs rather than a tag lookup or a signed download URL. No Actions retention assumption is required for these preserved bytes.

1. Obtain this preservation branch and these files from GitHub. Source parent `b65d80f716b8db646bfdf5f714892f1c0f6409b0` and the earlier accepted 8ab source remain separate committed identities. The normal combined child has not acquired independent package/full-player acceptance merely because it is backed up.
2. Sign `gh` into an account allowed to read the draft release. Choose a **new, nonexistent directory** on an available filesystem. The destination's parent must exist.
3. Run `python3 restore-original-archives.py --destination /absolute/new/folder` from this folder. An optional `--manifest` selects an explicitly saved manifest. The helper downloads by asset ID, hashes every byte, checks length/SHA-256, and writes a restore receipt. It refuses an existing destination or output file; failures leave their partial file for inspection.
4. The helper restores ZIP originals only. It does not extract archives, recreate `/Volumes/alex`, open a browser, change player databases, build the app or start a renderer/server.
5. If a review runtime is later needed, choose the exact original distribution ZIP and extract it into a separate new empty folder after verifying its manifest hash and safe headroom. The 9213 and 9214 fixture files are preserved in sibling snapshot folders. Their recorded `web/runtime` links originally pointed to alex; a restored review must explicitly point to its newly restored runtime. Preserve the frozen fixture files and their identities. A restored server has not by itself repeated native acceptance.
6. Keep old failure evidence and package identities. 81c's reproduced focus HOLD is distinct from root's narrow 8ab synthetic component acceptance. The public saved-map failure, physical devices, true offline/browser restart, normal combined player and performance gates remain open.

Pre-upload inspection recursively checked each ZIP and nested ZIP for unsafe paths, accidental credential/environment members and credential-shaped text. No forbidden file was found. A broad scanner matched two AWS-ID-shaped substrings in the known Rapier vendor's embedded base64 WebAssembly. The exact module matched committed public source SHA-256 `02dc6a4e2fffc013bab08fbb44fa68f501d8303615e9afe4c7d89ad4eedda0d0`; decoding confirmed the WebAssembly magic/version, and every match was inside that literal. The original broad result, the narrow review and the reviewed preflight are all retained. The module and archives were not modified.

All release assets use unique qualifier/hash-prefixed names. Existing release assets were checked by digest before uploads; no asset was clobbered, deleted, replaced or promoted. Each final manifest entry records whether an existing identical asset was reused.
