## Delivery gates

1. Resolve and independently review the integrated diff; run focused regression
   checks and source validation, lint and formatting.
2. Push the source branch and open a reviewed PR. Run every required hosted CI
   family on its exact head. Repair failures; do not bypass them.
3. Merge only the qualified head, then freeze its exact versioned source and
   distribution through the existing hosted qualification workflow.
4. The single release owner publishes the immutable release and reviewed Pages
   selector. Keep current and previous playable builds and the 950 MiB guard.
5. Verify successful deployment, the public version/source marker, asset binding,
   and playable entry. Only then resume new plan implementation.

Every subsequent completed increment follows the same PR → tests → versioned
release → Pages → public verification sequence before starting another increment.
A local commit or a source PR merge is not a deployment. A successful technical
release is not evidence of human enjoyment, accessibility or balanced difficulty.
