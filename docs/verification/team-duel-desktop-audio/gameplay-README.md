# Native normal-gameplay audio observer

This separate development observer complements the unchanged capture35 and codec102 probes. It observes an explicitly staged local candidate through ordinary gameplay. It does not install an uploaded theme into the public game, approve a release, drive input or provide acoustic/listening acceptance.

The caller stages a genuine Studio export with the production bundle reader/compiler in a new ignored output directory. Serve its exact compiled current manifest and hash-addressed assets as a local candidate, retaining the source's unchanged historical manifests/assets for approved actor leases. Never relabel a theme revision or alter admission pins. Team Originals `twin-landings` supports a positive `fpv` candidate revision; the legacy reviewed-picture route retains its separate admission guard.

## Installation and ordinary play

In a candidate-only entry loader, import the exact `Soundscape` module used by the normal host, install the hook in that same window, then import the unchanged Team or Duel host. Importing a class only in the outer frame cannot observe a different iframe realm.

```js
const observer = installGameplayAudioObserver({
  Soundscape,
  window,
  document,
  AudioContext,
  AudioBufferSourceNode,
  metadata: { sourceRevision, bundle, runtime, slots },
});
```

The caller supplies source, export, compiled-runtime and original-slot pins in `metadata`; the observer retains those declarations without independently certifying the transport. Retain the exact candidate loader/HTML/source overlay bytes separately. `slots` may preserve full selected asset records, including their nested `file` fields.

Open `gameplay.html`, choose the same-origin candidate Team/Duel page and use its ordinary controls. Its default is Team Originals; copying the page into `game/review-audio/` retains the candidate URL prefix. A first natural event may use fallback while the custom original decodes. Let decoding finish, then use an ordinary later event or Retry. Recoverable Team downing is a warning; terminal defeat is the applicable failure cue. Do not call `events()`, preload buffers, reset engines, advance clocks or hold decoding to manufacture a result.

The outer page displays and downloads the iframe's same-origin observation. **Refresh observation** only reads; **Stop observing** restores wrapped methods without stopping gameplay or audio. Reload the candidate to begin a new observation. These controls may move focus, so use the game's explicit Resume when needed.

## Reading the record

For a custom-cue claim, join the actual delivery's event/status, voice semantic name, board and source ID with a successful native `start` record and its native buffer ID. Join that buffer ID to the decoded original SHA-256. Inspect `fallbackBufferNames`: it records identity-equal buffers in the ready FeedbackDirector bank. A custom `failure` voice with a separate buffer ID and no bank match distinguishes it from the `loss` fallback even when both originals have the same SHA. Unknown or omitted hashes do not qualify a cue.

The observer preserves original method receivers, arguments, return values, Promise identity and errors. Hashing copies an encoded input before native decoding can detach it; it never replaces, delays or fabricates the decoder result. Decode rejection and observer hashing errors are distinct. Pause/master/context/disposal fields report observed state, not proof of silence or audible output. A context is closed only when an actual reported state says so; navigation does not imply asynchronous closure completed.

Records are bounded to 16 sound owners, 240 deliveries/notices, 400 native starts and 128 decoded identities. Each hashing input is at most 8 MiB with at most eight pending hashes. Event lists and labels are bounded; evictions and omitted hashes are counted. Continuous complete history, every codec/slot, full-game progression, perceived distinguishability and acoustic quality remain outside this observer's claims. It is not suitable for performance comparison.

Those tests use finite classes to verify observer semantics and identification; they are not native gameplay evidence. Native receipts and source transport records must be retained separately after actual play.
