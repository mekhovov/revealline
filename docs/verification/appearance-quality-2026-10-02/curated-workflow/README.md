# Curated custom-theme workflow evidence

Local engineering verification, 2026-10-02. No production publication was performed.
This evidence establishes the supported custom-interface workflow; it does not
approve every theme's artwork, all screens or target-device performance.

## Programmatic harness journey (not Cua UI proof)

`studio-sim-browser.json` records a programmatic Playwright Chrome desktop session at 1440×1000:

1. Create a named Porcelain-based Asset Studio workspace, edit its panel color and
   save a local revision.
2. Open the candidate in Company Studio. Its catalogue remains unchanged before
   explicit Apply, then contains the custom identity/name/revision and default.
3. Activate the real optional practice source link. Its new tab has `opener === null`
   and its own session storage, while the bounded consumed origin handoff delivers
   the exact custom interface palette and the base's pinned SIM collection.

The images are harness-only debugging evidence of the custom assignment and SIM interface. They are not Cua UI proof or approved user-facing screenshots.
Source export/reopen bytes are covered by the Company Studio host/model tests;
the browser harness did not establish a reliable download-event receipt.

## Packaging and scope

Academy remains **62 runtime files / 64 source files** inside its unchanged 64-file
and 8 MiB caps. Pure curated validation, transfer and seed contracts live in the
existing shared theme-system module; the authoring compatibility re-export is not
an added optional runtime dependency. No package cap was increased.

Candidates carry interface data plus exact installed Arcade/SIM dependencies.
They do not install arbitrary images, textures, fonts, audio, models, scripts or
CSS. The assignment action rejects unsupported selected asset edits. See
[curated community themes](../../../curated-community-themes.md) for the complete contract and extension boundary.

## Excluded browser experiment

A later compiled-entry harness used a saved-unlock fixture against the password
gate. That run is excluded from acceptance evidence. Its process/server were
closed and its screenshots removed. Compiled and auxiliary behavior is supported
here by source and Node tests only; password-gated Cua/browser acceptance remains
unverified. No password, access-gate production code or published access boundary
was changed.
