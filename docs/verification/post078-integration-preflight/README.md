# Post-v0.78 source composition preflight

This is a read-only integration rehearsal, not source adoption, an accepted
release, or a completed phase. It compares base `6f851d1b`, qualified music
`e9434d03`, and held Team `8cffb36b`. No branch, index, producer or generated
default was changed by the rehearsal.

## Findings and required resolution

There are 18 overlapping paths: nine merge cleanly as text, five have conflicts,
and four generated/binary files require reproduction. `overlaps.json` pins each
input and the three-way preview. Clean text composition still requires runtime
qualification.

- Keep both build systems in `scripts/game-cli.mjs`: soundtrack distribution
  and retained Team presentation verification. Include soundtrack entry names in
  the retained verifier's excluded optional bodies; build all entries before
  final verification. Preserve the music branch's lazy formatter loading.
- Preserve the accepted music production ledger, then append compatible optional
  Team slot contracts and combined recipe successors. Do not choose the Team
  binary wholesale or merge histories by revision number. Actual candidates have
  38 conflicting asset records and three conflicting theme records (`fpv39–41`).
- Team's explicit optional-slot migration supports this composition. A pure
  rehearsal imports both actual binary bundles, appends six Team-only slots to
  the music ledger, preserves every existing music selection and historical
  record, and verifies idempotence. Three checks pass on Node20.19.5 and22.22.2.
  This proves the schema path, not the final combined recipe or artwork review.
- Union the producer's fingerprint inputs: Team role registries/manifest-path,
  required-look preparation, and all music library/player inputs. Existing
  recipe review hashes cannot approve changed combined sources. Generate a
  source-stage successor, inspect it, then append a reviewed successor with
  actual evidence. Update current picture bindings only to that final identity.
- Preserve exact previously supported runtime manifests and dependencies under
  their hash-derived names. Never rebuild an archive from a different branch's
  conflicting revision. An unpublished Team candidate does not automatically
  become a supported historical receipt.
- Reproduce compiled manifests and binary bundle from the chosen ledger and
  final producer. Run retained-presentation, production-history, soundtrack
  distribution, saved-flight, rendering and input cohorts against the final
  source, followed by the normal release gates and public inventory.

until accepted post-v0.78 main. Their browser and modeled-input evidence cannot
qualify a different composition. In particular, the older Solo568px landscape

requiring fullscreen. Browser chrome and installed mode must be tested
separately ([WebKit safe areas](https://webkit.org/blog/7929/designing-websites-for-iphone-x/),
[Safari layout guidance](https://developer.apple.com/videos/play/wwdc2021/10029/)).

prompts, not only an injected A button ([Steamworks compatibility](https://partner.steamgames.com/doc/steamhardware/compat?language=english)).

asset property. Both setup failures are retained locally; the corrected fixture
uses original Git binary bytes and explicit slot identities. The TAP JSON files
preserve exact final output without whitespace normalization. No device,
audibility, offline, complete production or public verification is claimed.
