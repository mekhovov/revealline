**Frozen artifact integrity passes; frozen offline preparation failed.** The unchanged `v0.17.0` release at source commit `a38156e337bd274bb38231e9b408abd10d56404d` has a verified source archive, exact archived-CLI rebuild, 142 loose outputs, 138 manifest assets and 139 ZIP entries. Those [integrity results](integrity-notes.md) remain valid. They do not certify browser Cache Storage installation, and this report does not mark the frozen browser journey as passed.

The frozen offline inventory is **135 files / 31,764,790 bytes**, build `9c9ead88556353f1cf1b97b737ef033eacb8e32a9807524300ce0898622fd4b2`. Independent [HTTP checks](../../../.cache/round-27/frozen-browser/http-inventory.json) fetched all 135 entries successfully with matching sizes and hashes. Successful HTTP reads did not establish successful cache writes.

The third result demonstrates success for that modified worker on its tested origin; it does **not** certify the original v0.17.0 worker or its normal install/activate lifecycle.

The observed failure is a `NetworkError` at the Workshop asset's `Cache.put`. The original implementation retains fetched Responses after hashing cloned bodies; the successful probe instead caches Responses constructed from the verified bytes. This difference supports testing a bounded repair. It does not establish the browser's internal cause or prove that retained response bodies always fail.

A read-only [disk observation](../../../.cache/round-27/offline-investigation/cache-footprint.json) recorded about **3.5 GiB available**, with the volume displaying 100% capacity. Disk pressure was present; a browser quota failure or disk-induced response-spooling fault was **not proven**. No cache cleanup was performed by this investigation. One operational correction to that preserved footprint note: port 8839 used the root CLI, and the extracted source directory had no active serving consumer.

## Release disposition

Keep v0.17.0 immutable with its successful archive checks and these failed offline observations. There will be **no in-place replacement** or claim that the diagnostic copy is the frozen release. A normal **v0.17.1** repair is being prepared separately; it must retain ordinary lifecycle safeguards and receive its own affected tests, artifact verification and actual frozen offline check before any success claim.

The 20 preceding frozen release trees and 21 preceding tag identities passed preservation in the v0.17.0 integrity audit. They, the new v0.17.0 tree/tag, all three probes and earlier evidence remain preservation inputs for the repair. This investigation added no runtime changes and reran no broad gameplay suite. It makes no public-host, physical-controller or native-runtime claim.
