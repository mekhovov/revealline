This slice extends the existing Extra large preference to Classic Snake Solo,
Versus and Team (`game/snake/play.html`). It depends on the primary text-scaling
foundation at `e40b8983c1a94605beb1376fa85741ac5d40bf1c`. The separate Snake hub
and other game families retain their existing Large fallback.

## Source inventory and size policy

The pre-edit static/literal deferred import walk found 377 modules and 21 loaded
stylesheets. `text-scaling-snake-inventory.json` records the baseline absolute
font declarations, including deferred settings tools, controller configuration,
offline/recovery panels and soundtrack tools. The native bridge and the direct
launcher are explicit dynamic boundaries; this is not a runtime coverage claim.

Existing shared sheets already consume the default-one text multiplier. This
slice wraps 41 remaining readable absolute declarations in Classic Snake and
the shared play/settings/touch-control sheets. An additional runtime-style scan
identified six absolute declarations in transition status and enemy statistics,
including their responsive variants. Snake-only overrides wrap these sizes; the
regression executes both style owners instead of relying on linked CSS alone.
The collection-stat projection is defensive, not a Snake-host navigation claim.
Each authored Standard size is
multiplied once by two, including responsive `clamp()`/`max()` results. Unitless
line heights stay unchanged. `em` and `inherit` follow their enlarged parent.
Snake's inherited body text uses the same multiplier. Theme tokens retain their
Standard value for Extra large, avoiding an additional Large-token multiplier.

The entry, first-paint bootstrap, live theme owner, display preferences and both
settings controls explicitly agree on the Snake capability. The shared generated
settings owner captures that capability at initial mount; a later lazy provider
cannot grant or revoke it. Unqualified hosts remain unchanged. Captions keep their
independent preference and receive the existing factor exactly once.

Control direction arrows, thumbnail seat numerals, and operation letters/checkmarks
inside logical board cells remain artwork. They do not change world geometry.
Readable control labels, DOM scores, quotas and live operation status enlarge.
The password gate remains a separate pre-unlock surface. No whole-game or formal
accessibility conformance claim follows from this source inventory.

## Layout ownership

The extra-large family sheet gives dialogs one outer scroll owner, lets headers
and actions grow, and keeps native `[open]`, `[hidden]` and settings-category
ownership. The chooser preserves its existing focus/list controller while cards,
filters and footer actions receive sufficient width. Result actions wrap and the
result summary follows the picture. Its legacy nested scroller and runtime sticky
footer become ordinary flow inside the outer dialog, so an enlarged footer cannot
cover focused result actions. Compact Home utilities explicitly place by row, and
Pause rules target the actual native dialog to outrank the shared ID branch.
Live HUD groups wrap; numeric values do not
split into separate digits. The stage can scroll when enlarged HUD text needs
more height, retaining a minimum visible board region without changing its logical
cells or the player's seat arrangement. Touch-control dimensions remain separate.

bounded source closure and exact multipliers, not browser-computed typography.
