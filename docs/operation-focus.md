# Completed-operation focus

Chapter selection and Library installation temporarily disable their initiating buttons. Keep the actual focused control before disabling it, then return focus after completion or error only while that operation still owns the user's attention.

`captureOperationFocus` is a disposable UI lease. It never runs an action or opens a dialog. It requires the original connected, enabled and visible control in the same foreground dialog, and empty or still-owned focus. Another control, input outside the owned controls, a dialog transition, true window blur, hidden document or pagehide retires it. Consume the lease before calling focus so reentrant handlers retain authority.

A capturing window blur listener also receives non-bubbling descendant blur. Require `event.target === window` for loss of page focus; disabling the owned button must not invalidate its own lease. Test the actual event target and capture path, using one Window identity.

The chapter adapter requires an observed busy cycle and the same mirrored card; external native selection or destruction cancels it. Library keeps its existing task/check/commit/abort authority. Automatic completion and explicit Cancel have separate intent. Tabbing elsewhere retires the automatic lease. Activating the actual focused Cancel button captures a fresh lease before abort, with `restoreTo` constrained to the original connected opener in the same dialog. Cleanup can still retire it through newer focus or backgrounding. A detached durable operation abandons focus restoration without claiming rollback. The connected builtin Install button survives refresh. A separate explicit Remove adapter can resolve a logical successor after installed rows are rebuilt; other disconnected controls still receive no automatic fallback.

[Retained evidence](verification/cross-mode/p03-operation-focus/README.md) records the first native failure, the corrected event boundary, full affected-file tests and the limited native journeys. This does not change saves, gameplay, content identity or the strict profile format.

Reviewed 2026-09-15: the [W3C modal-dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) describes returning focus to the invoker on close, with a logical alternative if it is gone. [Xbox accessibility guideline 112](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112) calls for predictable UI focus. Returning from an explicit operation Cancel is RevealLine’s application of predictable focus; neither source prescribes this lease implementation.

## Installed-pack removal

Remove from device explicitly opts into the internal synchronous logical-target resolver. It captures the selected pack ID/version, the displayed neighbor order and the Library visit before starting. After settlement and the final refresh, it checks the exact current pack model, render generation and task generation. If the same pack/version remains, return to its recreated Remove control. If it is absent, prefer the next surviving captured row’s first Play action, then a previous surviving row’s first Play. With no exact eligible neighbor, or a different-version replacement under the selected ID, use the existing Expansion packs section button. Focusing Play never activates it.

The target must still belong to the same visible Library section and open dialog. Resolve only while the original focus lease remains live, recheck after the resolver, then retire before focusing. Newer focus, input, navigation, a dialog transition, backgrounding, a changed model or another task veto the handoff. Fixed-target callers keep the earlier contract. No persistent preference, content format or public API version changes.

Removal enters durable commit before its first await. Stop waiting therefore remains detached and never promises rollback or a later focus return. Derive the destination from the actual settled pack model, including errors after a model change; do not infer that a rejected promise proves the pack survived. Existing writer/currentness and active-pack behavior remain authoritative.

## Score and Collection paging

Keep each pager's Previous, count and Next elements instead of rebuilding them on every page. Update the existing controls' page, callbacks and disabled state. An enabled focused action needs no additional focus call, but page growth can still move it below the viewport. The pager alone opts into nearest, synchronous reveal after settlement, including this same-target case. If the owned action becomes disabled, focus the opposite enabled action; if neither is available, use that view's search field. Collection hides and detaches its pager when only one page remains, then reuses the cached controls if more pages return.

Capture the actual focused pager action before rendering or reading picture metadata. A later focus/input choice, dialog transition, true window blur, hidden document or pagehide retires the same operation-focus lease used by the other explicit adapters. Recheck the current Collection generation and library model before rendering and resolving focus. Target lookup and cleanup must preserve reentrant newer work; a missing, disabled or foreign-root target never receives focus.

An automatic refresh during a pending read transfers the existing lease to the newest pager render owner. It carries that lease's retired state too: it neither loses a still-valid handoff nor grants new permission after the player moved elsewhere. The old read loses its lease reference and cannot settle or cancel the newer owner. Only a fresh activation of the actual focused pager action captures new intent. This remains an internal presenter detail, with no profile, saved-game or public API version change.

A reveal consumes the lease once, keeps veto listeners through any focus callback, then rechecks the current resolver, exact active target, same open dialog, connection, eligibility and foreground before scrolling. A newer focus or lifecycle decision prevents both focus and scrolling; recursive restoration is refused and cleanup runs even if a focus or scroll callback throws. The helper keeps its existing return semantics and default behavior for every other caller. ## Returning from a Collection picture

Picture Back has a separate logical-target adapter. Store the originating Collection card with its stable key, page and query. At the queued child-close listener, admit a focus lease only if native close has actually restored that same connected card. Capture before `populateGallery` rebuilds it. A newer Search or Close choice is not the picture origin; an already detached origin that leaves BODY has no automatic return claim.

After metadata settles, retain the same library object, Collection population and picture generation. Resolve the current keyed enabled card, then another enabled card, then Search through the existing order. The shared helper rechecks foreground, ownership and the target's visible dialog after resolution. Retire on settlement, failure, another picture or Collection close. This owner must remain independent of paging and import/export owners; it never changes scores, results, Replay adoption or image release.
