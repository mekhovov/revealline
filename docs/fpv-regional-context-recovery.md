# Shared flight graphics recovery

The same renderer is reused across ordinary and regional flights. Previously, when a regional flight created it first, graphics-context loss paused the simulation but omitted the ordinary host’s recovery message and preparation reset. This made recovery guidance depend on which mode was opened first.

Both construction paths now share one host handler. It clears readiness and pending quality presentation state, pauses existing input/simulation, shows localized Menu/Retry guidance, and immediately refreshes the HUD and disabled Arm control. The renderer retains its existing resource-release behavior. Context restoration alone does not arm or mark the scene ready; explicit Retry rebuilds through existing verified preparation. Pause/setup controls also refresh from the shared shell’s surface lifecycle, independently of rendered frames. Previously the first menu opened after context loss could contain blank, uninitialized controls because drawFlight no longer ran; recovery now exposes the actual Regional free flight/Retry controls and hides unavailable setup. This reuses the same refresh functions without new per-frame snapshot calls. No physics, input mapping, ownership, proof or package contract changes.
