# First-earned picture view resolver

`ui/earned-picture.mjs` is an additive view adapter for Collection integration. It does not open a database, install content, award progress or modify a profile. `resolveEarnedPicture({item,receipt,metadata,entries})` validates an explicit receipt against the exact execution-to-authored owner. A managed original uses its retained owner, historical presentation revision and first-earned seed. Later assignment and better-score gallery metadata cannot replace that choice.

An installed exact campaign allows normal replay and celebration. With a removed pack, a verified managed original still has its retained map geometry and can be displayed; replay and theme celebration are unavailable until the actual pack is reinstalled. Retained owner data is validation context, not an installed campaign. Missing or changed original/history fails explicitly at acquisition and never selects today's assignment.

Collection labels separate the picture's best-score run from the level's best medal. The picture score, run medal and time come from its existing exact campaign/level/theme gallery row. The level medal comes only from that campaign's exact level clear; Standard and Gentle records are never combined. A Silver run worth 14,410 points can therefore remain the picture's best score while a later 13,820-point Gold run supplies the level's best medal. Missing or unsupported clear metadata leaves the score-run medal visible without inventing a level best.

These labels are a read-only view. The immutable first-earned picture receipt still chooses the original, seed and presentation revision, independently of later best-score and best-medal records. Opening Collection changes none of those records or stored profiles. The three label projection cases and complete 35-case modeled Collection file pass on both Node 22 and Node 20 (38/38 each). The retained initial run failed seven old text assertions; their expected wording now matches the intentional labels while preserving the loading, mode, score, time, stale-image, focus and no-mutation checks. Actual browser layout and release delivery remain separate.

No-receipt rows preserve existing authored-pack behavior. Explicit legacy receipts validate their installed owner and retain their first seed; their original embedded pack art is unavailable if that pack is removed. A legacy receipt is not a copy of the original file.

`acquireEarnedPicture` adds verified byte/decode acquisition and returns an owned backdrop/release handle. The caller owns cancellation and visible-canvas staging and must release on replacement/close. The source Collection now uses this adapter for managed thumbnails and full pictures. It stages complete decoding before changing visible pixels, cancels late work on Back/close or a newer selection, and restores normal keyboard focus. Installed-theme celebration and replay use the existing exact-content paths.

Four focused tests run real captures to produce receipts, then test removed-pack Gentle acquisition, changed assignment/better seed, foreign ownership and legacy behavior. The image decoder and IndexedDB boundary are modeled. An initial raw-versus-normalized geometry comparison incorrectly rejected an installed Standard map; the corrected adapter compares effective normalized levels. Independent review also found the explicit legacy branch needed owner validation and first-seed preservation; both have regressions. These initial tests are preserved as model evidence. Integrated source now passes all six gates/2,707 tests. Actual source-browser Collection retains first-earned A after assignment B and a better B win, including paired originals/JSON recovery. The [38-artifact receipt](feature-delivery-workflow.md#current-still-integration-evidence) does not certify actual removed-pack browser recovery, cold offline recovery, frozen/public delivery or physical devices.
