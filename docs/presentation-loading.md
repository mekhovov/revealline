# Presentation loading contract

P01 implementation contract, September 2026. Release acceptance belongs to the [cross-mode execution register](cross-mode-execution.md), with exact source, version, public bytes and browser evidence recorded separately.

## Feedback and ownership

Use `createOperationStatus(target, { isCurrent })` from `game/ui/operation-status.mjs` and the shared stylesheet. It creates a three-pixel activity signal, a polite live text label and an optional native progress control. Text and geometry require no downloaded image. Reduced Effects and the operating system's reduced-motion preference stop the animation while retaining the message.

`begin({ message, stage, progress, isCurrent })` returns a lease with `update`, `finish` and `clear`. Progress is either `null` or a real `{ completed, total, unit }` measurement. Unknown duration remains indeterminate. Terminal states are `ready`, `error`, `cancelled` and `detached`. A new lease, owner clear or disposal invalidates older DOM updates. Phase messages change the live text; numeric increments do not repeatedly announce the whole operation.

The presenter does not own tasks, storage, focus, cancellation or disabled controls. Each host keeps its existing operation identity and transaction boundary. A stale `finally` must not enable a newer operation's controls. Keep cancellation and navigation reachable. Do not make their containing dialog inert. Describe whether Cancel aborts an uncommitted candidate or merely stops waiting for shared/non-interruptible work. A detached save can reconcile its actual outcome through the same current lease; it cannot claim rollback.

Pending Start, Retry and confirmed Restart must also accept keyboard Escape and controller Back. After the active modal and course have handled Back, route only the current picture-launch owner through the existing preparation Cancel action and restore Start focus. Do not treat speculative prewarm, saved restoration, theme preparation or settled recovery as that owner. Test late decode success and failure, unchanged saved checkpoint/artwork and ordinary ready-state Back through the mounted input routes.

A file picker has its own `cancel` event when dismissed or when the same files are selected again. It bubbles from the file input and is not a request to close its containing dialog. A dialog's `cancel` handler must first require `event.target === dialog`; only then may it apply the existing Escape/Back, busy-operation or detail-collapse policy. Leave child events untouched, including retained file selections, draft/review state, status, focus and durable work. Test a bubbling non-cancelable child event separately from a non-bubbling cancelable dialog event. The [P01 file-dialog finding](verification/cross-mode/p01/native-file-dialog-cancel.md) records the affected hosts and native evidence limits.

An implemented operation also needs a normal visible entry. Replay export keeps its original `#export-replay` button in Workshop beside Replay Theater, reached from Pause → Main menu → Workshop. Do not leave required operations in the shell-hidden footer or add a proxy with separate enablement. Preserve the existing recorder, download lock, top-layer dialog and exact visible opener. Exercise the route through scoped keyboard/controller navigation and verify the exported checkpoint; direct hidden-button calls alone do not prove reachability. Native geometry and download outcomes remain separate checks.

Report an operation before its first delayed boundary. Keep the indicator beside its activating action or at the top of the current screen. A status below a long form does not acknowledge a visible action. Static direct-route feedback must exist before the main module runs. Main game boot also prepares styles after its independent initial loading card is present, and fails visibly if a required stylesheet cannot load.

A modal's status must belong to that modal's top layer. Craft preparation moves the original renderer status into the mission dialog's sticky feedback slot for both selection and direct briefing, restoring its exact original position on actual close or disposal. Preserve its one presenter, late-load guards and live region. A queued old close must not remove current feedback. Cosmetic preparation remains nonblocking; do not add a second load, Cancel policy or focus change. The empty/ready slot collapses, while an error remains readable.

Keep the active label concise. Optional pack catalogues and explanatory background belong in expandable details, so changing progress cannot push its count or Stop control out of the player's view. Offline observations provide a concise `summary` while retaining the complete `message` for existing consumers and diagnostic details. The panel uses the summary when available and preserves the message fallback. Qualify this with the full shipped optional-pack list, not only an empty or single-pack fixture.

Library operations use one sticky status area inside the existing dialog. Move the original status and operation-specific Cancel nodes there; preserve their IDs, handlers, presenters and transaction owners. Restore their exact sibling positions when closing or clearing the area. Remounting the same active owner must preserve focus. A cancelled backup read can retain its busy lock until it settles; its late cleanup may clear only its own status. Reopening detached work must show its current result without starting another operation. Keep full details keyboard-scrollable and escape controls at least 44 CSS pixels, including when the activating action is deep in a scrolled section.

Sticky feedback must not cover the focused control. Measure its actual lower edge after layout and scroll only enough to expose the current focused control. Where a modal also has a sticky action bar, measure that upper edge as the available space's lower boundary. Missions uses one heading box for title, Back and feedback, with `attachFocusClearance` accounting for both sticky regions. Do not restore a remembered opener, scroll on ordinary touch/wheel movement, or move focus. Skip disabled, hidden, outside-dialog and feedback-region targets. Close above the feedback retains its own destination. When an editor is taller than the remaining space, keep its beginning clear instead of scrolling it back underneath the status. Reset the scroll inset on clear or disposal.

Capture an initiating action's focus ownership before disabling or hiding it: native blur can move focus to the document body. Restore the existing return action only after a successful current operation, while that ownership remains valid. Later user input, focus movement, window blur, hidden document, cancellation or disposal relinquishes it. Controller Apply follows this rule without changing its transaction or bindings. In native checks record the actual element, action, `:focus` state and next Tab destination; an empty element ID does not prove lost focus.

Playground keeps the original editor, replay-verification and child-preview status nodes in one bounded sticky reading area. Their existing presenters and epochs remain independent. Put the current owner first visually; retain other pending messages and their Cancel controls. Only an owner switch may reset the message area’s scroll, while an actively read message keeps its position. Ordinary progress must not move page scroll or focus. The child remains loading until its actual readiness marker, and page-history restoration reconnects exactly one clearance owner. Exercise both replay file and pasted JSON, Generate/Undo, and the real child return.

Imported Music audition reports beside its Audition/Finish controls, outside conditionally hidden transport details. Call play in the original activation turn, then synchronously refresh the visible controls before awaiting playback. Finish must remain reachable while that promise is pending. A stopped or superseded audition cannot publish a late result, persist audio activation, revoke the replacement URL or restore music twice. Keep master sound behavior within its own phase.

Original-image recovery labels follow the current review handle. Successful verification updates both the selected summary and option; reverify, reselection and a fresh review clear that label before waiting. Describe verification in the past tense and retain the reminder that file preparation rechecks the original. A failed preparation must keep its own error and existing handle/link ownership; labels never change the reader’s immutable inventory or imply an earned picture.

## History return and picture ownership

Leaving the game releases its profile writer permanently for that page. A back/forward-cache return stays paused and session-only; it must not silently claim a fresh writer or replace saved picture pins. Retire speculative picture preparation on `pagehide` even when Start never joined it, abort the retained owner's pending work, and require the exact prewarm lease before publishing a late success or error. Keep already decoded images and immutable pins available for explicit Continue/Resume.

New attempts still resolve approved release artwork in a session-only page. Reuse its exact retained asset/presentation history without downloading or writing. If additional history must be saved, stop before downloading and explain that a new picture needs storage. Offer the existing game-data export screen and a deliberate reload of the saved profile; do not call this missing/corrupt media or silently select legacy artwork. Recheck writer ownership at the commit boundary as well. A commit already completed before cancellation remains durable, but its cancelled attempt cannot adopt a late pin.

Background picture preparation can fail before Start joins it. Publish that current error through the inline preparation presenter as well as the existing general warning, so its reason appears beside Retry/Export/Reload. The fallback must not take over an active launch, restore/import operation or theme operation. Stale/aborted prewarm remains fenced by its original owner, and no cancellation action is created for an already settled failure.

Keep the complete preparation reason and its recovery actions visible together at Standard text in portrait and short landscape. Use shared control typography and available panel width; never truncate the explanation or reduce touch targets. Constrained Large/zoom layouts must retain readable text and keyboard/touch scroll access, with no hidden overflow trapping actions. Verify initial visibility separately from actions reached by deliberate scrolling.

Keep a settled writer-recovery message and its actions while the same picture owner, run and theme opens a secondary dialog. Export must return directly to the visible Reload action and its original invoker, without requiring Check picture again. This exception applies only to terminal recovery: pending preparation still cancels on pause, and explicit retry, world/context replacement, saved restoration and page retirement clear the previous recovery. The [export-return correction](verification/cross-mode/p01/picture-recovery-return.md) preserves the public finding and its scoped regression.

The [history-picture correction](verification/cross-mode/p01/history-picture-return.md) records the public failure, focused source checks and remaining native/release evidence. Test an abort-ignoring late rejection, retained exact artwork, read-only saved Continue followed by explicit Resume, and a cancelled display decode separately from pre-commit validation. Preserve the writer lease, raw saves, run/checkpoint and original hashes in each applicable assertion.

## Existing integration boundaries

- Solo Deploy, saved-flight restoration, theme preparation and Retry retain their exact run/theme/generation guards. Foreground Start observes an existing picture prewarm promise. It must not restart download or decoding. Cosmetic craft/release decoration does not hold a playable run. Required-picture failure retains the original paused flight and explicit recovery actions.
- Earlier-release Copy is an explicit replacement of the complete reviewed collection. When the trusted locked external snapshot proves its index is absent, prepare an explicit empty backup.v2 index so Copy can replace a current indexed profile. Retain the raw source snapshot in the recheck/fingerprint, all source locks and zero source writes. The callback-omitted legacy path stays backup.v1; ordinary v1 files must still refuse indexed replacement. Verify actual Copy/Undo and retained originals, rather than treating a successful Review as adoption. See the [legacy transfer correction](verification/cross-mode/p01/legacy-transfer-index.md).
- Content callbacks report download, verification, storage and readiness around existing authenticated-content coordinators. Presentation metadata stays outside campaign and simulation identities. A completed durable write remains authoritative even when its screen has closed.
- `prepareOffline` and `checkOffline` accept `signal` and `onStatus`. Aborting the signal detaches this observer, not the shared service-worker installation. The versioned progress protocol is bound to request, build and scope, while legacy clients retain terminal-only replies. Inactivity is distinguished from proven failure; Check progress rejoins existing work. A waiting update retains the close-tabs instruction. The ready marker still follows verified bytes.
- Studio, Library, backup and media editors use local operation owners. Save/import atomicity, revision checks, source bytes and separate draft storage remain unchanged. Native downloads describe a requested download, rather than claiming a file was saved.
- Music preparation appears in `snapshot().preparation` without altering `status`, `playing` or `desired`. Enable/play requests retain the original user gesture. Background cue decoding keeps the existing immediate fallback and never replays a late cue.
- Couch and Replay own their preparation and current-board identity. Embedded Playground readiness uses the child's actual boot/tool-ready marker, not the iframe load event. Controller Lab retains its authenticated session messages and neutral-input gate.

## Couch/Team continuation supplement

The current candidate extends A45/A46 Versus picture preparation and A47 Team preparation without replacing the historical P01 inventory. Ready owns only an untouched initial entry; a later settings, focus or lifecycle action can revoke an automatic handoff. Uninterrupted explicit Rematch/Next prepares and starts the accepted recipe in one action. Interrupted Versus preparation can finish at Ready and require a separate deliberate Start. Team Next interruption cancels that transition and retains Results; starting its successor requires another explicit Next. Pending Team Next retains the completed result, exact earned picture and counters until successor acceptance. Cancel, Back, failure and stale completion cannot award again, replace newer work or resume a paused flight.

Verify visible action/status placement, exact artwork, retained score, focus restoration and actual browser routes separately from modeled delayed/failure cases. Keep known rotation failures open until corrected and observed. See [Couch/Team delivery](couch-team-delivery.md), [Team ordered results](team-ordered-results.md) and [Versus formats](versus-session-formats.md).

## Qualification for a changed entry point

Exercise real delayed success, cached success, failure and retry. Then cancel or navigate away, start a newer operation and let the old promise settle. Check current run/content/draft bytes, disabled controls, focus and status ownership. Non-interruptible saves and shared downloads need separate observed and durable outcomes. No artificial minimum delay is permitted.

Async fixtures should await the owned operation or use `game/test/helpers/wait-for.mjs` with the exact readiness predicate and a bounded elapsed-time allowance. A count of immediate callbacks does not bound Blob, WebCrypto, module loading or replay timer yields. Keep short drains only for known post-resolution microtasks; preserve runtime deadlines, cancellation and identity assertions. Retain scheduling failures and controlled reproductions alongside corrected runs.

When a fixture verifies real installed originals, give its initial preparation and later equivalent picture waits the same documented local allowance. Audit all entry points through that fixture, including restoration, recovery and replacement; a single subtest override leaves the same mismatch elsewhere. Keep the shared ordinary-host default and runtime deadlines unchanged, and preserve explicit shorter allowances used to exercise a timeout boundary.

Review 1280×800, 390×844 and 844×390, Large/Plain text, applicable 200% zoom and reduced motion. Use keyboard, touch and modeled controller checks without presenting them as physical-device evidence. Record initial visual failures as well as corrected retests. Source-only assertions cannot establish visibility or successful public play.

Later phases must add new entry points to the A01–A56 loading inventory and rerun affected lifecycle cases. They must also preserve the six source gates, ordinary build, offline/artifact budgets and immutable release workflow.

## References

The shared label and separate native meter follow that distinction. The initial boot treatment addresses the stylesheet loading behavior described in [MDN's link reference](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/link).

The Library placement review also follows [Xbox UI navigation](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112) and [visible focus](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/113): preserve predictable focus after reflow and a reachable return action. These references guide the design; actual browser geometry, assistive-technology announcements and physical devices remain separate verification categories.
