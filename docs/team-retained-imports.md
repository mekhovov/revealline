# Historical Team presentation imports

An accepted `.rlteam` file contains its original picture bytes and an exact
theme identity. Preparing that file against the page's latest theme can reject
the import or change its appearance. `createOwnedCoopPresentation` stages an
independent host for the two unambiguous published FPV identities below. Ordinary
JSON imports, current missions and unsupported identities keep the existing
strict resolver.

Both manifests are preserved byte-for-byte as explicit inputs in
`authoring/library/fpv-field-kit/retained/` and as hash-named compiled outputs.
Their 124 distinct dependency paths per manifest already have identical bytes
in the current compiled assets. No new binary artwork or fresh-theme revision
is introduced. The ordinary retained-production compiler verifies their schema,
identity, dependency paths, sizes and hashes, and retains them in its ownership
inventory. Do not format or reserialize the original manifests.

## Ownership and recovery

The association is code-owned and exact: theme ID, revision and null collection
select one known runtime hash. The envelope's `receipt.manifestSha256` identifies
the uploaded envelope metadata, **not** the theme runtime. Uploaded URLs and
revision ranges cannot authorize an arbitrary presentation. Later FPV revisions
with multiple published lineages need a separate exact-identity contract.

The wrapper requires the authenticated live envelope owner, matching pack,
level and theme. It prepares a separate historical snapshot and picture before
replacing the accepted selection. Cancellation, failure and stale completion
retire the staged host and decoded resources without discarding the old run.
Retry retains the exact accepted snapshot and picture. A successful replacement
retires the prior resources; disposal invalidates future reads.

Team previews, preflight painting and accepted play use the same snapshot.
Temporary candidate painting restores the prior painter snapshot even on error.
The accepted published-audio reader belongs to that same lease; it never reads
the current page's assets under a historical identity. The page's global menu
appearance and current missions remain unchanged.

These older themes contain no modern `team.*` actor family. Their historical
fallback presentation is intentional exact restoration. Silently substituting
today's Team art would change the accepted appearance. This support does not
claim that a historical import meets current production-art standards.

## Offline preparation

The two original manifests total 1,946,423 bytes. They are an explicit optional
**Older Team import themes** download, with the shared and Team runtime
dependencies, rather than an addition to every player's core installation.
All existing retained manifests and asset dependencies keep their current
ownership. The feature does not raise the 64 MiB core budget.

Download that optional group before opening one of these imports offline.
Without the required manifest, preparation fails visibly and keeps the prior
attempt available; reconnect or prepare the download and Retry. No current
theme or procedural substitute is silently selected. This is dependency
accounting, not comprehensive offline or physical-device acceptance.

## Verification limits

The ownership regression source covers exact originals, Retry/Next, rejected
substitution, cancellation, disposal and replacement failure. It remains
**WAIVED_SKIPPED_NOT_PASSED** under the 30 September test policy. Reconstructed
fixtures are explicitly identified as such; they are not recovered user exports.
Source/dependency/build checks and any browser observations must be recorded at
their exact revision. Public bytes/play, listening and physical devices remain
separate publisher/qualification work.

[retained-production rules](field-kit-retained-production.md) before extending
the supported identity list.
