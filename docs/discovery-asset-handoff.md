# Exact pictures between Studios

Asset Studio and Picture Workshop can prepare the **selected exact picture** for
reward authoring. The transfer is the original PNG, JPEG or WebP file, with no
resize, screenshot or re-encoding. It introduces no bundle format or asset store.
Preparing the file offers an explicit download link; it does not publish the
asset, claim a completed disk write, save an assignment or grant a reward.

In Asset Studio, bind the intended raster revision and use **Prepare selected
picture for reward authoring** below its history. A font, audio file, procedural
recipe or unavailable original cannot use this raster handoff. Existing `.rltheme`
exports still retain the complete authored source, provenance and history.

In Picture Workshop, preview an original draft or choose a saved picture revision,
then use the same action. A frame captured through its optional video tool enters
the existing picture-draft path and can be transferred here too. This transfers
only that captured poster. It does not transfer the clip, trim video, invent
captions or replace `.rlmedia`/`.rlstory` backups. Source credits and video-frame
provenance remain in the originating tool and its existing exports.

In Company Studio or Level/Campaign Studio, open the discovery controls and use
**Bring an exact picture from another Studio**:

1. Company Studio supplies its selected edition. In Level Studio, import the
   existing Company source-draft JSON and select its owning edition.
2. Select an existing reward and choose teaser, earned image or registered
   character. Select the downloaded original and verify it.
3. Explicitly select the matching admitted asset. For a character, also select an
   existing allowed reward recipe that uses that exact image. Enter English and
   Ukrainian descriptions/titles and, for payloads, an explicit ID.
4. Preview the chosen use, then apply it. Export/import through the normal Company
   source packet or Level reward-sidecar workflow, and run edition validation.

The destination inventory must already declare the exact SHA-256, byte count,
local raster path, owning campaign and publication approval. Matching a filename
or a source declaration is insufficient. A new derivative still needs the
existing source/rights review and inventory admission first. No control in this
handoff grants approval. Restricted or unapproved dependencies are rejected by the
same selected publication rules; public editions cannot admit private originals.
Teasers/reveals require the owning campaign's explicit asset declaration. Character
images require its selected edition's existing reward-character allowlist.

Apply uses the existing immutable reward edit/rebind authority. It retains the
reward ID and requirement set and creates a new revision. A payload ID can replace
only the same payload kind; it cannot silently overwrite a knowledge paragraph
with an image. Separate teaser artwork cannot reuse earned media. Already promised
and earned revisions remain governed by the existing retained-presentation rules.

Preview reads only the explicitly chosen local original, never an imported URL.
Source changes, cancellation and disposal retire pending reads and release owned
preview/download URLs. The 4 MiB raster and existing edition/offline budgets remain
unchanged. The helper has no player-profile, reward-receipt or appearance writes.

Focused checks cover unchanged original bytes, all three uses, both Studio source
round trips and selected player compilation, negative ownership/rights and
payload-type cases, cancellation and twenty download cycles. Actual Picture and
video-poster handlers are exercised with modeled native decode/download boundaries;
this is not physical-device or public-release qualification. Complete clip and
soundtrack reward handoffs remain separate work.
