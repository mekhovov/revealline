# About catalogue loading

About provides optional software history and a same-release mission selector. Load their catalogues independently: a slow or unavailable history host must never stop local mission discovery. Static mode links, the featured mission and pack cards remain available during preparation. The live mission status identifies loading and its existing fallback; it must not imply the complete catalogue is already ready.

Each loader retains its own failure handling and the About navigation lifetime. Neither completion moves focus, navigates or writes progress. A terminal departure rejects late DOM updates; a cached page retains its live owner and neutral-input rules. Do not reset a selected pack when release history settles. The broad campaign-browser redesign remains separate.

The bottom campaign link returns to the game and says so; it does not promise to open a particular dialog. Preserve release-local URLs, including archive-hosted builds.

## Verification and prompt

Hold software-history headers or its body while delivering the actual mission catalogue. Verify all choices appear, keyboard selection updates the exact launch URL, and later history completion preserves that selection and focus. Reverse the delay, exercise independent failures, terminal departure, cached return and native/controller navigation without granting rewards or modifying saves. Ordinary browser input and modeled controller checks remain distinct evidence.

Prompt example: “Keep About mission discovery independent of preserved-software history. Retain static play routes during loading, truthful live status, validated launch URLs and current navigation ownership. Verify delayed/failing requests in both directions and no focus, selection or progress changes from an unrelated completion.”

This correction does not add request deadlines, new catalogue routes, physical-device qualification or campaign-specific offline readiness.
