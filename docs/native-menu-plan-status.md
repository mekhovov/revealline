## Delivery order

1. **Input safety and honest inventory.** Correct authoring keyboard scope and six legacy Confirm owners; mount Community and Controller Practice on the existing shared owner without another input poller. Keep the Practice session-checked child bridge. Fix disabled/high-contrast states, pending-tool metadata and candidate evidence attribution. Focused automated checks and real browser observations qualify this batch.
2. **Visible portrait animation.** Add orientation-specific regions on visible painted features for the five affected Dutch campaigns. Keep original raster bytes and the supplied aggregate DroneAid poster. Validate crop intersection using image dimensions and observe changing frames in the browser.
3. **Custom Solo landing.** Adapt the existing installed campaign player without replacing its runtime or saved edition identity. Move setup and recovery into Settings, expose a truthful Start/Continue and an in-pack selector, retain runtime controls, and restore focus to Play after successful creator installation.
4. **Mode artwork.** Four base worlds × three supported modes: retain the Solo scene, create distinct opposing/linked actor arrangements for Versus/Team using approved artwork references and separated layers. No unsupported multiplayer modes in company editions. Record prompts, provenance, bytes, static fallback and reduced motion; no palette-only substitute for composition.
5. **Creator acceptance and dependency integration.** Run each existing tool’s complete keyboard/controller workflow, including invalid input, cancellation, preview return and artifact validation; fix discovered gaps. Integrate the pending Demo tool and new Community routes with their owners. Keep imported content, saves and drafts intact.
6. **Aggregate qualification and publication.** Coordinator reconciles overlapping inputs, checks source/runtime/package identity and publishes via the main-repository-only process. Verify the actual public current bytes and player experience after deployment.

Each source batch is a separate commit with its own evidence. Independent source fixes can be integrated earlier if the canonical coordinator finds a compatible queue slot; batches do not create separate publishers or pre-allocate release versions.
