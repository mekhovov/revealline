# Field Kit reveal production

The [read-only prepared-art review](../authoring/library/fpv-field-kit/prepared/reveals/review.html) shows every exact game frame at 240 pixels wide and at native 1:1 size. All **38 distinct compositions, 44 exact exports and 56 FPV owner bindings** in the [production plan](../authoring/design-atlas/reveal-production-plan.json) are produced. The PNG derivatives total **2,087,270 bytes** (about 1.99 MiB). Artistic approval and actual game context review remain separate from production completeness.

The public review loads the same SHA-256-named PNGs as the compiled game, without including a second set of derivatives or any generated originals in the release. Localhost previews may fall back to the source derivative. Locating a retained original requires an explicit local action; unavailable images show a recovery message instead of a broken or misleading reference. Full source path/hash provenance stays visible in both environments.

Every composition uses a separate built-in `image_gen.imagegen` request. The shared art contract and full individual prompts live in `authoring/library/fpv-field-kit/reveal-generation-prompts.json`; the first four proof records live in `reveal-proof-sources.json`, and additional generated sources in `reveal-generated-sources.json`. Each record preserves the original tool path, project source path, exact bytes, dimensions, SHA-256 and effective prompt. Original files under `originals/reveals/` remain unchanged. No legacy image or reference-game pixels were copied into the new sources.

Run `node scripts/prepare-field-kit-reveals.mjs` to create missing derivatives and refresh the manifest for available sources. Run with `--check` for a read-only reproducibility check. A differing existing PNG is never overwritten: change the preparation revision and destination intentionally. The derivative pipeline fully decodes the pinned RGB8 source, chooses its recorded crop, samples pixel centers into a bounded logical grid, selects the nearest of 36 shared colors without dithering and emits exact registered dimensions with integer clusters. It then decodes the output and checks the RGB byte hash.

The 768×576 frame uses a 384×288 sampled grid enlarged 2×. The 1152×576 frame uses 384×192 enlarged 3×. The 1774×887 external frame uses 444×222 clusters enlarged 4×, clipping two pixels only at the final right edge and one at the bottom edge. There is no fractional stretching of these output clusters. This is a documented derivative preparation operation, **not proof that the generated source was drawn on a hand-authored pixel grid**.

Homeward has two separately framed derivatives per composition: full 4:3 and a 2:1 crop retaining its landmark. The wide beacon crop moves upward to keep the moon and full tower; `reveal-crop-decisions.json` records the source dimensions, exact rectangle and reason. Pressure uses the same 2:1 subject in two registered export sizes. No source is edited in place to accommodate either case.

The [prepared manifest](../authoring/library/fpv-field-kit/prepared/reveals/reveals.json) contains `assets[]` with `id`, `compositionId`, `slotIds`, `file`, `geometry`, `provenance`, `preparation` and `quality`. `file.path` points to a derivative outside the runtime include tree. Runtime compilation copies selected bytes once to its immutable hashed assets directory. Source originals remain in the authoring repository; provenance discloses their path/hash even when an unbound source is not included in the runtime theme bundle. Report actual total PNG bytes instead of raising budgets implicitly.

Each derivative fills its opaque frame, with measured occupied bounds `{x:0,y:0,width:1,height:1}`. All produced owner IDs are validated against the exact current slot dimensions and byte budget. Source/progress manifests and the preparation script do not change campaign identity, live flights, installed picture assignments, replays or first-earned originals. Runtime adoption and historical-pin preservation are separate integration responsibilities.

All outputs stay at `quality.stage: produced` until actual artistic and gameplay evidence is recorded. Native/240 px source review, deterministic bytes and decoder tests do not establish phone readability or partially revealed gameplay hierarchy. Review actual boards, scene exposure, rewards and historical originals before marking a release ready.
