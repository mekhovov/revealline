**Implementation status:** the bounded layout and visible geometry diagnostic are now implemented in the v0.15.0 working source. The sections below retain the accepted pre-edit baseline, risks and requested matrix; their old fixed-strip, board-reserve and aggregate-diagnostic descriptions are historical, not the final CSS. Genuine coarse input, browser text zoom and coordinate-level edge hits remain unestablished. v0.14.0 remains the latest frozen release at this review.

Implementation plan for the [accepted candidate](round-25-candidate-backlog.md), prepared on 12 September 2026 while v0.14 frozen verification finishes. This document implements nothing and changes no historical evidence. The bounded goal is a consistent, non-overlapping **44×44 CSS-pixel minimum for the existing solo flight buttons**, with usable group reflow. There is no new setting, mirrored layout, input mode, schema or simulation behavior.

## Baseline before any CSS edit

The Round 24 browser observation already establishes small wide-desktop targets: at 1280×720 the flight minimum was 34×28, while compact 320/390 layouts measured 44. The predicted wide/coarse overlap is still only source arithmetic. Reproduce and record the current page before changing it:

1. Use the actual source solo page through Playground, with its existing **Desktop** preset or **Custom size → Apply size**. Let layout settle, then record requested size, iframe `innerWidth`/`innerHeight`, display scale and device-pixel ratio. A scaled screenshot is not a CSS-pixel measurement. Keep the same page/source revision for the before/after pair.
2. At 1280×720, record the browser's actual `(pointer: coarse)`, `(pointer: fine)`, `(any-pointer: coarse)` and hover media results. For each direction, Stop, ability, Supply, Boost, pause, restart and sound button, record its ID/action, computed grid tracks where relevant, border-box rectangle, enabled/visible state and label. Record the arena and containing control-group rectangles too.
3. Repeat at the same dimensions with **real supported coarse-pointer emulation or actual appropriate hardware**, recording the media results again. Merely resizing an iframe does not change pointer capability. Do not override `matchMedia`, inject a coarse CSS class or modify styles to manufacture a reproduction. If the available browser tool cannot establish coarse capability, record that limitation before editing; retain the verified wide fine-pointer size issue as the reason for the improvement and leave the overlap claim unconfirmed until a real coarse case is available.
4. Calculate intersections for every pair of active button rectangles. A positive shared width and height is an overlap; record which targets and the dimensions. On the unmodified source, 44px children within the wide 34×28 tracks with 3px gaps predict 7px horizontal and 13px vertical overlap, but actual layout decides the finding. Near-edge pointer actions should identify which existing control receives the gesture; use a safe practice attempt and normal controls.

The existing [Playground measurement code](../game/playground/playground.mjs) reports aggregate target minima and viewport visibility. It does **not** establish non-overlap, media capability, safe-area behavior or unclipped labels. Supplement it through read-only DOM inspection of the actual page, not a second synthetic layout or an imperative state patch. Preserve the initial evidence even if the hypothesis is disproved.

## Size and layout contract

Keep [the existing HTML controls](../game/index.html) and [input handlers](../game/ui/input.mjs). Scope sizing to `.play-controls` and its children in [the solo stylesheet](../game/style.css), rather than globally enlarging every `.button` used by dialogs or other pages.

- Introduce a small local token set, such as `--flight-target-size:44px` and `--flight-target-gap:4px`. These are CSS implementation constants, not player configuration. Every direction and Stop grid track uses the same target size as its button's actual border box; no child minimum may overflow a smaller explicit track.
- Direction buttons stay in the existing cross with Stop in the center. Three 44px tracks and two 4px gaps produce a 140px square, fitting the current 144px compact column. Retain inactive gaps. Do not enlarge invisible hit areas with pseudo-elements or use transforms to make undersized targets appear larger.
- Ability, Supply and Boost each have at least 44px width and height; their existing labels normally require more width. Allow height to grow for a long valid class label or remapped key hint. Utility buttons are at least 44×44. Keep visible text/pressed states and native accessible names; do not replace labels with new unlabeled icons to force a fit.
- Groups may wrap, stack or use a utility column/row according to available width. Preserve DOM order and stable nodes: directions/Stop, actions, then utilities. No CSS `order`, reversed direction meaning, duplicate hidden controls, changed tab order, new pointer listener or JavaScript resize logic is needed.
- Retain both keyboard and touch interaction, `touch-action` rules, pointer capture/cancellation, Hold/Tap steering, controller Boost and logical menu navigation. Do not add resize-specific preference adoption, command releases, run resets or awards. Editing the parent's viewport controls can already move focus and trigger the game's existing pause/input-release lifecycle; record that separately from the layout change and preserve it.

Do not promise a complete arbitrary touch-layout editor. That requires separate accessible settings, strict migration, transport/Undo and focus/neutral-gate design. A consistent default has independent value.

## Accepted scrolling limits

Vertical document scrolling is accepted at compact and short desktop sizes, including 844×501. There is no above-the-fold guarantee for the entire board, all controls, full brief, optional seal, Boost cue and collection notice together. Preserve the current board aspect ratio and 48×36 simulation grid. Keep the existing 320px arena minimum where the available column permits it; mobile uses its actual available width, and short-landscape Sentinel has its existing 200px floor. Do not apply a new universal 320px floor that creates horizontal overflow at 320px viewport width.

Every board area, active control and essential status must be reachable through normal scrolling. No positive horizontal page overflow, clipped labels, overlapping active target boxes or fixed control stack outside the viewport is accepted. A fixed strip that remains visible while the document scrolls must not cover the board, Retry/reader controls, or another active target at any tested scroll position. Do not create a new scrollable subpanel just for the flight buttons.

The mission/result reader may retain its established independent vertical scrolling. Read/Done and launch/result actions stay outside its text area; the retry consequence remains inside. Keyboard focus and controller focus must remain visible and scroll into view through existing behavior. Focus outlines may extend beyond a border box, but must not be clipped or mistaken for enlarged active hit areas.

## Delivery scope

Expected implementation ownership is `game/style.css`, with a minimal `game/index.html` edit only if observed layout requires one. Independent review also accepted a visible, bounded **Control geometry → Capture geometry** diagnostic in Playground. It measures existing child-page DOM through the Playground's own same-origin preview code and presents text/JSON to the author; it does not modify game state or simulate pointer capabilities. Per-target rectangles, enabled/visible flags, viewport/media results, overlaps and conservative overflow indicators supplement the existing rounded readouts. The capture identifies its time and viewport so an earlier sample cannot be mistaken for a live measurement. This is reusable authoring functionality, not private browser inspection or a test-only state hook.

Add a short player/maintainer note and exact browser evidence after behavior exists. No change to core, bindings, preferences, library, session/replay/pack versions, maps, music, assets, couch/Theater logic or frozen releases is needed. Keep CSS selectors narrow because Couch and the Playground outer page also import the solo stylesheet.

The [candidate research](round-25-candidate-backlog.md) distinguishes WCAG 2.5.8 AA's 24px minimum from WCAG 2.5.5 AAA's 44px criterion and XAG 107's physical mobile guidance. This plan chooses 44px as a product target, not a universal legal or accessibility-conformance claim. Physical reach, comfort, assistive-device behavior and enjoyment remain unmeasured unless actual corresponding evidence is recorded. The user's standing instruction is autonomous iteration; this layout work does not add a human approval or playtest gate.
