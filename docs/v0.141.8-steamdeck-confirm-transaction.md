# v0.141.8 Steam Deck Confirm transaction

## Reported failure

On public v0.141.7 in Chrome launched from Steam Game Mode, a short South/A press could
change a menu action on press and reverse it on release. Holding A made the first state
visible for longer, which identified two activation paths around one physical gesture.
Home Sound, Start, Home, and pause-menu controls were reported affected.

Steam Input can combine gamepad, keyboard, and mouse bindings and supports Release Press
activators. The browser Gamepad API is independently sampled rather than delivered in the
same native-event stream. Event ordering therefore cannot prove that two browser paths are
separate physical gestures:

- [Steam Input legacy-mode bindings](https://partner.steamgames.com/doc/features/steam_controller/legacy_mode)
- [Steam Input activators](https://partner.steamgames.com/doc/features/steam_controller/activators)
- [W3C Gamepad API](https://www.w3.org/TR/gamepad/)

## Changed contract

A menu Confirm is now one release-committed transaction:

1. A-down captures the focused control and applies pressed feedback without invoking it.
2. Confirm keyboard, pointer, mouse, and click representations are consumed while held.
3. A-up invokes the captured control through the guarded programmatic path exactly once.
4. Disconnect, focus/visibility loss, scope changes, and removed controls cancel it.

Controller frames expose the exact active Confirm indexes and Gamepad timestamp. South and
the default West alias overlap as one transaction. A different alias pulse within 1.25
seconds of release is quarantined; the original button can begin a deliberate new
transaction after a sampled neutral frame. A trusted native activation that finishes just
before Gamepad sampling remains the winning activation for the complete hold.

`?controllerTrace=1` enables a bounded, memory-only on-screen trace. It shows this build
version, relative time, Gamepad timestamp, Confirm indexes, transaction phase, native event
type, target ID, and winning path. It stores no typed text, writes no persistent state, and
sends no network telemetry.

## Verification scope

Automated coverage includes short taps, five-second holds, Gamepad-first and native-first
ordering, release-only clicks, Enter/Space and primary pointer echoes, overlapping and
delayed aliases, rapid deliberate repeats, custom Confirm indexes, cancellation paths,
touchscreen recovery, Home Sound, Start, and all visible pause actions. The packaged
1280×800 browser check and immutable artifact audit qualify the shipped bytes.

Physical Steam Deck behavior remains a hardware acceptance gate. Test the stable
`https://mekhovov.github.io/revealline/game/` entry, verify v0.141.8, and use
`?controllerTrace=1` on that same stable entry if any short tap or long hold still produces
more than one activation.
