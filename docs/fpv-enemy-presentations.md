# Compact FPV enemy presentation sources

This candidate wires seven independent original FPV enemy defaults through `game/content/enemy-presentations.json`. It keeps existing enemy type/skin IDs, uploaded image transport, physical rules, player presets and historical pack bytes unchanged. Source inspection and the earlier native source preview are separate from a combined runtime build or gameplay qualification; focused results will be recorded after peer review.

The registry records the exact original path, length, SHA256,1254×1254 dimensions, frame-center pivot and finite surface-motion components. `game/enemy-presentations.mjs` validates and freezes a detached JSON snapshot. Each record is independently replaceable through its versioned presentation ID and exact media identity, without renaming `bouncer`, `border-patrol`, `contour-patrol`, `claimed-rover`, `eroder`, `lane-boss` or `relay-sentinel`. Preserve prior source originals/provenance for a replacement, update the explicit build path if separately authorized, and recheck the real painter and memory budget.

Resolved enemy skin takes precedence over current world theme. Only an actual FPV frame uses these defaults. Existing explicit role uploads override defaults, including the legacy `boss` upload overriding both boss types. Even an unavailable requested upload retains its previous vector fallback rather than quietly replacing it with a new default. Other theme skins keep their authored vector bodies. There is no new persisted per-type upload schema.

`BoardPainter` requests only visible active FPV types. A shared seven-entry image pool holds one decoded result per presentation identity, with separate leases for each painter. Changing look, removing the type or releasing the final lease cancels pending ownership and disposes its image. A late decoder cannot install into a newer look and its eventual drawable is released. Failed assets retain the exact type's vector fallback, display an availability message and retry only after a new look/context boundary. Couch uses the shared painter while preserving independent run/input state.

Original bytes remain exact. When supported, the browser retains a128×128 ImageBitmap per image and closes it after the final lease. The fallback uses the original HTML image and releases its object URL and source. Document teardown and bfcache remain ordinary caller behavior; explicit disposal is exercised at clear, type and look changes. Seven128-square RGBA buffers account for458,752 bytes; seven full1254-square buffers account for44,030,448 bytes before decoder, compressed-data, GPU and browser overhead. The decode queue serializes normal loads; cancellation cannot force a noncooperative browser decoder to stop immediately, so a late decode may briefly overlap its successor. These figures are lower-bound pixel accounting, not measured browser memory. Actual native bitmap/fallback behavior remains a qualification step.

The standard bitmap resize options and `close()` support this lifecycle. The `pixelated` resize preference can still interpolate for a noninteger scale; final canvas painting disables smoothing, and actual small-size appearance still needs review. [HTML image bitmap specification](https://html.spec.whatwg.org/multipage/imagebitmap-and-animations.html#dom-createimagebitmap).

Surface glints on tracks/wheel rims and a contained drill/emitter sweep use existing `travelPhase`/`phase`. They consume held frame clocks; no independent simulation timer or actor mutation is introduced. Reduced effects suppress the accents. The baked tracks, wheels and drill remain painted parts. Four- and twin-rotor originals have no extra blade rig, and relay has no independent opening timer: those bodies retain heading/bank with existing functional cues. A later blade-free original and measured hub/part anchors are needed for genuine rotor animation. The accents' normalized positions are candidates pending actual pose review.

Existing warning lanes, pressure targets, contour/rejoining outlines, eroded-cell marks, active cut, role badges, nose cues and physical contact rings remain in their previous order. Image/body size uses unchanged actorDiameter limits, including its narrow-canvas logical cap. Root's source-only review found24/32/64px silhouettes distinct and clearer than the detailed atlas; the twin-rotor remains thin at16px. The requested12–16-color palette was not achieved. Do not treat this work as a completed animation set or physical-device approval.

The seven originals add 6,522,849 bytes and this slice adds 21,977 shipped text bytes. Using authenticated frozen040 core 52,816,659, accepted Ukraine player originals 5,873,332 and their measured runtime text delta 11,937 gives a prior-artifact projection of 65,246,754 bytes, below unchanged 64MiB by 1,862,110. Later041/current source differences must be counted in the actual combined build. No optional bundle is provisionally required for these known sets alone; further themes need their own budget and likely an optional presentation format or separately approved runtime derivatives. Lazy decoding does not reduce offline bytes. No version, release, whole build or64MiB cap change is part of this source slice.

Focused checks cover strict registry/path/type/anchor refusal, exact metadata/source association, uploaded and skin precedence, shared/late/failed decode ownership, retained clock/envelope behavior and the actual image painter. Existing actor/capture tests remain authoritative for unchanged physical cues. An exact allowlist/build plus moving native light/dark scene and warning/cut checks are still required before a public adoption claim.

Focused source qualification completed with 44/44 cases on Node 22 and 44/44 on Node 20, with no failures, skips or cancellations. The same 12 new cases first passed alone on Node 22; they are included in the 44, not additional unique coverage. The five files include the unchanged actor and Classic regression cases plus the narrow new boss-slot assertion. Exactly 43 inherited Git fixtures (12,188,936 bytes, including the existing FPV Arcade JSON) were materialized; their bytes and the source status were verified. Correctly rehashed malformed width and height headers both refuse before the mocked decoder. These tests observe canvas commands and loader ownership; they do not decode the seven originals or qualify native bitmap resizing, actual memory, the complete build allowlist, gameplay readability or all motion poses.
