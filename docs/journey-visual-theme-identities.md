# Journey visual-theme ownership

This unpublished extension follows catalogue foundation patch `f73ee4f8` and Legacy/Team adapter patch `eda7970c`. It adds an explicit `journey` owner to the catalogue v1 union before publication; existing campaign/Team contexts remain valid and unchanged. No persistent format or runtime call site changes.

`createJourneyVisualThemeIdentityAdapter(acceptedProject, {mode, signal})` bounds and owns the project, then calls the existing `createContentExecutionCatalog` authority. That owner already compiles registered project/map/mission/policy/catalogue data for all presets. The adapter computes canonical SHA-256 of that exact source and retains the resulting immutable execution catalogue. Compile once per accepted project/mode, outside rendering and the gameplay tick. Do not rebuild per frame. Large-project performance qualification remains required before runtime adoption.

`adapter.prepare({entry, level, association}, {signal})` requires exact accepted execution data, including source pack/campaign membership, policy, manifests and official-progress flags, plus full selected-level membership. The association is the host's code-owned edition/content-theme/mode mapping, never a cosmetic selection or user-declared ownership. Existing import authentication remains with its owner.

The context has `owner.kind = journey`, project ID/revision/canonical SHA-256, source pack ID, campaign ID, the existing Standard `baseCampaignKey`, and registered `policyId`. Its level retains the Standard authored resolved level ID/revision/canonical SHA-256 and the compiler's existing 16-hex `simulationIdentity`. Gentle/Standard/Expert share the original visual identity within a mode. Mode remains explicit, so coverage never transfers automatically between Solo, Versus and Team. Shared campaign membership in different packs remains distinct.

These fields scope visual compatibility only. They do not replace any existing execution key, save reader, progress identity or eligibility decision. Difficulty-specific runtime data remains unchanged. Standard normalization is the existing Journey compiler's authored baseline, not Legacy Gentle projection. A project source change intentionally invalidates its exact catalogue coverage even if only metadata changes; new approval is explicit. Changed policy, simulation or original-picture metadata uses the existing execution identities and also invalidates prior visual coverage.

All inputs are owned before awaits. Aborted creation/preparation returns no context. The adapter changes no cache, network, audio, presentation host or saves. Local hashes are identity checks, not signatures. An adapter can validate a compiler-supported greybox without approving its artwork or playability.

Tests reuse actual Starter/Opening project factories and the existing Team fixture construction. They cover all three modes and presets, exact existing simulation/pack identities, shared campaigns, changed mission/project/map/policy/art metadata, hostile owner declarations, stale entry/level rejection, cancellation, mutation and old-schema regression. No physical-device, decoded-media, release or production-quality claim is made.
