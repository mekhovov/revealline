# Native compatibility review

Reviewed 2026-09-12 against the v0.2.1 web implementation and current official documentation. This is an integration review, not a claim that an Electron binary or an iPhone build has passed device testing. The desktop and iOS wrappers are being developed independently; the recommendations below identify what their host layer must provide.

The deterministic game kernel can remain shared. The required native work concerns the document origin, file transfer, persistence and application lifecycle. Keep platform access behind small host adapters; do not add filesystem or platform assumptions to territory capture, class rules or replay verification.

## Electron: stable local serving and a narrow bridge

Use a standard, secure custom scheme with Fetch support, registered before Electron becomes ready. Register its handler on the actual session used by the window. Electron documents that nonstandard schemes lack normal relative-resource resolution and disable web storage by default. Preserve a stable persistent session across app updates; a changing port/origin/partition appears to the game as another collection. These are reasons to avoid a raw `loadFile()` wrapper for this repository. [Electron protocol documentation](https://www.electronjs.org/docs/latest/api/protocol)

The protocol handler should expose only packaged public assets, constrain resolved paths to the bundle and return correct MIME types. Compare protocol and hostname explicitly when checking trusted custom URLs: Node's `URL.origin` is `"null"` for ordinary custom-scheme URLs, so comparing that string alone is not an origin allowlist. Keep `nodeIntegration: false`, context isolation and sandboxing; validate bridge callers and payloads, and expose a specific export method rather than raw filesystem or IPC access. Keep remote pages out of the privileged game window. [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security), [context isolation](https://www.electronjs.org/docs/latest/tutorial/context-isolation)

For exports, either handle the existing Blob download with a bounded, trusted `will-download` flow, or expose a narrow `saveJSON({name,text})` operation that obtains the destination from a native Save dialog. Return cancellation without treating it as successful export. The host can observe a DownloadItem's completion/interruption/cancellation; a renderer anchor click cannot establish that outcome. Do not accept an arbitrary filesystem destination from a theme or imported file. [Electron DownloadItem](https://www.electronjs.org/docs/latest/api/download-item), [native dialogs](https://www.electronjs.org/docs/latest/api/dialog)

Do not indiscriminately reject the Playground's trusted local `target="_blank"` action: `game/playground/index.html` uses `rel="opener"` so browser-created preview tabs inherit the session configuration. Manually creating a new BrowserWindow does not establish that same handoff just because the persistent partition matches. Same-window local navigation is a simple option; a second window needs a deliberate bounded scenario transfer. This is a finding from the application's current data flow, not a request to allow arbitrary popups.

## Capacitor/iOS: capability floor and storage boundaries

Keep the full distribution as `webDir`, a stable `localhost` hostname, and a local iOS scheme such as Capacitor's default. Do not set a production `server.url` pointing to the development machine or broadly permit remote navigation to make asset requests work. Capacitor recommends localhost for secure-context APIs and notes that WKWebView cannot register an iOS handler for schemes it already handles, such as HTTP or HTTPS. [Capacitor configuration](https://capacitorjs.com/docs/config)

The current game requires features shipped in WebKit for iOS 15.4, including Web Locks, `structuredClone`, and `Array.at`; it also uses native modal dialogs and `Object.hasOwn`. Capacitor's own minimum OS is therefore not by itself the game's supported floor. Set the deployment/runtime floor deliberately and probe the actual packaged scheme. Test lock exclusion between the game and a second relevant context, not just the existence of `navigator.locks`. [WebKit 15.4 release notes](https://webkit.org/blog/12445/new-webkit-features-in-safari-15-4/)

Capacitor warns that mobile systems may clear localStorage and describes Preferences as a lightweight key/value facility, not a database. The game currently allows a 4 MiB player profile and a 48 MiB pack library, with an additional rollback journal; do not move those wholesale into Preferences. A future durable store needs explicit completion acknowledgements, ordering, recovery and adoption rules compatible with `saveLibrary`/`commitBackup`. A fire-and-forget Preferences write behind a synchronous `setItem` facade would falsely report success. [Capacitor Preferences](https://capacitorjs.com/docs/apis/preferences)

IndexedDB remains useful for a preview wrapper, but quotas and eviction still apply to WebKit website storage. Use a persistent WKWebsiteDataStore and preserve its identity. A storage estimate or a successful first write is not proof that all completed images will survive cleanup or app removal. If the initial wrapper retains the browser persistence layer, describe that limitation and keep portable backups available. [WebKit storage policy](https://webkit.org/blog/14403/updates-to-storage-policy/), [Apple WKWebsiteDataStore](https://developer.apple.com/documentation/webkit/wkwebsitedatastore)

For a share-based JSON export, write the exact bounded UTF-8 JSON to an app cache file and pass its file URL to the native share sheet, then report the result honestly. A completed share sheet is not proof the player chose “Save to Files.” Avoid passing an entire large backup as share-sheet text. Capacitor's Share API explicitly supports local file URLs; Filesystem provides the cache/file operation. If using these plugins, include the applicable privacy manifest entries documented by the plugins actually installed, not a generic set of unrelated permissions. [Capacitor Share](https://capacitorjs.com/docs/apis/share), [Filesystem and its manifest requirements](https://capacitorjs.com/docs/apis/filesystem)

The alternative is a deliberate WKDownload delegate implementation. Apple's API exposes download progress, failure and cancellation; simply displaying the current Blob anchor in WKWebView does not implement such a delegate. [Apple WKDownload](https://developer.apple.com/documentation/webkit/wkdownload)

## Imports, interruptions and controls

Existing file inputs, `File.text()` and FileReader can remain the first import path if they pass a real Files-picker test. Feed returned bytes through the same `prepareBackup`, `preparePack` or `prepareScenario` checks before adopting anything. A native picker should check file size before bridging content to JavaScript, then apply the same format/decode budgets. Native imports must not become arbitrary URL fetches or filesystem reads selected by imported JSON. Preserve original image bytes; the current image importer already checks headers before sequential full decoding and does not silently convert assets.

Current backup preparation can hold source JSON, parsed/cloned objects and decoded surfaces simultaneously. Its bounded maximum is larger than a single pack. Keep large-file acceptance separate from “it works on my desktop”; on iOS, a native write/share layer should avoid unnecessary base64 copies of JSON and should not declare success until the file operation finishes. These are resource implications of the code, not a measured device-memory ceiling.

Capacitor's `App.appStateChange` maps to native resignation/activation notifications on iOS. Connect inactivity to pausing the game, releasing held input and stopping WebAudio. Avoid synthetic catch-up ticks and automatic resumption on return. The existing audio engine already has explicit enable/resume, pause, disable and bounded scheduling; a wrapper should preserve that user-gesture contract. Also checkpoint an unfinished flight while the app is active or during supported lifecycle callbacks; termination must not be assumed to deliver a final event. [Capacitor App API](https://capacitorjs.com/docs/apis/app)

No game document currently requires the browser Fullscreen API. The board keeps a 4:3 simulation and its surrounding layout adapts. On macOS, native full-screen window transitions are asynchronous; wait for the relevant Electron window event if coordinating UI around them. On iOS, test safe-area padding, rotation, the share sheet and settings with the on-screen keyboard before changing native inset or zoom policy. [Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)

The game uses `navigator.getGamepads` with standard mappings and has keyboard/touch fallbacks. Verify controller pairing, first interaction, disconnect/reconnect and neutral-before-resume in the actual wrapper. A browser gamepad test or an Electron build does not establish support for every controller in WKWebView. Keep remapped keyboard keys from swallowing native text-field, dialog or system shortcuts.

## Offline and privacy wording

Native builds already contain their shipped assets. `game/offline.mjs` is a web-distribution Service Worker installer, not a native installation test. Hide or adapt “Prepare offline play” in native mode instead of relying on a custom-scheme worker/cache combination. Its absence must not imply that the bundled native game needs the internet. Test a cold launch with networking disabled and no development server.

The current generated privacy page accurately describes the web build's lack of account, tracker and upload code. Native wrappers should preserve that behavior and explain any new cache exports or native persistence. Opening a player-requested share sheet hands that chosen file to another app; it is distinct from automatic upload. Apply the existing CSP to native-served content, retaining only the local script/image/frame needs, and keep analytics, remote code and broad native permissions out unless deliberately introduced.

## Native acceptance outcomes

Before labelling a wrapper supported, record these concrete results for its actual OS/runtime version:

1. Cold offline launch loads the four worlds, body assets, example packs, nested Playground and Replay Theater routes without an external server.
2. The packaged origin can write/read IndexedDB and localStorage and reserve/release an exclusive writer; relaunch and an app update preserve the same collection identity.
3. Export a profile, image pack and full backup; cancel the picker/share flow; then import each from the OS Files picker. UI messages distinguish outcomes and existing data survives rejection.
4. Interrupt a cut with app switching, a native dialog, controller disconnect and device lock; no held movement or music resumes automatically. Resume/replay still matches the authoritative result.
5. Restore a valid backup over corrupt stored data; force a write failure; confirm the journal rollback and an honest unavailable-Undo state. A native storage adapter must retain these semantics.
6. Play a large imported image pack and open the paginated collection on an actual supported iPhone and macOS build. Record decode/memory failures rather than treating schema acceptance as a performance result.

No native compilation, audio audition, native file-picker round trip or physical controller test was performed in this review. The wrapper owners should add their observed results separately; this document deliberately does not turn recommendations into completed claims.
