# Bounded parent-first Pages measurement

Status: user approved the bounded design; independent written-spec review approved. Written-spec user review precedes implementation planning. This is a diagnostic extension, not merge admission or publication qualification.

## Purpose and alternatives

Measure the complete production-profile archive for two or three dependency-linked, same-repository open PRs composed parent-first on exact current main. The existing single-candidate workflow and its behavior remain unchanged. Individual measurements cannot establish combined capacity; a whole-queue build would exceed the deliberately bounded review and failure-isolation scope. A separate bounded workflow reuses the accepted composition foundation and trusted byte-verification components.

The first implementation supports one contiguous chain only. Independent PR groups, arbitrary queue ordering, automatic discovery, automatic dispatch, branch updates, merge operations and content reductions are out of scope. Longer chains require successive, separately frozen diagnostic batches; no sum of batch sizes or incremental savings is a combined-queue measurement.

## Exact input and dependency contract

Dispatch only from main with its full lowercase 40-character SHA and one bounded JSON array containing exactly two or three ordered entries with precisely `prNumber` and `headSha`. Reject unknown keys, malformed or unsafe numbers, duplicate PR numbers, duplicate heads, missing values and oversized input. Do not interpolate input into shell commands. The workflow/controller source must equal the requested current main at the initial snapshot.

Use trusted GitHub API reads to capture each PR number, OPEN state, boolean draft state, exact head SHA, head ref, head repository, base ref, base repository and reported base SHA. Require both repositories to be exactly mekhovov/revealline. Preserve draft state for diagnostics; measuring a draft never marks it ready. Require distinct head refs. The first PR must target main; its reported base SHA may be an ancestor of frozen main rather than its current tip. Each later PR must target the immediately preceding PR's exact head ref, and that named branch's current tip must equal the preceding frozen head. The child's reported base SHA must be an ancestor of the preceding frozen head. Independently prove that each preceding original head is an ancestor of the next original head, using fetched Git objects. Ref names alone do not prove dependency.

Freeze the complete current exact-head check inventories and mergeability observations for context. Missing checks do not become successful; neither successful checks nor mergeability admit or qualify a diagnostic batch. A freshness comparison detects changed, missing or newly added checks; observations such as mergeability UNKNOWN are recorded, not silently converted into clean status. API incompleteness, inaccessible refs or unproven ancestry reject preflight.

## Three-job trust boundary

1. Trusted preflight checks out exact dispatch main without persistent credentials, uses read-only API authority, fetches exact public objects, validates the complete chain, and calls the merged `composeStackObjects` helper with main plus ordered original heads and main's committed timestamp. The helper itself does not fetch, check out files, change refs/index/worktree or contact the network. Record every deterministic intermediate tree/commit/parent relationship and final synthetic source. Reject a conflict without changing the source PRs. Freeze and hash the preflight packet and all supporting data.
2. Candidate job uses a fresh trusted controller checkout and a separate candidate checkout, downloads only the identified preflight artifact from this run, reconstructs all intermediate objects from public exact source objects and proves all identities match. No GitHub API credential is supplied to reconstruction, candidate dependencies or build. Candidate source executes only on this isolated, nonprivileged runner. No deployment permissions, environments, secrets or production artifact name are available. Trusted staging/inventory/archive tooling remains sourced from dispatch main.
3. Final trusted verifier uses a fresh main checkout, never checks out or imports candidate source, and downloads this run's exact identified preflight, candidate archive and receipt artifacts. It independently validates provenance and all bytes, then refreshes the entire frozen chain, main and external inputs. Candidate execution and privileged verification never share a workspace or process.

Workflow permissions stay contents:read/actions:read globally; candidate has contents:read only. Checkouts do not retain credentials. No Pages deployment job, pages:write, id-token:write, PR mutation or controller admission hook is introduced. Pin existing approved actions. Serialize the new workflow against existing candidate diagnostics using the existing `pages-candidate-diagnostic` concurrency group without canceling in-progress runs. Do not add redundant CI dispatches.

## Publication contract and external bytes

Apply the existing unsupported-publication-path boundary to every original composition step and to the final main-to-synthetic difference, not only the final diff: canceling changes must not conceal a changed contract. Include both rename endpoints or conservatively disable rename detection. Reject changes to workflow/tooling/dependency/build configuration and the trusted renderer import closure exactly as the current single-candidate diagnostic does. This first extension does not qualify arbitrary tooling-changing PRs for measurement.

Freeze the final synthetic optional-package selector by exact bytes and checksum. Freeze selected release/tag/asset identities, published checksums, byte lengths and actual public bytes using the existing overlay contract. Capture all trusted renderer closure file identities from frozen main and forbid changes at any step. Keep the five illustrated live gameplay pack bodies totaling 56425044 source bytes outside download-only candidates; this workflow does not remove or relocate anything.

Build the unchanged complete main-pages production profile from the final synthetic source, then apply the frozen overlay and byte-identical rolling metadata with the synthetic source and frozen main timestamp. Verify tracked candidate source identity before and after build. Keep both 980000000-byte guards exactly unchanged. Upload under a distinct stack diagnostic artifact name, never github-pages. Do not publish a release, reserve headroom or modify a selector/tag/asset.

## Independent acceptance and freshness

Bind run repository, workflow path, main branch, dispatch event, run identity, attempt and exact controller source. Validate every artifact ID, expected diagnostic name, run/source association, expiration and checksum. The trusted preflight checksum comes from the preflight job output, never candidate-written metadata. Validate preflight schema before using any field. The candidate cannot choose the workflow path, trusted modules or artifact identities used by the verifier.

Inspect the actual complete archive without extracting or executing its contents. Require safe unique members, only permitted regular files/directories, complete inventory equality, every file length/hash, raw and archive byte arithmetic, exact synthetic source, all production acceptance receipts and unchanged guards. Independently reproduce rolling metadata. Verify each frozen overlay member is present with the pinned bytes. Shared Python archive validation may be reused unchanged where its input contract is identical; no duplicate scanner or relaxed validation is needed.

Refresh main plus each PR's repository, ref, head, state, draft, base ref and reported base SHA, every dependency branch tip, and exact-head check inventories after archive verification. Recheck selector/external asset/tag/checksum/public-byte identities. Do not infer freshness from an unchanged head alone. Changed or unreadable inputs produce historical/ineligible evidence with explicit changed versus unverifiable reasons. Do not discard a fully verified historical archive measurement merely because freshness changed.

Results use a separate versioned stack-measurement format with the complete ordered frozen chain, intermediate objects, final source/tree, preflight hash, artifact/run/controller identities, exact archive bytes/hash and freshness reasons. `measurementComplete` is true only after full independent byte verification. `currentQueueEligible` is true only while every frozen identity remains current and independently readable. Incomplete builds or failed archive verification yield `measurementComplete:false` and `currentQueueEligible:false`, not an accepted zero-byte measurement. All result paths explicitly set `mergeAuthorized:false`, `qualificationPerformed:false`, `productionDeploymentPerformed:false`; no admission flags can become true. Queue eligibility means measurement freshness only, never merge readiness.

## Tests and rollout checkpoints

First add pure stack input/snapshot/freshness validation with tiny fixtures: valid two/three chains, advanced main, stale reported base with proven ancestry, draft diagnostics, ref retargeting at the same SHA, changed repositories/state/draft/base/head, missing refs, duplicate identities, malformed/oversized JSON, reversed/unrelated/missing ancestry, and incomplete/changed check inventories. Maintain existing real-Git composition isolation tests and unchanged single-candidate regressions.

Then add the separate controller/workflow with mock API/artifact fixtures. Verify deterministic reconstruction, intermediate and net unsupported paths, closure changes, packet/schema/digest tampering, wrong run/attempt/workflow/artifact/source/expiry, altered selectors/external bytes, stale/unreadable snapshots, candidate failures, malformed/incomplete archives, and explicit false nonadmission flags on every result. Workflow tests prove permission separation, no candidate credential environment, no deploy/push/merge command, pinned actions, exact guard values and unchanged single-workflow bytes.

Independently review design and implementation, run focused tests/lint/format, publish only reviewed files on a fresh main-based branch, and wait for complete applicable exact-head checks before promotion/merge under the user's separately granted safe queue-management authorization. This specification and its diagnostic outputs grant no new merge or deployment authority. Preserve branches and verify MERGED/main reachability and source-bound production. Only then dispatch one real bounded chain after a fresh queue/source/contract check. Independently verify its complete artifact ZIP digest and every archive member once on approved external storage, with explicit external TMPDIR for downloads. If main or a member moves, retain the measurement as historical and do not issue duplicate runs automatically.

After this checkpoint, separately prove affected consumers and public download bytes before any small reduction batch. Each reduction needs its own full archive and live-behavior verification. Actual targets remain 950 MB then 900 MB; no measurement alone authorizes reduction, gameplay/native/offline qualification or merging a PR whose independent gates are not satisfied.
