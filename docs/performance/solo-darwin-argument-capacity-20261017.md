The source audit independently found a request-size defect. The helper supplied a fixed 2 MiB buffer to `KERN_PROCARGS2`. Apple's pinned [`sysctl_procargsx` implementation](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/kern_sysctl.c) subtracts the argc word, then rejects a requested size exceeding `ARG_MAX` with EINVAL before looking up the process. That source exposes the actual limit through `KERN_ARGMAX`; its [macOS limit is 1 MiB](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/sys/syslimits.h). The retained hosted result does not include each failed inspection's errno, so this independently demonstrated defect is not presented as a captured per-field diagnosis of that run. The public kernel source is a research reference, not a verified source match for the hosted kernel.

The correction queries `KERN_ARGMAX` once per helper invocation and accepts only a complete positive integer larger than the argc word and within the existing 2 MiB ceiling. Argument reads allocate and request exactly that admitted capacity. A failed or malformed limit aborts the inventory; a full, truncated or unreadable argument buffer remains incomplete. Global enumeration, lifetime/exec identity, UID/parent/group checks, mandatory owned-process RSS/path/token inspection, fresh identity before signals and uncertainty handling are unchanged. No argument or environment contents are output. No workflow, retry or browser execution is introduced.

All 14 controls have their expected outcomes: the old request becomes incomplete at both 256 KiB and 1 MiB kernel limits; the corrected request finds the exact owner token, queries the limit once and preserves genuine absence. Denied, short, zero, negative and oversized limits fail before reading arguments; denied, truncated and saturated buffers remain incomplete.
