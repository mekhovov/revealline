## Prioritized findings

1. **P1 — WebKit performance remains unqualified.** The retained current-package first-eight run passed all eight correctness rows and four same-source native replay checks. Its single candidate WebKit timing window missed 2.948784% of callback opportunities, exceeding the 1% gate, at reduced decorative quality. Candidate Chromium passed its single observed window. Neither result supplies three matched repetitions or device qualification. See [the exact outcome](solo-de332-first-eight-outcome-20261018.md).
2. **P2 — Public music catalogue currently unavailable; not a demonstrated regression.** Audio displays the archive warning and the configured [catalogue endpoint](https://mekhovov.github.io/revealline-soundtracks/catalogue.json) returns direct HTTP 404. The URL and HTTP-200 validation rule are identical before and after the release (`game/online-soundtrack-catalogue.mjs`). The correct follow-up is to inspect the external catalogue deployment or establish its intended URL; weakening response validation is not justified. Built-in/installed/uploaded playback was not audibly qualified by this muted smoke check.
3. **P2 — Controller Resume can consume paused time; source-reproduced and pre-existing.** A read-only in-memory control executed each revision's complete `resume()` function, actual frame/controller/update statements and the unchanged real simulation step, with already-prepared readiness and UI/hardware boundaries modeled. A controller Menu Resume inside a 100 ms paused callback advanced 12 ticks in both old and shipped source. The local elapsed value was sampled before polling; resetting the clock cannot revoke that value already passed into the callback. See `game/app.mjs:13343`, `:11654`, `:10846` and `:11718`. Native controller frequency/impact remains unmeasured; not every Resume necessarily takes this synchronous cached path.
4. **P2 — Valid Journey saves receive a misleading Archived label; pre-existing.** The live library displayed “Choose your share · Archived · difficulty unavailable” although the exact save restored successfully. Actual `createCandidateSoloHost(createOpeningCandidates(), themes)` entries for Standard/Gentle/Expert reproduced the incorrect label through `createGalleryDifficultyResolver`. Host-owned Journey entries intentionally have `baseCampaign: null`; the legacy resolver rejects that shape and uses its archived fallback. Actual legacy Standard/Gentle controls returned correct labels. `game/gallery-difficulty.mjs:23`, `game/ui/library-panel.mjs:217` and `game/content-design/solo-host.mjs:19` are byte-identical in the before/after revisions. This is a presentation bug, not evidence of an invalid save.
5. **P2 — One Snake landing load failed; cause and release attribution unresolved.** Its first public load showed “The page could not load. Reload to try again.” One explicit reload recovered the full guide; subsequent Snake play, retry and pause worked. The message originates from `game/access-gate.mjs:68`: a restored script error rejects boot, but the handler discards the failing URL/event and hides the rest of the page. Empty captured logs are therefore inconclusive. Direct Snake/gate/installation entry sources are unchanged. Twelve bounded live HTTP checks currently returned 200 with expected MIME; they bypass this browser's cache/service worker and cannot explain the original failure. The optional flight catalogue has its own recovery path and cannot produce this whole-page error. Preserve the first failure rather than calling the reload a fix.

The controller control retained these results; the second value follows one additional 16.67 ms callback:

| Resume route                                      | Before release, ticks | Shipped, ticks |
| ------------------------------------------------- | --------------------: | -------------: |
| Controller Menu inside the 100 ms paused callback |               12 → 14 |        12 → 12 |
| Resume before the callback                        |               12 → 14 |          0 → 2 |

The shipped external Resume route improves clock reset. The in-callback route still consumes the pre-Resume interval, then takes a fresh zero-elapsed callback. This small modeled boundary control is not a full-host replay or hardware test.
