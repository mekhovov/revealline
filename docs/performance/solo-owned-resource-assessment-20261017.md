# Paused owned-resource assessment

The existing soak retained resource snapshots but automatically checked only three canvas plateau counters. The new `scripts/solo-owned-resource-assessment.mjs` provides a separate, pure assessment of the existing exported image, canvas, PCM, compressed soundtrack, worker and pending-work counters. It does not change the game, any running qualifier, existing fixture, manifest, deadline or budget. Its use in a future hosted cohort must be explicitly declared and frozen with that cohort's tools.

The caller must first complete its existing source, report, chunk and file-integrity readback. The analyzer checks **every** retained snapshot, including preparation and failed-attempt boundaries, before selecting the last ten comparable result snapshots for trends. An earlier breach cannot disappear because later snapshots are flat. The 512-snapshot input limit is the existing chunk-store limit; excess input is rejected rather than truncated. Missing/null counters remain unknown, invalid numbers fail, and arithmetic disagreements or overflow fail. An unknown owner or unsuccessful URL revocation prevents a bounds pass. Saturated revocation counters remain uncertainty about browser release, not measured retained or freed memory.

`bounds.status: pass` only means the observed counters meet the listed source bounds and accounting identities. It does not grant retention, native-memory or gameplay qualification. Trend results preserve every selected value, minimum, maximum and first-to-last difference. Flat values are labeled observations; changing values require owner/phase review, with no invented growth tolerance. An idle reusable worker is an owned resource, not pending work. A pending native decode retains its reservation until the actual owner settles. None of these categories is added into a purported total browser memory value.
