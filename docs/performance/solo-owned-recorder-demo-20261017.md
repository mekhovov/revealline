# Owned recording prefixes and admitted Demo retention

The earlier first-victory profile found synchronous replay export in terminal work. Moving hashing behind preparation admission still left a full recording snapshot before admission. Dense supported recordings made that initial copy material, and automatic Demo retention called the required synchronous export before its optional verification.

Main Solo now uses a recorder with private backing data. Only the replay module can append segments or extend the last segment. An optional export captures the array identity, prefix length, copied tail, scalar header and authoritative projection; it does not traverse the recording prefix. Later recording cannot change that captured prefix. Final assembly, bounded copying and checkpoint hashing run in the existing preparation owner. Required public/save exports retain their synchronous defensive contract, and ordinary public recorders retain defensive optional snapshots.

Fresh and prepared Main Solo attempts create the handle before publishing the prepared bundle, preserving the bundle's identity checks. Completed restoration adopts a copied recorder during preparation. The public restoration modules and Company preparer keep their original recorder representation. Handles expose only tick and segment counts.

Demo retention captures options at invocation and defers entry inspection only for the exact existing immutable execution-catalog or candidate-host publication. Arbitrary caller entries retain the original immediate defensive path. Disable, clear and disposal cancel owned queued operations. Verification, descriptor work, serialization and storage processing share the existing admission owner. A native IndexedDB read returning after Start aborts before inspecting the library or writing; no await is inserted into a transaction and no automatic retry is added. Already completed transactions remain committed.
