# Late presentation during Start preparation

## Finding and bounded fix

The WebKit recovery observation in [run 38990616921](https://github.com/mekhovov/revealline/actions/runs/38990616921) used package `3adcd537`. Its public Signal 07 Start click completed, but the game stayed in briefing until the fixed 60-second deadline. The retained transitions moved from ready to preparing and back to ready after about 1.25 seconds. Required media had no active or queued work, no page errors or resource failures were recorded, and page presentation images changed from zero before Start to 80 afterward. This is consistent with a canceled Start after late presentation acceptance; the original report did not record the exact cancellation interleaving, so it cannot prove that cause by itself.

The host reproduction deliberately accepts the actual compiled canvas presentation after `painter.prepare()` completes and before Phaser's next `POST_RENDER`. Before the fix, the changed `paintRevision` threw `AbortError`; Start treated that as cancellation and left the same authoritative run in briefing. The preserved reproduction times out waiting for the second preparation, with one completed preparation and no pending submission. This establishes a concrete runtime defect independently of the native observation.

Commit `b5b985f70` makes the existing current-attempt preparation loop prepare and submit again when only the painter or scene revision changes. It retains the single cancellation owner and requires a fresh visible submission. Changed run, accepted originals, presentation generation, actor lease, visibility, focus, dialog ownership or renderer availability still abort. The additional blur regression proves that a real lifecycle interruption during re-preparation requires an explicit fresh Start. Checkpoints stay unchanged during preparation.

The complete preparation-invalidation host file and render-submission file pass 12 tests. Scoped lint and formatting pass. The red reproduction and green tests remain in `.cache/solo-followup/late-presentation-preparation-01/`. These are host and source checks, not physical-device or native-browser confirmation.
