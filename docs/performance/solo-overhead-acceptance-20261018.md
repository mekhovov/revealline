# Empirical clock overhead acceptance

The existing app and journal assessors compute useful conditional intervals. Their observed minimum positive clock increment does not establish a maximum duration error or privacy-jitter bound. A conditional upper endpoint below 5% therefore cannot clear the diagnostics-overhead qualification gate.

The separately versioned SoloEmpiricalClockSensitivityV2 acceptance assessment applies to every current native adapter result and both current CLI analyze/run completion paths, including historical-default and paired-p95-endpoint-box-v1 arithmetic. It preserves the original interval, observations, pairs and reasons, records the original verdict as conditionalStatus, and sets qualification status to unresolved with eligible false. It accepts no caller-supplied trust switch or proposed clock bound. The timer-probe command still reports whether observation succeeded; that command does not qualify overhead.

Historical pure-assessor output and immutable executed declarations/results remain unchanged. Reading old arithmetic is not prospective qualification. Existing strict source-input hashing remains intact: this source change makes old tool-pinned dispatch declarations inadmissible unless separately reviewed successor tooling is declared. No frozen declaration, artifact, workload, threshold, pair count, deadline, or prior result is repinned or relabeled here.

Ten exact declaration identities and the two original source bodies are retained in a test-only witness. The active app and journal historical readers require that immutable witness and actual unchanged declaration bytes; production never imports it. An actual setup control confirms that historical readback cannot admit changed current tools. Seven live native sparse source jobs include the runtime helper; the five historical-reader owners also include the test-only reader and witness. The new source entry executes the complete analyzer, CLI and adapter controls and negative sparse-closure controls. Seven archived workflows retain their original source identities and old PR/synchronize/before guards; they are historical execution records, not current prospective dispatch paths. Current/future dispatch must retain this acceptance fence, including when reading a historical method. Run the complete analyzer, real CLI and adapter controls remotely. No new native dispatch is authorized by this source proposal.

The interval arithmetic remains conditional on the stated duration-error assumptions and matched-run statistical assumptions. Its target is a geometric mean of run-p95 ratios, not pooled frame p95. Adjacent balanced pairs and fresh browser profiles do not alone establish independence or remove thermal drift. Journal evidence covers its declared synchronous envelope, excluding observer delivery, export and other unmeasured browser costs. Current retained native cohorts remain unresolved.

References: [High Resolution Time](https://www.w3.org/TR/hr-time-3/) permits implementation-defined coarsening and jitter; [NIST confidence intervals](https://www.itl.nist.gov/div898/handbook/prc/section3/prc311.htm) describes the statistical assumptions behind mean intervals.
