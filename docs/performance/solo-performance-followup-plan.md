## Research review and resulting decisions

- **Keep optional module loading within its existing owner.** The chooser has one use inside the guarded Missions request; moving its import there removes seven eager modules without a new loading system. Current HTML specifies removal of failed fetch entries, while evaluated modules have separate caching semantics; browser-version behavior still requires observation. [Module fetch algorithm](https://html.spec.whatwg.org/multipage/webappapis.html#fetch-a-single-module-script), [dynamic import caching](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import#module_namespace_object).

Correct stale plan status before commissioning repetitions. The next hosted lanes reuse the verified package and existing workloads; source/tooling identities remain distinct.
- **Treat normal-clock precision as a limitation of the overhead claim.** The High Resolution Time specification permits implementation-defined coarsening and jitter. A measured minimum clock step is not a proven error bound. A tighter bounded offline interval method can reduce unnecessary slack under its stated assumptions, but cannot establish that assumption or turn old failed rows into a pass. [High Resolution Time coarsening](https://www.w3.org/TR/hr-time-3/#dfn-coarsen-time).
- **Keep diagnostic tracing out of ordinary timing.** Current Chrome documentation warns that advanced paint instrumentation and CSS-selector statistics significantly affect performance, and that CPU throttling cannot reproduce mobile CPU architecture. WebKit explains that explicit `decode()` uses natural dimensions without the display path’s subsampling. The existing actor pool reserves decoded RGBA bytes (64 MiB standard, 32 MiB compact), and the legacy painter serializes decoding with a 16-million-pixel retained limit.
