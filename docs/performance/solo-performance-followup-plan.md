## Research review and resulting decisions

- **Separate input-delay components before attributing touch failures.** Chrome distinguishes input delay, handler processing and presentation delay. Our elapsed boundary from `event.timeStamp` to a late observer listener can include queueing plus earlier handlers; it is not pure queue time. Inspect those components separately in diagnostics. Pointer Events permits browser delay/coalescing, but this possibility does not establish the cause of the retained failures or justify changing input APIs, synthetic input, thresholds or the existing Warm frame-trace scope. [Chrome interaction breakdown](https://developer.chrome.com/docs/performance/insights/inp-breakdown), [W3C coalesced events](https://www.w3.org/TR/pointerevents3/#coalesced-and-predicted-events).

- **Keep optional module loading within its existing owner.** The chooser has one use inside the guarded Missions request; moving its import there removes seven eager modules without a new loading system. The fresh-process refusal test establishes source-host isolation, not native network-retry behavior. Current HTML specifies removal of failed fetch entries, while evaluated modules have separate caching semantics; browser-version behavior still requires observation. Preserve explicit full-document boot recovery rather than adding unbounded query-string imports or alternate evaluation. [Module fetch algorithm](https://html.spec.whatwg.org/multipage/webappapis.html#fetch-a-single-module-script), [dynamic import caching](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/import#module_namespace_object).
- **Review completed work before adding experiments.** The post-publication audit found selected-font correctness already observed, final production artifacts available, and the Cocoa identity successor already executed. Correct stale plan status before commissioning repetitions. The next hosted lanes reuse the verified package and existing workloads; source/tooling identities remain distinct.
- **Treat normal-clock precision as a limitation of the overhead claim.** The High Resolution Time specification permits implementation-defined coarsening and jitter. A measured minimum clock step is not a proven error bound. A tighter bounded offline interval method can reduce unnecessary slack under its stated assumptions, but cannot establish that assumption or turn old failed rows into a pass. [High Resolution Time coarsening](https://www.w3.org/TR/hr-time-3/#dfn-coarsen-time).
- **Keep diagnostic tracing out of ordinary timing.** Current Chrome documentation warns that advanced paint instrumentation and CSS-selector statistics significantly affect performance, and that CPU throttling cannot reproduce mobile CPU architecture. Use separate attribution runs and preserve the actual device requirement. [Performance recording settings](https://developer.chrome.com/docs/devtools/performance/overview), [throttling limitations](https://developer.chrome.com/docs/devtools/performance/reference#throttle-the-cpu-while-recording).
- **Budget decoded pixels, not only downloaded bytes.** A Safari 26 report reproduces memory termination with twenty parallel 4000 × 4000 image decodes. WebKit explains that explicit `decode()` uses natural dimensions without the display path’s subsampling. The existing actor pool reserves decoded RGBA bytes (64 MiB standard, 32 MiB compact), and the legacy painter serializes decoding with a 16-million-pixel retained limit. Preserve reservations through non-cancelable decode settlement and verify settled owners after transitions. This supports the existing policy; it does not establish this phone’s failure cause. [WebKit image-decoding example](https://bugs.webkit.org/show_bug.cgi?id=302801).
- **Inspect Safari canvases separately from timing.** Web Inspector can report canvas dimensions and memory and record drawing commands frame by frame. Use that diagnostic to explain native raster or memory anomalies; retain its exported recording separately from low-overhead timing runs. [WebKit Canvas debugging](https://webkit.org/blog/8452/canvas-debugging/).
- **Check whether a browser workaround is obsolete.** The widely cited Safari 17 `drawImage` privacy-protection regression was fixed in WebKit in January 2024. It does not establish the cause on an iPhone 17 Pro. Keep browser security settings intact and require a current reproducible profile before changing surface visibility or canvas architecture. [Resolved WebKit regression](https://bugs.webkit.org/show_bug.cgi?id=266181).

- **Recheck the owner after asynchronous preparation.** A completed network or storage request does not prove that the original menu intent is still valid. Retire late catalogue work before synchronous compilation or adoption; splitting it into helper functions alone does not create rendering opportunities. The new delayed-Missions reproduction makes this a required correction. [Long-task execution and yielding](https://web.dev/articles/optimize-long-tasks).
- **Distinguish asynchronous waiting from CPU attribution.** Web Crypto copies digest input and schedules the digest asynchronously. A loading label or long promise settlement is insufficient evidence that hashing caused the stall. Retain owner state, then correlate a separate CPU/frame diagnostic before moving work to a worker or changing validation. [Web Crypto digest algorithm](https://www.w3.org/TR/webcrypto/#SubtleCrypto-method-digest).

- **Use CPU samples for CPU questions and frame traces for browser rendering questions.** Chrome distinguishes sampled JavaScript stacks from layout/painting events and offers separate call-tree and bottom-up views. Join new HUD spans to a profiler only after proving their clock mapping. The current first-victory profile cannot explain a later Two Bays interruption, and sampled CPU alone cannot attribute GPU or compositor cost. Keep any such diagnostic separate from ordinary timing. [Chrome profiling reference](https://developer.chrome.com/docs/devtools/performance/reference).
- **Keep critical results immediate and defer only independent work.** The web.dev long-task example updates essential UI before yielding lower-priority work. Apply this only after attributing the current terminal HUD: required saves and authoritative state must retain their ownership/order. A microtask does not provide a rendering opportunity; yielding does not remove the work or prove its cost. [Long-task scheduling example](https://web.dev/articles/optimize-long-tasks).
- **Feature-detect Safari interaction measurements.** Safari 26.2 added Event Timing. Use available native entries as supplementary evidence without assuming the affected phone's browser version or replacing continuous-movement application measurements. Browser/device/version still belongs in physical qualification. [WebKit Safari 26.2](https://webkit.org/blog/17640/webkit-features-for-safari-26-2/).
- **Keep all CI partitions required.** GitHub matrix jobs can continue collecting evidence with `fail-fast: false`. Partition only the final unchanged command plan and require every same-source shard and its complete union; a faster wall-clock result must not come from omitted tests or relaxed timeouts. [GitHub matrix behavior](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/run-job-variations).

- **Avoid redundant geometry reads during preparation.** Chrome explains that geometry reads following invalidated styles can force synchronous layout. Directly validating the current controller target removes repeated whole-menu style/rectangle walks, while retaining live checks when navigation needs them. The source counts demonstrate removed work; native traces must establish its actual layout and timing impact. [Chrome forced-reflow guidance](https://developer.chrome.com/docs/performance/insights/forced-reflow).
- **Measure layout before calling a HUD span forced reflow.** WebKit separates style invalidation, layout, paint/composite and rendering frames; media/memory recording can perturb observation. The application markers are inclusive elapsed boundaries. Use the existing separate diagnostic to locate browser work before changing DOM order; batching reads/writes is a candidate only where actual ordering and cost support it. [WebKit timelines](https://webkit.org/web-inspector/timelines-tab/), [layout measurement guidance](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing).
- **Attribute whole rendering frames.** WebKit’s frame timeline separates events/scripts, layout and painting/compositing. Use it in a separate diagnostic pass when callback gaps remain despite inexpensive measured application work; keep raw callback intervals and do not treat hidden idle periods as continuous healthy cadence. [WebKit rendering-frame example](https://webkit.org/blog/3996/introducing-the-rendering-frames-timeline/).
- **Observe the resource owner directly.** CSSOM associates a stylesheet with its `link` through `sheet`. The font diagnostic now targets that existing owner, rejects missing/duplicate/foreign ownership and retains bounded rule inspection. A document-wide inventory limit must not prevent the intended experiment. [CSSOM LinkStyle](https://drafts.csswg.org/cssom/#the-linkstyle-interface), [link.sheet](https://developer.mozilla.org/en-US/docs/Web/API/HTMLLinkElement/sheet).
- **Measure ordinary missed frames independently of long-frame attribution.** Long Animation Frames exposes script and forced-style/layout costs, but its 50 ms threshold misses repeated shorter overruns. Retain callback measurements and separate tracing from ordinary timing. [Chrome guidance and examples](https://developer.chrome.com/docs/web-platform/long-animation-frames).
- **Reduce hidden work and verify sustained power behavior.** WebKit identifies offscreen painting, timers and background callbacks as CPU/GPU costs. Keep covered-board/speculative-work suspension and include Demo ownership in sustained checks. [WebKit power guidance](https://webkit.org/blog/8970/how-web-content-can-affect-power-usage/).
- **Separate owned resources from the browser's memory footprint.** WebKit distinguishes JavaScript, decoded images, graphics layers and other page memory. Repeated-transition checks must compare settled owners and, in separate diagnostic runs, native memory categories. A single snapshot or a cache's first growth is insufficient evidence of a leak; heap snapshots must not contaminate timing runs. [WebKit memory investigation example](https://webkit.org/blog/6425/memory-debugging-with-web-inspector/).
- **Include work deferred by the engine.** WebKit's Speedometer investigation found that allocations in one workload could cause collection in later workloads; canvas work also includes GPU-process and surface-buffer costs. Keep first-thirty-second and sustained windows after preparation, and retain ordinary callback misses even when measured JavaScript is inexpensive. Do not force collection or warm away these costs to obtain a pass. [WebKit profiling examples](https://webkit.org/blog/15249/).
- **Remove work before offloading it.** PROXX demonstrates improved responsiveness even when worker processing takes longer overall. Retain the targeted MP3 structural worker and bounded preparation; do not infer reduced total CPU or substitute workers for the existing browser PCM decoder. [PROXX example](https://web.dev/articles/off-main-thread), [Web Audio decoding](https://www.w3.org/TR/2021/REC-webaudio-20210617/#dom-baseaudiocontext-decodeaudiodata).
- **Use caching appropriate to a single board.** Spatial indexing can add overhead to a single-screen game. Preserve static-layer caching and explicit invalidation; broad spatial machinery is not justified. [Construct renderer example](https://www.construct.net/en/blogs/ashleys-blog-2/render-cells-work-921).
- **Defer complete optional features.** Code splitting can reduce initial evaluation but create request waterfalls. The unopened Library owner and its exclusive graph are deferred together, with explicit loading/cancellation and production/offline validation. Source bytes removed are not measured time savings. [Code-splitting examples](https://web.dev/learn/performance/code-split-javascript).
- **Wait outside database transactions.** Optional admission waits must not hold a live IndexedDB transaction. Retry only after the owned abort settles within its original deadline, and preserve committed-write truth. Yielding alone also does not prevent work competing with gameplay. [IndexedDB lifecycle](https://www.w3.org/TR/IndexedDB/#transaction-lifecycle), [long-task scheduling](https://web.dev/articles/optimize-long-tasks).
- **Keep recovery and native observation truthful.** Do not suppress automatic Canvas2D restoration by canceling `contextlost`. Observe completed native input after its command boundary, not a capture-listener microtask that may run before later listeners. [Canvas context loss](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/contextlost_event), [HTML callback cleanup](https://html.spec.whatwg.org/multipage/webappapis.html#clean-up-after-running-callback).
- **Desktop stress does not qualify a physical device.** CPU throttling cannot reproduce all GPU, browser, display, power-saving or thermal behavior. Record actual device/OS/browser/cadence and the published HTTPS context; retain browser security settings. [Chrome calibrated-throttling example](https://developer.chrome.com/blog/devtools-grounded-real-world).
