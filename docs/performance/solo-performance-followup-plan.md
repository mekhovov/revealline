## Review decisions

The original phases 0–4 remain the implementation direction. Native callbacks, real elapsed time, prepared assets, bounded media admission, cached board layers and presentation-only adaptation address demonstrated costs. This follow-up closes evidence gaps and fixes concrete defects found by qualification. It does not introduce a renderer rewrite, smaller simulation step cap or universal frame-rate guarantee.

1. **Establish a complete test result.** Two failing PR jobs reproduce seven presentation fixture failures. Their assumptions predate the scene-clock reset and retained paused canvas. Correct fixtures must preserve presentation, persistence and checkpoint assertions. A subsequent reward audit also found a real regression: throttling every interface refresh can let an immediate Retry/Next replace the winning run before mastery observes it. Run identity/status transitions require immediate refresh; ordinary polling remains bounded. The earlier interrupted broad run has 234 failures, including confirmed original-main defects and unclassified cases; a passing subset cannot replace a full inventory.
2. **Calibrate CPU stress on this host.** The earlier 4× setting is useful stress evidence but is uncalibrated. Add a reproducible local calibration using Chrome's benchmark and score targets, record every sample and independently verify the selected rate. This still does not reproduce mobile GPU, memory bandwidth or thermals. [Chrome calibration guidance](https://developer.chrome.com/docs/devtools/settings/throttling), [device-comparison limitations](https://developer.chrome.com/blog/devtools-grounded-real-world).
3. **Exercise real work and retain failed attempts.** Border movement with muted audio does not qualify captures, erosion, jammers, combat, recording, music or transitions. Native scenarios must use legal controls and check public outcomes. Fixed-tick model proofs remain correctness evidence. A route that fails under wall-clock input must be recorded as failed; state injection cannot make it a performance pass.
4. **Separate cache states and instrumentation.** Playwright request interception disables its HTTP cache. The existing access fixture therefore cannot prove a cold-versus-warm HTTP comparison. Label that limitation or move only the explicit local access fixture to the server. Run timing separately from screenshots, CPU/allocation profiles, heap snapshots and forced collection. [Playwright route behavior](https://playwright.dev/docs/api/class-page#page-route), [Chrome memory tools](https://developer.chrome.com/docs/devtools/memory).
5. **Measure resource stability without destroying the workload.** Compare the same paused state after repeated transitions, covering owner counters, JavaScript heap and DOM retention separately. A heap snapshot forces collection and omits some native/GPU allocations. `Memory.prepareForLeakDetection` also terminates workers and drops caches, so it is unsuitable for live-owner plateau checks. [Heap snapshot behavior](https://developer.chrome.com/docs/devtools/memory-problems/heap-snapshots), [CDP Memory methods](https://chromedevtools.github.io/devtools-protocol/tot/Memory/).
6. **Use explicit yielding only where measurements justify it.** A resolved promise does not yield to rendering. Substantial remaining optional preparation can use feature-detected `scheduler.yield()` with a task fallback, batching work to avoid excessive overhead. Authoritative ticks, integrity checks and durable-save guarantees remain intact. [Task yielding guidance](https://web.dev/articles/optimize-long-tasks).
7. **Keep Safari findings evidence-based.** Inspect actual canvas/composited surfaces and focused styles before changing them. A historical WebKit canvas/outline report is a useful diagnostic example, not proof of a current iPhone 17 Pro defect. Preserve visible keyboard/controller focus. Use separate Web Inspector CPU/canvas captures for physical diagnosis. [WebKit report](https://bugs.webkit.org/show_bug.cgi?id=248460), [Canvas inspection](https://webkit.org/blog/8452/canvas-debugging/), [CPU timeline](https://webkit.org/blog/8993/cpu-timeline-in-web-inspector/).
8. **Verify native recordings in their observed engine.** Perform strict replay and mechanic verification after measurement, in a fresh instance of the same browser version using the exact artifact modules. Keep Node portability checks separately. Do not replace checkpoints or use the bundled-demo exception. The baseline pilot passes strict Chrome verification but differs in Node's enemy checkpoint; this establishes an engine-dependent result, not the precise mathematical cause. ECMAScript permits implementation-dependent approximation in functions such as sine. [ECMAScript Math.sin](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-math.sin).
9. **Keep result controls stationary throughout activation.** A native Next attempt exposed a shared baseline/candidate defect: dismissing the automatic-advance notice on pointer-down moves Next before pointer-up. The observed click lands on a parent instead. Preserve the occupied result space while canceling the countdown, remove stale accessibility announcements, and verify complete mouse/touch/keyboard activation in a browser. Calling a handler directly cannot detect this defect. Do not rely on CLS alone: its recent-input exclusion can omit shifts within 500 ms of a discrete interaction, exactly where this activation failure occurred. Use a separate, excluded native event/rectangle diagnostic and retain recent-input shifts when available; do not add per-frame layout reads to gameplay. [Recent-input exclusion](https://wicg.github.io/layout-instability/#dom-layoutshift-hadrecentinput), [CLS interaction window](https://web.dev/articles/cls?bbpage=1). The current Pointer Events draft describes ancestor targeting when uncaptured pointer-down/up targets differ; that mechanism agrees with the captured native event sequence. [Pointer Events dispatch](https://www.w3.org/TR/pointerevents4/#event-dispatch), [layout-shift examples](https://web.dev/articles/cls?bbpage=1).
10. **Reuse owned, validated bytes before invoking codecs.** `Blob.arrayBuffer()` reads a stream and creates a new buffer; `FontFace` already accepts binary data. Validate image headers directly from the response bytes already checked for length and hash, and pass the exact font buffer to the font loader. Keep native image decoding, size limits and cleanup. This removes demonstrated unnecessary I/O/allocation without claiming to solve every browser navigation failure. [File API read algorithm](https://w3c.github.io/FileAPI/#dom-blob-arraybuffer), [FontFace binary sources](https://developer.mozilla.org/en-US/docs/Web/API/FontFace/FontFace).
11. **Attribute browser errors to their document and phase.** The observed WebKit error precedes injected recovery faults; its stack and navigation context implicate work in the departing editor. A retained top-level URL alone does not establish the originating frame. WebKit's Blob reader internally uses a temporary URL and loader; a current Playwright issue describes access-control errors during document replacement. These sources suggest a mechanism, not proof of identity or permission to ignore the error. Preserve timestamps, action, URL and stacks, check that test navigation follows the public link's actual behavior, and retain the original failed report. [WebKit implementation](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/fileapi/FileReaderLoader.cpp), [Playwright reproduction](https://github.com/microsoft/playwright/issues/43120).

12. **Separate real browser suspension from injected recovery events.** WebKit suspends animation callbacks on inactive pages, while Chromium Energy Saver can freeze queued tasks in eligible background tabs. Synthetic blur/context-loss dispatch verifies handlers but does not establish native visibility, task suspension or restoration. Keep physical power/cadence observations and an explicitly labeled native browser lifecycle check separate from the controlled fault reports; retain the fresh-clock and explicit Resume requirements. [WebKit power guidance](https://webkit.org/blog/8970/how-web-content-can-affect-power-usage/), [Chrome Energy Saver freezing](https://developer.chrome.com/blog/freezing-on-energy-saver).

13. **Qualify actual steering surfaces separately.** The audit found that the opt-in latency listener includes canvas and individual direction buttons but misses the default stick/swipe surface and pointer-captured moves retargeted to the direction-pad container. Repair only that observability boundary, retaining active-state and lifecycle guards, then verify meaningful native steering and strict replay on a separately versioned artifact. Menu/Next touch activation is not gameplay latency. The current Event Timing draft excludes continuous pointer/touch movement, so it cannot fill this gap automatically; pointer capture also changes event targeting. A mocked gamepad remains synthetic correctness evidence, not physical-controller latency qualification. [Event Timing exclusions](https://www.w3.org/TR/event-timing/#sec-events-exposed), [pointer capture behavior](https://www.w3.org/TR/pointerevents4/#the-setpointercapture-method).

14. **Treat Demo as its own sustained workload.** Preserve replay, practice and background-audio behavior while removing redundant paused and covered presentation. Observe actual canvas calls, control writes, menu animation state and audio activity before considering any further decorative policy. Keep active-play input sampling native. Qualification must distinguish an unchanged spectator pause, visible watching, practice and true hidden-tab behavior; none establishes physical heat reduction by itself.
