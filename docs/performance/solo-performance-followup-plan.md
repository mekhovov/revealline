## Unchanged acceptance gates

Establish **B** during lightweight foreground preparation and record it; do not redefine loaded gameplay as the baseline. Use at least three equivalent baseline/candidate runs per qualification scenario and retain every result. Candidate-only diagnostics and fault injections remain separate.

| Application update/draw/HUD work       | p95 ≤ min(10 ms, 0.6 × B)                                                     |
| Callback interval                      | p95 ≤ 1.2 × B; p99 ≤ 2 × B                                                    |
| Missed callback opportunities          | ≤1%; investigate every consecutive-miss burst                                 |
| Application input-to-render submission | p95 ≤ 2 × B                                                                   |
| Severe interruption                    | No reproducible application-caused ≥100 ms foreground stall or overload pause |
| Retained resources                     | Explicit limits and stable repeated-transition retention                      |
| Diagnostics overhead                   | ≤5% p95 application-work increase in matched enabled/disabled runs            |

Retain all >33/50/100/250 ms intervals and every active-play task >50 ms. Percentiles do not excuse repeated hitches. Input-to-render submission is application latency, not physical input-to-photon latency. Whole-session totals, partial samples, failures and pause-causing intervals remain visible.

## Research review and resulting decisions

- **Keep the published HTTPS environment in the device record.** WebKit maintainers confirm that Safari 27 can apply enhanced-security restrictions to plaintext HTTP navigation. The user's published-HTTPS clarification removes that specific local-development explanation; it does not establish which other browser policies were active. Keep the existing security settings during qualification. [WebKit issue and maintainer confirmation](https://bugs.webkit.org/show_bug.cgi?id=324968).
- **Record the actual Safari release alongside rendering evidence.** Safari 27's release notes include fixes for large-radius blur loading, unnecessary Canvas2D compositing layers and progressively sluggish ResizeObserver callbacks. These examples support testing first draw, restoration and sustained callbacks on the actual browser; they do not establish that any listed bug caused this game's slowdown. Keep bounded decorative effects and paused layout preparation, without adding version-specific workarounds from these reports alone. [Safari 27 release notes](https://webkit.org/blog/18325/webkit-features-for-safari-27-0/).
- **Prepare the final layout before Start.** CSS Font Loading specifies that ready follows relevant font/layout work, while later changes can create another readiness cycle. WebKit's ResizeObserver example also shows layout can run again after observer changes. This supports the implemented paused final-layout owner and boundary checks; it does not attribute an old native interruption. [CSS Font Loading](https://www.w3.org/TR/css-font-loading/), [WebKit ResizeObserver](https://webkit.org/blog/9997/resizeobserver-in-webkit/).
- **Observe completed native input after its command boundary.** The HTML callback cleanup rules permit a microtask checkpoint between native event listeners; a programmatic dispatch can keep an outer JavaScript stack alive and defer that checkpoint. Therefore a capture-listener microtask is not a reliable completion witness. The new Cancel protocol retains early evidence and reads the real state after the existing awaited native key command, without an added delay or application hook. [HTML callback cleanup](https://html.spec.whatwg.org/multipage/webappapis.html#clean-up-after-running-callback), [native/programmatic example](https://jakearchibald.com/2015/tasks-microtasks-queues-and-schedules/index.html).
- **Check the actual selected face.** FontFaceSet.check() can return true without a matching face; it is not definitive loaded-font proof. Keep the raw check value, inspect the bounded exact family/weight/status at preparation boundaries and retain the transport owner. [Specification](https://www.w3.org/TR/css-font-loading/#font-face-set-check).
- **Separate browser delivery from synchronous application work.** Long Animation Frame duration and input blocking measure different things; several shorter tasks can still delay a frame, and the API excludes ordinary 20–40 ms misses. Keep numeric callback evidence alongside application work. [Chrome timing examples](https://developer.chrome.com/docs/web-platform/long-animation-frames).
- **Record the WebKit port and backend.** WebKitGTK's 2.52/2.54 examples describe GPU-dependent tiling, deferred drawing and compositor-thread work. These explain why synchronous submission cannot account for every frame cost. They do not prove those implementations ran in our hosted browser or caused its misses, and Linux WebKit is not iPhone Safari. [2.52 examples](https://webkitgtk.org/2026/03/18/webkitgtk-2.52-highlights.html), [2.54 examples](https://webkitgtk.org/2026/09/16/webkitgtk-2.54-highlights.html).
- **Use workers for the demonstrated JavaScript computation.** PROXX shows improved responsiveness can coexist with longer total processing. Web Audio already performs decoding off the control thread. Keep the static MP3 structural-inspection worker, bounded transfer/ownership and existing streamed music; do not move the entire renderer or decode soundtrack recordings to PCM. [PROXX case study](https://web.dev/articles/off-main-thread), [Web Audio algorithm](https://www.w3.org/TR/webaudio-1.0/#dom-baseaudiocontext-decodeaudiodata).
- **Reduce hidden work and measure sustained behavior.** WebKit recommends stopping hidden animation and unnecessary background work. Preserve idle suppression, optional-preparation admission and owned offline pauses, then verify warmth/background behavior on actual devices. [WebKit power guidance](https://webkit.org/blog/8970/how-web-content-can-affect-power-usage/).
- **Inspect actual canvas surfaces and keep capture separate.** WebKit's canvas tooling exposes commands, dimensions and memory, while its timeline documentation warns that capture can affect performance. Profile only separate diagnostic runs; theoretical viewport pixel count and sample counts are not raster duration. [Canvas example](https://webkit.org/blog/8452/canvas-debugging/), [timeline limitations](https://webkit.org/web-inspector/timelines-tab/).
- **Keep desktop stress in scope.** Chrome's calibrated-throttling example shows GPU differences can make a phone slower than a CPU-throttled desktop prediction. Use desktop stress as evidence, then qualify the user's devices under recorded cadence, power and sustained conditions. [Chrome example](https://developer.chrome.com/blog/devtools-grounded-real-world).

Completion means demonstrated removal of application-caused stalls within the declared qualification scenarios. It cannot guarantee behavior against browser scheduling, driver failures or thermal throttling. Current results do not yet meet that completion condition.
