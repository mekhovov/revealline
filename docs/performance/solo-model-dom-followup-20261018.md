# Modeled DOM lookup correction

The fixture reused its generic selector parser for each ID lookup and for each element visited by every selector query. A bounded actual Solo probe made 1,080 `dialog[open]` queries in 60 frames: the modeled host has no MutationObserver, so the application correctly retains its unsupported-host polling fallback. No observer or application behavior was changed.

The two test-only changes use literal depth-first ID lookup over the current document tree and retain at most 64 parsed selector descriptions of at most 2,048 characters each. The cache contains syntax only. Queries still visit the same current tree and read current attributes, ancestry and visibility. Long selectors are parsed without retention. ID tests cover duplicates, root membership, special characters, moves, removals and ID changes.

On the same 60-frame model workload, the original probe recorded 4,742,553 element matches, 1,233 ms in dialog queries and 1,374 ms total. The final helper retained all 1,080 dialog queries and recorded 4,100,280 matches, 375 ms in dialog queries and 426 ms total. Both reached tick 120 and checkpoint `a45091e5ac1e696b`. These are local model observations, not browser performance or attribution of a native stall.
