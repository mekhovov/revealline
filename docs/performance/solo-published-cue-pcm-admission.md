# Published cue PCM admission

The published-cue owner previously reserved a guessed stereo duration before native decoding and checked the actual duration and channel count afterward. A canonical 120-second mono PCM8 WAV is only 960,044 bytes, below the published 4 MiB original limit. At a 48 kHz context rate its output requires 23,040,000 PCM bytes, but the old owner reserved 5,760,000 bytes and called the decoder before rejecting the result. The retained reproduction observes the actual owner and shared queue with a controlled decoder; it allocates no native PCM and makes no device-performance claim.

The new boundary validates encoded bytes before native decoding. It accepts bounded PCM/IEEE-float RIFF WAVE, including the standard extensible subformat, with exact chunk sizes, one format/data chunk, consistent block alignment and frame counts, and a 1,024-chunk traversal bound. MP3 uses the existing complete Layer III inspector. Every materialization, scan, and hash stage passes through the owner's existing safe-phase admission, including after asynchronous work. Active play uses the existing fallback while a demanded inspection waits for a safe phase. No new worker or resource manager is created.

Admission uses the validated channels and source frame count, plus the ceiling of resampled output frames at the actual context rate. When rates differ, the reservation conservatively includes both source and output PCM; equal-rate decoding reserves one buffer. The shared 16 MiB limit and existing cue duration limits remain unchanged. This follows the Web Audio sequence of decoding and then resampling; it does not claim to bound browser-internal codec overhead. Postdecode length/channel checks remain defensive. [Web Audio decoding and resampling](https://www.w3.org/TR/2021/REC-webaudio-20210617/#dom-baseaudiocontext-decodeaudiodata), [AudioBuffer PCM representation](https://www.w3.org/TR/2021/REC-webaudio-20210617/#AudioBuffer), [Microsoft RIFF layout](https://learn.microsoft.com/en-us/windows/win32/xaudio2/resource-interchange-file-format--riff-), [WAVEFORMATEX alignment](<https://learn.microsoft.com/en-us/previous-versions/dd757713(v=vs.85)>).

The runtime inventory contains WAV and MP3 originals and no Ogg files under `game/`. Compiling the current default presentation in memory gives 21 audio slots, all recipes with no encoded MIME. This is a source inventory, not inspection of the next production package. Authoring Ogg originals do exist. **Custom published Ogg, compressed WAV, and alternate WAV layouts without a provable bound now use the established optional fallback.** The published schema and streamed music playback are unchanged; this note does not claim that every previously accepted container still decodes as an effect.

Cancellation retains the shared reservation until actual byte materialization or native decoding settles. The loader rechecks the exact context/controller after materialization before calling the decoder, discards abandoned results, and retains the fallback for an unprovable or oversized cue so gameplay events cannot repeatedly retry it.
