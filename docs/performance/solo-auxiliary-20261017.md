### Retained failure now narrows the WebKit cause

Immediately after import completion, action 16 records the public error **“Decoded MP3 duration must be finite and at most 12 minutes.”**, status `error`, 36 playlist options and an empty selection in both WebKit arms. Later action 20, Apply listening, replaces that error with a saved-selection message without adding the missing playlist. Action 21 then times out after the original 30-second selection deadline. The diagnostic now establishes the earlier import failure instead of treating the selection timeout as the cause.

Only the first Bossa Nova audio Blob is observed, with its exact resolved hash and 1,196,325-byte identity; no playback event occurs. `probeMP3Media` checks native `duration` after `readyState >= 2`, rejecting non-finite, non-positive or greater-than-720-second values. That function is byte-identical in the two source revisions (SHA-256 `db5a39714b2ff996047ed6b15c28a8267b345a8321b991dc6042f4613663985b`). This report did **not** distinguish `NaN`, infinity, zero, an excessive finite value or a transient value. The later passive observation below resolves the rejected value as zero; whether it would subsequently become positive remains unobserved.

The HTML standard distinguishes unavailable duration (`NaN`) from unbounded duration (`Infinity`) and defines `durationchange` when the value changes. It also requires duration determination before metadata readiness. The next useful evidence is therefore the actual value class and readiness/event sequence before application cleanup, while retaining finite-duration and integrity validation. This is an investigation direction, not a claim that this engine violates the standard. [HTML media duration and ready states](https://html.spec.whatwg.org/multipage/media.html#dom-media-duration)

Playwright uses its own patched WebKit build; branded Safari cannot be driven through that implementation. Its media codecs also vary by operating system, with macOS closest to Safari. The Linux failure remains a concrete compatibility finding, but it cannot establish the cause on the user's iPhone 17 Pro. [Playwright WebKit limitations](https://playwright.dev/docs/browsers#webkit)
