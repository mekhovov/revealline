# Optional replay verification admission

Main Solo optional replay verification now uses the existing media-preparation main-thread owner for each bounded synchronous reconstruction chunk and final checkpoint. The legacy mastery observer setup after the initial yield uses that owner too. Active play and suspension leave this work pending; Pause or a safe menu/preparation phase can admit it. There is no new scheduler, worker, simulation policy or timer allowance.

The opt-in callback reaches Journey personal-best capture/hydration, automatic/manual Demo retention, legacy equipment awards, authored Journey mastery and completed authored lesson evidence through their existing owners. An early nullable reference permits bootstrap hydration before Soundscape exists, then uses the actual shared owner for later chunks. Saved-flight restoration and other default verifier consumers do not receive this callback, so required restoration cannot deadlock waiting for a flight that has not started.

The callback receives only a synchronous closure and its existing abort signal. Core state is not exposed. Missing, repeated or retired invocation fails, including a repeated invocation whose exception a scheduler swallows. No main-thread slot is held across another asynchronous admission. Replay chunks retain the existing 600-tick default (caller range 1–1,200) and 8 ms checked-every-eight-ticks boundary. The separate authored learning verifier retains its 600-tick/8 ms boundary, consecutive evidence observations, release inputs and every anchored learning action.

Demo retention rechecks its original generation inside admitted work, so disable/clear/dispose cannot resume obsolete verification and write. Existing Journey, mastery and lesson abort lifetimes remain authoritative. Pending rewards remain attached to their original captured attempt; the ordinary earned-picture reward is not delayed.

## Demonstrated gap and regression scope

The exact-before Journey controller reproduction used a valid 2,918-tick recording. Both capture and hydration completed five yield callbacks and 369 verifier clock reads after the existing media owner had switched to playing, without entering its queue. Capture committed once; hydration did not write. This demonstrates an admission gap, not measured native cost or the cause of any retained frame interruption.

Six new Demo/legacy-owner controls fail against the original production modules and pass with admission. The authored mastery public-host negative persists its old proof during immediate Retry; the corrected host holds it until public Pause. Five optional learning controls also fail against original modules. The default evidence, restoration and proof-wire tests retain exact results with no admission option.

The actual modeled Main Solo Next and Retry cases restore a legitimate historical flight, execute its legal win, retain its ordinary picture immediately, and start a new run while the old optional seal is pending. The new run advances 120 ticks while optional verification remains held. Public Pause then permits the original seal to become durable without changing the new paused checkpoint, awarding another picture or announcing the old seal as the new attempt's result. The complete authored mastery host similarly preserves its original accepted clear across Retry; the completed-bonus UI control closes its dialog, holds verification during play and preserves out-of-order independent proof saves after Pause.

These are Node host/core controls, not browser/device timing observations. The pre-existing 180-second per-case public-host bounds are unchanged. All source snapshots are still taken before the first yield; caller mutations after submission cannot alter the checked replay, campaign, mastery rule or learning transcript.

## Scope and retained evidence

This removes optional replay reconstruction, post-yield legacy observer setup and final verification from active-play admission. It does not remove the synchronous pre-yield snapshot/validation/create-run cost, or every downstream identity, binding, hash, projection and storage operation. Journey comparison construction, proof hashing and durable storage still use their existing owners and guards. No retained native stall is attributed to this path without profiling, and no previous failed native result is promoted.

Evidence is retained under `.cache/solo-followup/performance-verification-admission/`: `exact-before.tap`, `owners-before.tap`, `authored-host-before.tap`, `learning-before.tap`, the complete before/after TAP files, `paths.json`, `proposal.patch` and `review.json`. The corrected loader preserves query/hash identity. Initial learning-control fixture mutations targeted frozen output; their red is retained and the controls now mutate the caller-owned clone. Neither correction changes runtime or a native outcome.
