The executable harness separates three kinds of evidence: native performance observations, repeated public-UI lifecycle transitions, and synthetic recovery-handler checks. Fixed-step route preparation is recorded as model correctness. None of these substitutes for the iPhone 17 Pro Safari or Steam Deck OLED Chrome check.

Create a new fixture directory with `node scripts/prepare-solo-qualification.mjs <new-directory>`. The preparer replays existing legal routes, verifies their public replay, and rejects missing required mechanics. It writes validated Playground imports and runnable `.qualification.json` cases. It does not edit a player profile, gameplay definition, archive or runtime.

The prepared cases cover:

- `first-return`: a real capture and win.
- `long-rail`: a longer authored cut/capture route with patrols.
- `first-fracture`: earned erosion and recapture on the existing Fractured Grid definition.
- `sentry-detour`: the existing Standard, seed 1, grid-centred route, including an actual fired projectile. The immediate-turn route currently produces no projectile and is deliberately excluded from that claim.
- `signal-07`: thirty seconds of the shipped lane-boss mission. Its warning/active phases activate the same jammer-picture filter used by reception interference.
- `original-art-opening`: the public opening Journey and its registered originals, with a real long cut and large capture. Its recording must confirm at least twenty trail cells and five hundred claimed cells.
- `original-art-sentinel`: the public `?pack=sentinel-relay` route, preserving the shipped original JPEG background and encounter. Thirty seconds of border key gestures run through its warning/active phases. The actual exported recording must confirm jamming occurred; importing a greybox version is not used for this case.
- `twenty-retries`: twenty completed wins and actual Retry transitions, with equivalent result resource snapshots.
- `ten-next`: eleven opening wins and ten actual public Next transitions. This uses the public opening Journey, not the single-level Playground. Existing fixed-step commands are translated to real-time gestures; any missed result remains a failed observation.
- `enabled-audio`: user-gesture unmute, a local music-style change, enabled reaction preference, and native audio API activity. The report does not claim audible sound, a speech clip, or remote playlist playback unless separately observed.
- `recovery`: synthetic Canvas loss/restoration and blur/focus events, plus an actual viewport resize and explicit Resume. This tests handlers; it does not cause native GPU loss or a real mobile orientation event.
- `large-profile`: a validated synthetic backup with 480 campaign records, 3,840 gallery records and 960 score records, imported through Scores & saves, reloaded and played. This exercises metadata pressure; it excludes original-media and custom-soundtrack libraries.
- `thirty-minute-soak`: at least thirty real minutes of capture/result/Retry cycles, with bounded repetition and owned-canvas plateau rules. It fails if the duration cap, expected outcomes, or resource checks are not met.

Run one case against the exact generated build under production policy:

```sh
PLAYWRIGHT_MODULE=/absolute/path/to/playwright-core/index.mjs \
CHROME_EXECUTABLE='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
node scripts/qualify-solo-runtime.mjs \
  http://127.0.0.1:8776/game/ \
  /absolute/path/to/fixtures/first-fracture.qualification.json \
  /absolute/path/to/new-report.json \
  --server-fixture-access --source-revision=<runtime-commit>
```

Use `--browser=webkit` for WebKit. `--cpu=4` is an uncalibrated Chromium CPU proxy, not a Steam Deck preset. Only run timing after builds, tests, profilers and archive copies have stopped. Use a fresh report name: the runner refuses to overwrite prior evidence and preserves partial failures.

For a matched original-main comparison, use `--work-probe` on both builds and add `--baseline-runtime` only for the baseline. Baseline mode requires a full `--source-revision` and verifies the generated `game/build-info.json`; it permits absent application diagnostics without replacing them with zeros. Run the same scenario, browser, viewport, input timings, audio settings, cache mode and work-probe flags at least three times on each build. Retain failed routes and their partial external measurements instead of selecting only completed attempts. A route that fails differently cannot qualify the full requested workload on that build.

The shared independent probe measures Phaser `PRE_STEP` through `POST_RENDER`, including render submission and observer overhead. After boot and observable required picture/Start readiness, it captures thirty non-playing rAF intervals with a five-second deadline. The fixed median B is admitted only when the coefficient of variation is ≤0.10 and p05–p95 spread is ≤20% of B; otherwise calibration remains provisional. Raw samples, variance, visibility, phase and picture state are retained. Optional catalogue/decode work can still be present, so this ready window does not prove quiescence. The runner never recalibrates during play. Independent work/cadence/missed-frame gates remain separate from missing baseline internal latency, safety and owned-resource counters. Exact work quantiles are reported only when the bounded5,000-callback ring retained the entire document's observations; otherwise only histogram bounds are available. Baseline `partial-baseline-internal-unknown` is not a complete performance pass.

`--server-fixture-access` unlocks the local preview server's fixture password without adding browser routing. With the server's revalidation cache policy this preserves normal HTTP cache behavior. `--fixture-access` instead rewrites the HTML access metadata with Playwright routing; that disables HTTP cache and is explicitly labeled. Neither changes CSP. Service workers are blocked in this runner; offline install/update testing remains separate.

To exercise the catalogue's real same-origin policy, optionally use `--public-url=https://mekhovov.github.io/revealline/game/ --manifest=/absolute/path/to/frozen/manifest.json` while the positional URL remains the local generated build. The browser retains the original production origin and exact CSP. Every manifest-admitted deployment path uses local transport, including `authoring/` dependencies outside `game/`. Missing deployment paths are blocked instead of falling through to today's public runtime. Only the explicit sibling `/revealline-soundtracks/` publication may remain live on that origin. The manifest revision and hash are recorded. This is synthetic network/origin qualification and disables HTTP cache; it does not establish deployed network latency. No security-disabling browser flag or CSP weakening is used.

The practice cases import scenario files through the public Playground file control, launch its ordinary preview, and follow the prepared full-preview link. Original-art cases launch their public Journey or pack directly. The runner never writes IndexedDB, localStorage, sessionStorage, run objects, simulation ticks, or caches. Authored gameplay definitions stay unchanged; prepared practice fixtures omit authored decorative backdrops and cannot qualify original-art decode/memory pressure. After gameplay, mechanic cases export the actual recording through More → Workshop tools → Export replay. Only after the browser closes does the harness verify and reconstruct that recording, counting actual captures, erosion, shots and jamming. Requested coverage is separate from this proof; a missed feature fails the scenario.

`scenarioStatus` describes public actions, actual outcomes, replay mechanics and declared resource checks. `performanceGateStatus` is separate. The evaluator uses the final paused application export and its measured pre-play cadence B. It checks playing-work p95 ≤ min(10 ms, 0.6B), cadence p95 ≤ 1.2B and p99 ≤ 2B, missed opportunities / (observed + missed) ≤ 1%, and keyboard input-to-submitted-render p95 ≤ 2B. It requires at least 100 playing frames and 20 keyboard samples for those respective checks. Missing calibration or samples remain unobserved; a quantile bucket crossing its threshold is inconclusive. These minimum counts are safeguards against tiny passes, not statistical confidence. At least three independent runs per scenario/browser/quality are still needed.

A numerical pass means only `pass-observed-window`. Interruption/failure counters must be zero. Any prior-playing-phase interval ≥100 ms, playing work >50 ms, or burst exceeding two missed opportunities requires attribution before qualification. Transition-crossing intervals remain in the report; a pause transition is not silently deleted or declared an application stall. Physical devices, thermal stability, resources, actual mechanics and matched diagnostics overhead remain separate. The runner does not establish a ≤5% overhead bound; use the paired diagnostics tool and retain inconclusive results. Recovery cases are explicitly excluded from numerical performance qualification. Exit code 1 denotes a scenario/replay failure; 2 denotes failed numerical gates or invalid numerical evidence after a successful scenario. Exit 0 may still contain inconclusive or review-required gates: inspect the JSON, not just the process exit.

Each snapshot requires a paused/result boundary. Counter comparisons use a named group of compatible snapshots and explicit paths; missing counters are unobserved, not zero. Owned categories may share underlying assets, so the harness does not sum them into total browser memory. Forced GC, heap snapshots, `Memory.prepareForLeakDetection`, screenshots and pixel readbacks are excluded from timing. The rAF histogram reports bounded quantiles and retains transition-crossing severe intervals. Native audio starts prove API activity, not physical speaker output.

For separate recorded-audio correctness, run a prepared speech or imported-music scenario with `--audio-proof`. The same scenario without this flag remains the ordinary performance run. Proof mode copies and hashes at most 2 MiB per encoded recording, 16 MiB in aggregate and 64 identities; it never reads PCM samples. A speech requirement passes only when an exact original-file hash is linked to a successful native buffer start during running, picture or result presentation. A decoded cache entry, enabled preference or paused preview alone cannot pass. `audio-ready` waits for exact decoded recordings only in proof mode; ordinary timing uses the declared fixed preparation wait, whose recording readiness remains unobserved.

Imported music proof links each playable `audio/*` Blob URL to its original encoded hash, requires native playback and at least the declared advancement of `currentTime`, and retains first-track order. A labeled `natural-music-transition` duration wait contains no harness input. Within that window, a switch to the other known recording requires the outgoing track to be within four seconds of its duration or to have emitted native `ended`; this admits the player's near-end crossfade. All timestamps and supporting events are retained. Events are bounded to 512, buffer starts to 128 and retained media elements to eight; missing, pending or capped identities remain unobserved and fail an explicitly requested proof. The whole proof run is excluded from timing and memory qualification, and cannot be combined with `--memory-profile`. Hashing and retained elements perturb both. API starts and advancing media do not establish audible output at the speakers.

The public `result` action waits for the visible won/lost overlay and uses only available Skip celebration / Show result buttons, with a bounded deadline. It does not advance clocks or assign the result. This avoids assuming that celebration controls appear within a fixed short delay.

For a separate Chromium memory run, add `--memory-profile` to `twenty-retries` or `ten-next`. At each paused/result snapshot (maximum 64), the runner retains `Runtime.getHeapUsage` and `Memory.getDOMCounters` before and after `HeapProfiler.collectGarbage`, alongside the existing owned-resource export. It summarizes the last ten same-group post-GC checkpoints, reporting values, range and first-to-last change. Missing optional native counters remain unavailable. No universal heap tolerance or leak-free verdict is invented. The whole report is labeled `memory-profile` and excluded from timing qualification; forced GC alters browser behavior. It never calls `Memory.prepareForLeakDetection`, which would retire workers and caches. Chromium JS/embedder/backing-store counters are not total process, native audio decoder or GPU memory.

Existing paused exports retain the quality-policy snapshot. First-active action boundaries and paused snapshots additionally read only the scene's retained `lastPaint.quality`, using a one-time Phaser constructor capture; they never call draw options or reconstruct asset ownership. These sparse samples label observed tiers and leave intervening changes unknown. The added phase, audio and quality observers mean this harness is separate from ordinary diagnostics overhead qualification. A failed route attempts a public Escape to pause, marks that harness-induced boundary and retains partial application diagnostics before closing; the failed status is preserved.

The remaining device handoff should use the generated build directly, ordinary access, and the actual saved library. Record the browser/OS version, active refresh rate, viewport, power mode, battery/charger, temperature state, audio output and input method. On both devices, collect cold opening, repeated warm opening, long cuts and captures, an earned erosion, active jammer/lane attack, combat warning/projectile, enabled music and speech, ten Next transitions and twenty Retries. Pause before exporting diagnostics. Repeat a thirty-minute active session from a cool start; note thermal changes and exact interruption times. On iPhone rotate both ways, background/lock and return; on Steam Deck test the controller and Chrome focus transitions. Verify the same mission resumes only after explicit Resume. A clean desktop proxy cannot close these physical-device checks.

Actual speech playback, installed original-media/custom-soundtrack pressure and native context loss remain separate qualification cases until their concrete actions and observed outcomes are recorded. Prepared cases are not executed evidence until their native reports exist. Public `upload` actions are available for existing `.rlmedia`, `.rlsound` and profile backups; the runner hashes uploaded bytes and leaves all application validation and confirmation flows intact. Never populate storage directly to turn an unobserved case into a pass.
