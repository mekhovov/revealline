## Implemented changes

1. **Timing and evidence.** Native Phaser callbacks remain unlimited, with smoothing disabled. A monotonic scene clock feeds the existing 120 Hz simulation. Actual interruptions over 250 ms pause before catch-up; lifecycle transitions clear debt and pending input observations. Diagnostics retain startup, interrupted and partial windows, lifetime histograms, bounded recent samples and failure reasons. No automatic uploads occur.
2. **Unnecessary work.** Combat validation translates only failing checks. Played-mission links use accepted mission identities without constructing the unified library. Journey sharing needs no discovery request. Optional Classic sharing runs while paused and cannot hold Start; Resume cancels its request and prevents late parsing or pack cloning. Solo resolves its immutable music catalogue once; transport notifications reuse the existing safe selection cache. Scene transitions also reuse the owned, validated library after local-playback/playlist policy is applied, without copying the entire catalogue again. Replacing library data clears both caches, and invalid contexts are rejected before playback state changes. Optional menu panels, historical route factories and company bootstrap modules are deferred.
3. **Readiness and media.** The owned preparation lease awaits relevant picture/actor decoding and painter caches, then a paused board submission before accepted Start. Optional audio uses fallbacks. Default muted Start defers unused context construction until an audible control gesture. Effects, speech and music share narrow admission controls: two fetches and one PCM decode, with reservations retained until non-cancelable decoding settles. MP3 structural scanning uses one reusable static worker; worker-unavailable main-thread fallback checks safe-phase admission separately at byte reading, synchronous scanning and checksum initiation, including Resume between asynchronous stages. Soundtracks remain streamed.
4. **Rendering and interface.** Structural HUD updates are change-driven; clocks and movement-derived status refresh at 10 Hz. Locale formatters and displayed dimensions are cached. Coverage uses a stable text node and transform. The painter caches fitted pictures, concealment, terrain and exact boundary geometry, detecting equal-coverage topology changes. Prepared noise replaces decorative pixel readback. Full/reduced/minimal tiers affect decoration only and respect Reduced Effects. Unchanged paused, covered and hidden boards avoid both painter redraw and Phaser display compositing. Foreground-paused controller polling continues independently; hidden or unfocused Solo suspends it. Required animation, resize, recovery and Resume invalidate drawing suppression. Local and external display, encounter, ground and theme preference changes invalidate the paused board once. Adapter restoration replaces snapshot identity and retires old derived canvases so Team cannot keep expired image references.
5. **Resources and recovery.** Images, PCM, canvas layers, workers and pending reservations expose separate diagnostics. Estimates enumerate owned displayed/detached, ground, static, adapter, demonstration, jammer and noise surfaces plus pixel buffers. Browser-internal copies, GPU allocation and total process memory remain unobservable through this accounting; overlap with shared presentation images is explicitly labeled. Canceled decoding retains its reservation until settlement. Binary image validation avoids a base64 round trip; required legacy data URLs use cancellable native encoding. Displayed and owned Canvas2D surfaces report loss; recovery invalidates/rebuilds presentation while preserving the authoritative run and requiring explicit Resume. `contextlost` is not canceled. Shared FPV reaction output was regenerated from its canonical dependencies; FPV flight rules were not changed.

Replay/save formats, accepted campaign and mission identities, controls, actor geometry and capture rules remain unchanged. Save verification and readback authority remain intact.

The final media audit additionally guards late online-catalogue parsing, authority adoption, source unions and menu updates. Network slots are released before parsing waits for preparation or pause. Existing validated catalogues remain available to active saved playlists. Late player/panel construction and saved-library adoption also wait for a safe phase; cancellation cannot revive them after page teardown. Existing bounds remain four sources, at most 2 MiB and 512 records each. Those bounded downloaded chunks can remain queued until a safe phase. Newly requested uncached metadata may wait until pause; optional discovery does not hold Start.

Manual resource exports now include effect, published-cue and reaction PCM caches with their existing limits, plus the procedural-noise buffer. These are constant-time owner counters. They exclude active voices retaining evicted buffers, native decoder/storage copies, streamed media and browser overhead. Pending admission reservations are caller-declared source-byte or estimated-PCM amounts, not measured native allocations, and must not be summed with retained cache bytes as total process memory.

The offline scheduling audit found no automatic bulk installation initiated by active Solo. Ordinary Start uses only optional local retention, bounded to one second, before required picture readiness (`game/offline-download-access.mjs`); selected gameplay assets continue through their verified loaders. Opening the lazy download panel pauses Solo, and closing it cancels its owned request. The existing downloads page already yields its approved transfer to reported gameplay and can resume that same approved selection when play ends (`game/downloads.mjs`); verified committed files remain reusable. This change adds no global worker abort, automatic installation, or new resume policy. The shared worker pause message remains unsuitable for a new unconditional Start hook, so no such hook was added.

## Reproducing browser observations

Run `scripts/observe-solo-performance.mjs` against separately served baseline and candidate origins. Supply `PLAYWRIGHT_MODULE` and, for Chromium, `CHROME_EXECUTABLE`. The script accepts `--browser=webkit`, `--runs=3`, `--duration=30000`, `--warm`, `--inputs`, `--input-probe`, `--work-probe`, `--cpu=4`, `--diagnostics=0` and `--source-revision=<commit>`. Keep every report, including failures and early pauses. `--inputs` sends a real right edge, waits 1358 ms, then sends down on the opening mission; it does not spoof simulation time or guarantee an identical final board when scheduling differs. The separate input probe alternates directions on the opening mission's revealed border. The optional work probe measures the native Phaser PRE_STEP-to-POST_RENDER interval in both diagnostics-enabled and disabled runs.

The optional `--fixture-access` flag is restricted to localhost and changes only the access verifier in the test response to a known fixture credential; it then submits the real access form. Production source and content-security policy are unchanged. Reports disclose this fixture.

The access fixture uses response interception, which disables Playwright's HTTP cache; the ordinary source server also sends `no-store`. Consequently `--warm` describes a second navigation in the same profile, not a qualified warm HTTP-cache run. A real installed/warm-cache qualification must use the production build without interception and a normal authorized profile.

CPU throttle factors are desktop stress settings. Record an independently measured calibration before describing a run as device-calibrated. They do not simulate a mobile GPU, memory pressure or thermal behavior. Run timing captures separately from screenshots, CPU profiles, heap snapshots, builds and test suites. Default audio settings, exact browser/version, viewport, source identity, inputs and preparation/active times belong in every result.

For manual diagnostics, open Solo with `performance=1`, pause, then export `RevealLineSoloPerformance.export()` from the browser console. Calibration requires thirty lightweight foreground callbacks before play; an early Start reports its 60 Hz baseline as provisional. Export is rejected during active play. Input measurements end at application render submission, not physical input-to-photon display.

Controller diagnostics measure assigned controller samples, including unchanged/neutral polls; they do not isolate physical action edges. Internal instrumentation starts after eager module imports, so external timing/CPU traces are required for complete startup attribution. Long Task and Long Animation Frame duration aggregates alone do not attribute a stall to a script or phase. Resource exports are snapshots, not automatic memory peaks or proof of a plateau across transitions. Solo owns the new phase and explicit recovery policy; shared-helper regression tests do not imply that Team and Versus have adopted every Solo host policy.

Use `scripts/serve-production-preview.mjs` for local public-policy checks: the ordinary source server has no CSP and the usual preview intentionally has a broader preview policy. `scripts/verify-solo-build.mjs` checks the finished artifact's manifest hashes, source agreement, static/dynamic module and worker closure, offline descriptors, service-worker configuration and ZIP sidecar digest. Native worker and paused-canvas probes should then run against that finished artifact as well as source.

## Release gates and remaining qualification

Use the approved budget relative to the measured pre-play interval B: application p95 ≤ min(10 ms, 0.6B), callback p95 ≤ 1.2B/p99 ≤ 2B, missed opportunities ≤1%, and application input-to-render p95 ≤2B. Investigate every repeated missed-frame burst and every active task over 50 ms. A reproducible application-caused foreground stall of at least 100 ms fails qualification even when aggregate percentiles pass.

The user identified the affected devices as **iPhone 17 Pro using Safari** and **Steam Deck OLED using Chrome**. Physical qualification on these devices remains required. The active Deck refresh rate is unconfirmed; do not infer it from the model. Record OS/browser, display cadence, battery/power-saving state, orientation and sustained conditions. Qualification must include enabled recordings/speech, large saved profiles, long cuts/captures, erosion, combat/jammers, repeated transitions, memory pressure and a 30-minute sustained session. Recovery fault injection is evaluated separately from performance-pass runs. A cheap stable 30 Hz browser cadence must not repeatedly lower quality; GPU/compositor stalls cannot be diagnosed from CPU submission cost alone.

No universal no-stutter guarantee follows from desktop tests. Browser scheduling, GPU drivers, memory pressure and thermal throttling remain outside the application's control. Existing published artifacts were not replaced. The baseline source and fixtures are archived with a checksum for reproduction; this source archive is not a prebuilt release artifact. Release only after the declared gates pass; the implementation and diagnostic results are not an automatic publication approval.

## Reference guidance

The timing policy follows Phaser's distinction between smoothed delta and actual elapsed time; it retains the browser's native callback cadence. See [Phaser TimeStep](https://docs.phaser.io/api-documentation/class/core-timestep). The checked-in runtime and regression tests remain the authority for this project's installed version.

Canvas2D recovery preserves automatic restoration: canceling `contextlost` would suppress it. See [MDN's context-loss behavior](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/contextlost_event). The application work targets leave room for the browser's rendering pipeline, following [web.dev rendering guidance](https://web.dev/articles/rendering-performance); measured CPU submission time alone does not establish GPU or physical display completion.
