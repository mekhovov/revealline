# Text size preference

The working source adds **Text size: Standard / Large** to Settings. The value is a presentation preference, separate from board geometry, steering, campaign difficulty, scores and replay identity. Browser zoom remains independent; this setting does not establish device accessibility or replace viewport checks.

`preferences.textSize` accepts exactly `standard` or `large` in the existing `xonix-library.v2` profile. An omitted own property in a valid older v1/v2 profile becomes `standard` in the owned in-memory copy. Explicit undefined, null, other types, unknown strings, accessors and inherited values reject. Reading an older profile never rewrites its stored bytes. The usual successful save persists the normalized preference.

The existing per-preference merge keeps a newer stored size when an older caller edits an unrelated preference. An explicit change from Large back to Standard is retained. Hosts must apply the actual returned library after a successful save or import, rather than reapplying the possibly stale control value. Startup, complete-backup import, Undo and profile adoption must synchronize both the Settings control and presentation state.

No storage key, backup envelope, campaign key or session/replay format changes. Complete backups carry the preference alongside the original pack and saved-flight data; restoring the preference must not change that attempt. The existing writer, generation and backup locks remain authoritative. Failed writes keep the valid session value exportable and preserve the previous stored profile. Practice preferences stay in that practice session through the existing non-writing settings path.

This is forward compatibility: new source reads omitted values in older exports. Older frozen readers can reject a newly exported profile containing `textSize`; no older artifact or fixture is rewritten to accept it.

Maintainer APIs are [text-size.mjs](../game/text-size.mjs) (`TEXT_SIZES`, `DEFAULT_TEXT_SIZE`, `resolveTextSize`) and the existing [library functions](../game/library.mjs). Use `updatePreferences(library, {textSize})`; do not write the profile directly. The [persistence tests](../game/test/text-size-library.test.mjs) cover strict migration, no-write rejection, exact retained metadata, stale merges, a verified historical suspended attempt, complete-backup replacement/Undo and failed saves. Those tests model storage and image decoding; actual Large-text layout and browser interaction require separate checks.

Six [solo-host tests](../game/test/text-size-host.test.mjs) exercise the actual app and Settings handlers: persisted Large at startup, a Standard change across reload, both steering modes' paused live cuts and verified Resume recordings, failed storage followed by a successful unrelated save, adoption of merged preferences, and complete-backup import/Undo. Opening Settings performs its ordinary pause/save first; the subsequent size changes preserve the exact run checkpoint, selected campaign and saved-slot bytes without another attempt write. Backup replacement follows its existing Ready preparation and retains the verified suspended flight. These tests model the DOM, Phaser drawing and browser storage; they establish neither actual typography/layout nor real multi-tab contention.
