# Staged visual-theme resource ownership

`prepareVisualThemeLease({catalogue, selection, content, requiredSlots}, {createHost, signal, onStatus})` connects the owned compatibility catalogue to the verified compiled-asset loader. Use content from the accepted Legacy/Team/Journey identity adapter and required slot IDs from the code-owned mode/scene registry. It returns the catalogue's explicit campaign-style/unavailable/unsupported outcome without loading a host; it never silently substitutes another collection.

For compatible content it bounds and owns required slots, creates an independent host, loads the exact manifest hash, and verifies the accepted source/theme/collection/hash and required roles. Only then does it return `kind: prepared-presentation` with the match, decoded snapshot, explicit `release`, and guarded apply/picture/audio operations. Picture/audio reads force this lease's accepted snapshot even if options attempt to override it. They retain the existing loader's lazy verification semantics; readiness here does not claim all picture/audio bytes are already available.

The host factory is trusted code and must create a new unused host. A mistakenly supplied host with an accepted snapshot is rejected without reloading or closing it. The page-wide shared host is never the staging target. After return the caller owns the lease until explicit release; a later preparation-signal abort cannot destroy an adopted attempt. Failed checks and cancellation close only staged resources. Observer exceptions cannot own state; readiness is reported only after identity/slot checks.

This is one dependency of staged attempt preparation, not the full coordinator. The host must retain results/current flight, own request generations and discard stale returned leases, finish exact reveal-art/audio dependencies, validate run/session state, and adopt once. It must release every rejected/replaced lease exactly once. Keep campaign, progression, earned originals, legacy save readers and interface appearance authority unchanged.

Remaining before theme choice: complete presentation/session pins and migrations; exact picture selection; cross-mode painters and Studio use; two reviewed full collections; Retry/restore/export/import/offline journeys; source gates and public release. Catalogue coverage and decoded snapshots are necessary evidence, not proof of art quality, playability or production completeness.

Focused tests use real compiler output and local Git sprite bytes with modeled image decoding. They cover reference mismatch despite matching bytes, missing roles, explicit unavailable alternatives, required-slot ownership, live-host protection, late decode cancellation, resource transfer and reentrant observers. The combined suite also reruns catalogue, Legacy/Team/Journey adapters and existing loader regressions. No real-browser, physical-input, full offline or deployment claim is made.
