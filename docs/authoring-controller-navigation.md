# Authoring input coverage

The authoring hosts use the same controller router, focus navigation and field editor as the player menus. Arrow keys/Tab move between controls; Enter/Space activates native controls. A controller uses the D-pad or left stick, South to choose/edit, East to return, and Menu to open section navigation where available. The existing Enemy, Picture and Video workshops retain their deliberate controller join step. Other authoring pages automatically adopt the first available controller.

Text, search, multiline, number and color fields use the shared controller field editor. It supplies English/Ukrainian/symbol keyboards, caret/selection, newline, undo/redo and explicit Done/Cancel. Native keyboard typing remains native. Selects, ranges, checkboxes and disclosure controls retain their established operations. Shared editor commands use Departure Mono and the same pixel icon family as the game menus; descriptions use Exo 2. Sections includes a Page actions shortcut for save/export controls above long inventories.

## Input ownership and canvas commands

`game/ui/authoring-input-host.mjs` mounts once per document. Its Confirm coordinator captures native and controller activation against the same target, commits on release, and drains compatibility events across menu changes. It uses the accepted shared lifecycle rather than a second device sampler. It does not sample controllers while a child iframe has focus, the document is hidden, or the document lacks focus. Blur clears routing/edit state; disposal cancels the animation frame, observers and listeners. Existing native workshop hosts integrate the same source picker into their own active modal scope instead of mounting another input host.

`game/ui/authoring-editors.mjs` registers custom surfaces with the shared navigator. Direction/Confirm/Back call domain adapters rather than synthesizing keyboard events. The grid adapter bounds the cursor to the current map and displays a cell outline. Confirm applies one operation. Back cancels an unfinished shape/selection anchor before leaving the editor. Sprite tools keep their existing keyboard handling and pixel-history owner. Playground and Content Studio share their existing paint/form validators with keyboard/controller input.

Loading a preview preserves the editor’s focus until Enter preview is chosen. An iframe receives a real Return to editor button inside its active menu or dialog. It moves as the child opens and closes menus. During active gameplay, pause using the game's normal control to reach the return action. The parent does not issue gameplay commands. Existing authenticated preview-transfer behavior remains available.

## Source boundary

Choose a source is available alongside native file inputs and from controller activation of those inputs. The dialog filters by the input's accepted types and offers bundled examples, recent files opened in this document, and same-origin image/video/audio already displayed by the editor. Selected bytes pass through the original input `change` boundary; the receiving editor still validates, reviews and commits them. Closing the chooser aborts an outstanding read and fences late results.

Recent source memory is bounded to 12 files and 32 MiB total for the page session. Individual in-app source reads are limited to 32 MiB. Large or newly located device files use the existing native file picker. The browser/OS owns that picker and download/save dialogs; page Gamepad API code cannot guarantee controller-only operation there. This boundary is explained in the dialog. Built-in templates, blank sprites and bundled sources support useful creation without that boundary. Binary backup formats are offered only when their matching extension is accepted; arbitrary JSON is not substituted across incompatible tool schemas.

The independently developed Demo recording tool is not part of this integration; an optional navigation adapter must travel with that tool’s own delivery.
