## Actual gap and bounded scope

The [navigation adapter](../game/ui/controller-navigation.mjs) enumerates buttons, links, selects, inputs, textareas and summaries. It does not include static regions. The existing `.overlay-message` already has `role="region"`, `tabindex="0"` and `data-game-reading`, allowing native keyboard reading, but controller focus skips it. Its content contains compact requirements and results. The full authored description is separately rendered into `#mission-brief-title`, `#mission-brief-copy` and `#mission-brief-facts`; reading only the overlay would leave long authored guidance inaccessible to the controller.

Register exactly two surfaces initially:

| Entry                  | Reading surface                                                                                                                                      | Availability                                                                                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Read details**       | Give the existing `.overlay-message` the stable ID `overlay-reading`; retain its title, requirements/result, medal and optional seal text.           | Visible ready, paused, won, lost or campaign-complete overlay containing text. Hidden with the overlay during flight, celebration and clean-picture viewing. |
| **Read mission brief** | Wrap the existing full briefing paragraphs and optional seal explanation in `#mission-brief-reading`, a named, focusable `data-game-reading` region. | Inside the opened Mission brief. Entry during a running flight first invokes the existing forced pause.                                                      |

Use the existing content nodes and safe `textContent`; do not copy results into a second persistent document, truncate the full brief, or treat arbitrary pack HTML/selectors as reader registrations. Keep native pointer, touch, keyboard and assistive reading available. Help/settings/collection long-form readers, Replay Theater and couch menu ownership are later surfaces, not acceptance claims for this increment.

## Player interaction

1. Confirm **Read details** or **Read mission brief**. Entry never starts an unstarted mission. A running mission pauses before reading begins. Show a local visible reading indicator, focus/outline the named region, and leave the simulation stopped.
2. Configured menu Up/Down scroll only that region vertically. A discrete event moves `min(48, max(1, floor(clientHeight / 2)))` CSS pixels, clamped to `0…max(0, scrollHeight - clientHeight)`. Use instant scrolling, independent of animation preferences. Keep the router's existing 350 ms initial repeat delay and 120 ms repeat interval; no new scrolling timer or acceleration.
3. Left/Right do not navigate another control or move the page horizontally while reading. Briefly identify Up/Down as the available directions. At the start/end, stay there and report the boundary once rather than wrapping or repeating announcements indefinitely.
4. Remapped Back, Confirm or Menu ends reading and consumes that gesture. None also clicks Start/Next/Retry, dismisses a parent dialog, skips a finale, or calls Resume. Restore the entry button when it still belongs to the current visible scope. A fresh, neutral-gated gesture may then activate Resume or another action.
5. Provide a visible **Done reading** button beside the entry control, outside the scrolling text, and a local prompt using current mapped labels: “Up/Down scroll · [Confirm] or [Back] returns.” Menu also returns but need not lengthen the compact prompt. Keep the Done control's layout stable and disabled when inactive: a pointerdown that relinquishes controller mode must not remove the pressed target or make a following click re-enter reading/activate a newly exposed action. The click handler only ends reading; it never toggles it back on.

Do not require overflow to enter: a short region says that all text is visible and has the same immediate exit. Preserve its scroll position when exiting/re-entering unchanged text. Content replacement starts a later entry at the top. Resize alone clamps the current scroll position without cancelling or replaying an input.

## Smallest adapter/host contract

Extend `attachControllerNavigation` without changing existing defaults:

```js
attachControllerNavigation({
  // Existing options stay unchanged.
  onReadingChange: (state) => {}, // null or owned { regionId, label }
});

navigation.beginReading({ region, origin, label }); // boolean accepted
navigation.endReading({ restoreFocus: true }); // boolean was active
navigation.readingState(); // null or owned { regionId, label }
```

The host binds the two real buttons to these methods through normal DOM handlers. No raw device polling, external selector input, new content fields or global document scan is needed. The adapter owns transient references to the region/origin, base scope/root, and its initial text signature. Require a connected, visible, non-inert named region with `data-game-reading`, a usable viewport and an allowed origin in the same root. Reject entry in `flight`, destroyed state or a scope whose root excludes either element. Beginning reading cancels an uncommitted select/range edit; it cannot commit it.

Process active reading **before** ordinary `ensureFocus()` and `move()` in `handle()`. Otherwise the current controls-only logic would immediately move focus away from the static region. `sync()` must recognize the active region as its permitted focused target. Do not add every static region to ordinary sequential menu traversal. On scope/root/content/target invalidation, cancel and return the existing invalidation signal so the same command cannot activate the newly chosen fallback.

Keep `controllerScope()` as the existing base menu/flight scope for both navigation and the router. Entry/exit explicitly clears input, so a second router scope scheme is unnecessary. If desired, append a short reading suffix only to the lab's **reported** scope; it remains presentation text, not an additional protocol field or command context. The local prompt and region focus must identify reading even if that suffix is omitted.

One host integration detail is essential: `clearInput()` currently calls `controllerNavigation.clear()`. An unconditional call from `onReadingChange` would cancel the reading state just created. Add a narrow optional `clearInput({ preserveNavigation: true })` path (default false), used only for reader transitions. It still clears pending ability/pickup/switch, controller frame, physical edges/repeats/stick history, input adapter holds, accumulator and recorded released inputs. It only skips the navigation reset. All existing lifecycle callers retain the default full clear. Emit the callback after the internal reading state is updated; avoid recursive callbacks when `clear()` is already inactive.

Successful entry and exit require the existing router's neutral sample across both configured contexts before another action. Do not validate bindings every frame or duplicate their mapping. Update the reading prompt from the current `getControlLabels()` so remapped Back/Confirm remain accurate. Reading is not a new preference and requires no save/library migration.

## Lifecycle and focus rules

| Trigger                                                                                | Required outcome                                                                                                                                                                      |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Explicit Back/Confirm/Menu/Done                                                        | End once, return to valid origin, gate held inputs; preserve paused/ready/terminal state.                                                                                             |
| New modal, campaign/mission/class/policy selection, prepare/retry, restore/import/Undo | Existing clear/scope change cancels without committing or restoring focus into stale content. The new scope owns focus.                                                               |
| Region or origin removed, hidden, disabled/inert; closed Mission brief; replaced text  | Cancel safely. Consume any command on that invalidation tick. Use current host fallback only when appropriate; never activate it.                                                     |
| Native focus moves outside the region                                                  | Cancel without stealing the new focus. A late optional-seal update is content replacement, not permission to restart the run.                                                         |
| Pointer or keyboard input                                                              | Relinquish controller mode, retain native focus/scroll semantics, clear controller held/repeat state. Do not prevent native Arrow/Page/Home/End scrolling inside `data-game-reading`. |
| Blur, hidden page, disconnect, pagehide/BFCache, destruction                           | Existing full input/lifecycle clear cancels reading. No automatic return to reading or flight on refocus/reconnect. Preserve current writer/session-only protections.                 |

For a pointer activating a reader entry, the pointerdown occurs before its normal click: ordinary relinquish may run first, then the click may deliberately start reading. For Done, the click is end-only and remains harmless if pointerdown already cancelled. Test this event ordering rather than relying on synthetic `.click()` alone.

## Layout and accessibility

Keep both entry and exit buttons at least 44 CSS pixels high with visible focus. Their toolbar is separate from the existing ready overlay's non-wrapping primary action row, avoiding another Start-button squeeze. Put the local hint outside the region and its accessible label; scrolling must not rewrite the region name. Use a stable name through `aria-label`/`aria-labelledby`, `aria-controls` on entry/exit, and a polite status for entry/exit and first arrival at an edge. Do not announce every repeat or mark the entire briefing live.

Reading text wraps with `overflow-wrap:anywhere`, `white-space:pre-wrap` where authored line breaks matter, and `overflow-x:hidden`; required content must fit its text width, not be clipped to hide a layout defect. Give the full-brief wrapper its own bounded vertical scroll area. Preserve the arena's current readable minimum size. Do not introduce another height-reserve subtraction that collapses the board near 500/501 px. Keep the reader toolbar visible while its text scrolls; when the containing page needs vertical scrolling, focus placement must bring this reader unit into view. Verify actual region, toolbar and ancestor geometry at short heights instead of assuming `scrollIntoView()` makes everything visible.

The native keyboard protection already exists in [input.mjs](../game/ui/input.mjs) for `data-game-reading`; the new full-brief wrapper must carry that marker too. Keep its native tabindex and semantics. This is controller navigation, not speech narration or a replacement for screen-reader behavior.

## Research basis and limits

The [Microsoft UI navigation guidance](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112) supports consistent mapped operations, visible ways back, and text reflow that avoids two-direction scrolling. The named-region, stable-return-focus and visible-exit choices also follow the reasoning in [WAI's modal-dialog guidance](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), though this proposal reuses existing inline regions and does **not** declare them modal dialogs. [MDN's element scrolling API](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollTo) documents explicit element coordinates and instant behavior; use the bounded synchronous scroll position without depending on newer optional return-value behavior. These primary pages were read for this plan; no new media, physical-device session or accessibility conformance test was performed.
