# Reproducible presentation output with retained originals

The Field Kit generator now prepares compiled output through `preparePresentationOutput`. The helper owns input bytes before awaiting work, authenticates fresh compiler output, formats only the new current JSON/CSS, rebuilds its ownership inventory, retains the previous authenticated manifests and selected assets, and finally formats only ownership metadata. Hash-named archived runtime bytes are never formatted. Passing an already archived tree as fresh compiler output fails explicitly.

Both generator modes use this same preparation: `--write` adopts the prepared map through the existing staged writer, while `--check` compares it without rewriting anything. The previous map comes from `readPresentation` and errors for an incomplete, edited, linked or unmanaged tree; only a genuinely absent output root can start empty. The original theme ledger, current selection, artwork quality and release version are not changed by this code refactor.

The preparation step does not add new Team roles, approve their art, update recipe approvals or choose a successor theme revision. Those production changes remain a separate coordinated adoption. After adoption, derive exact fresh picture/theme associations from the actual generated output. Keep historical associations immutable and verify both retained build membership and real offline/public journeys.

Maintenance prompt: format fresh compiler output before preserving history, retain original hashes byte-for-byte, use the same preparation for write/check, and keep the ownership manifest consistent. Prove unchanged current output is reproducible, old archives survive later generations, formatter options cannot rewrite originals, mutable inputs cannot race async formatting, and damaged output fails visibly. Never reuse a provisional fixture identity as an approved production identity.

Repository-wide `npm run format` and `format:check` also exclude `game/presentation/compiled/runtime.*.json` through `.prettierignore`. The current `runtime.json` and other generated metadata remain formatted normally. This exclusion protects original pins when formatter settings change; it does not exempt archives from compiler ownership, hash/dependency validation or release checks. The formatting regression uses a small JSON sentinel solely to test the real formatter command, not to claim that sentinel is a valid runtime manifest.
