# Bounded live endurance diagnostics

The authoring endurance page previously rebuilt the complete raw report and replaced its formatted JSON every second, even with its details closed. That copies retained lifecycle traces, observation events, recent samples and minute samples into an increasingly large text node during a measured flight. This change limits the live display to scalar progress facts and defers the complete report to finish or an explicit export. All existing raw sample rings, minute records, peaks, route evidence and lifecycle events remain owned by the same runner and retain their existing bounds.

A live export is explicitly provisional and `accepted: false`; the current run is exported, rather than a previous completed segment. Finishing still applies the exact real-time, coverage and disposal acceptance rules. A new segment preserves the previous completed summary as history and clears its old live result. The 250 ms maximum gap, focus/visibility policy, wall clock, fixed physics steps, collision/resource limits and rendering workload are unchanged.

The full report now exposes count/mean/max synchronous CPU submissions for frame checks, sample collection and the bounded live display. These do not measure asynchronous observer callbacks, layout, garbage collection attribution, GPU completion or final/export serialization. They can compare a future fresh run against retained evidence; they do not establish that report overhead caused any earlier frame gap.

`verify-endurance-report-display.mjs` verifies bounded two-hour-equivalent display updates, retained-data independence, CPU-counter snapshots and failure propagation, and confirms that the actual unchanged clock rejects a 257.1 ms interval. The accelerated display loop is not elapsed endurance. Existing clock, observation and lifecycle checks remain required. Native smoke/full-report export and any new actual two-hour segment are separate verification gates. Every old negative run, fixture and package stays preserved; this is authoring-only and adds no production module, simulation capability or budget.
