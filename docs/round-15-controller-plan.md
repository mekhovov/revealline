## Primary-source guidance checked this round

These are observed source recommendations/API facts. The implementation choices in the following sections are our proposals, not a claim of Xbox certification.

| Source                                                                                                                            | Relevant fact                                                                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Xbox Accessibility Guideline 107: Input](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107) | Recommends digital alternatives, controls remapping, updated prompts and alternatives to prolonged holds or simultaneous presses. Navigation should not require holding Confirm while adjusting a value. |
| [XAG 112: UI navigation](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/112)                  | Recommends consistent navigation and Back routes, meaningful focus order and navigation that follows layout changes. Linear menus may wrap; multidirectional grids do not need to.                       |
| [XAG 113: UI focus handling](https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/113)              | Recommends a conspicuous, visible focus indicator and keeping interaction inside an open modal. Focus should not land on hidden or offscreen controls.                                                   |
| [MDN: Using the Gamepad API](https://developer.mozilla.org/en-US/docs/Web/API/Gamepad_API/Using_the_Gamepad_API)                  | Exposure can require interaction with a controller on a visible/focused page. Read fresh state in the animation loop; track connection index and mapping. Indices can be reused after disconnect.        |
| [MDN: getGamepads](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/getGamepads)                                        | Returned slots may be null so surviving pads keep their indices. The call can throw `SecurityError` under Permissions Policy.                                                                            |
| [MDN: User activation](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/User_activation)                            | Activation requires specified trusted keyboard/pointer/touch events. Transient activation gates APIs including native pickers, fullscreen and sharing; WebAudio can depend on sticky activation.         |

The last point creates a concrete host boundary: polling a gamepad and calling a button's `.click()` does not manufacture trusted activation. Use a DOM choice editor for ordinary selects, keep gameplay operable when audio remains suspended, and report the actual result of sound/export/picker requests. Preserve normal keyboard/touch activation. Do not weaken Electron download restrictions or manufacture synthetic trusted events to hide the limitation. A host may offer its own supported controller/OS interaction, but that must be separately verified. [Current host adapter](../game/platform.mjs), [native compatibility review](native-compatibility.md)

## Proposed input architecture

Read controller state once per animation frame through a shared sampler. Its output contains finite normalized values, connection identity, held controls and press/release edges. A scope router sends each sample to **one** destination: active flight, ready/paused UI, modal, control capture, celebration/results, or replay transport. UI activity continues while the simulation is paused. Input mapping produces the existing cardinal direction/boost/action/pickup/switch commands; it does not modify terrain, speed, collision geometry or fill rules.

Every scope transition cancels queued UI activation, resets repeat timers, clears held flight commands and records the existing release boundary through `clearInput()`. Require controls used for entry to return neutral before accepting them in the destination. Process a UI activation against the scope and element captured for that press; if either changed or the element became disabled/disconnected before release, cancel it. Never run two polling loops that independently interpret the same A press.

Choose the solo pad using a deliberate button press after a neutral sample, not the first array entry. Track index plus the observed connection generation; a changed device descriptor or disconnect event invalidates the assignment. Do not save a runtime index as a permanent device identifier. Treat API denial, disappearing state, blur and hidden-page transitions as loss of active control: clear, pause, explain, then require fresh confirmation to resume. Reconnection never launches a cut automatically.

Proposed default additions, keeping existing flight buttons:

| Context | Control                 | Action                                                            |
| ------- | ----------------------- | ----------------------------------------------------------------- |
| Flight  | D-pad or selected stick | Cardinal movement; release stops                                  |
| Flight  | A / south               | Ability                                                           |
| Flight  | X / west                | Supply pickup                                                     |
| Flight  | Right shoulder          | Boost, with optional toggle                                       |
| Flight  | Y / north               | Open Hangar, pause and choose craft                               |
| Flight  | B / east                | Stop and clear movement/boost                                     |
| Flight  | Menu / index 9          | Pause                                                             |
| UI      | D-pad or selected stick | Move focus; left/right adjust only in explicit edit mode          |
| UI      | A / south               | Activate focused control or commit the edited value               |
| UI      | B / east                | Cancel editing, then scoped Back; no implicit restart or discard  |
| Pause   | Menu                    | Resume only this paused flight; blocked during another modal/task |

Button labels are presentation: offer Xbox, PlayStation and neutral positional labels, with neutral labels as the safe fallback. Changing glyphs must not change mappings. Keep visible Confirm/Back prompts in the same place across menus and show the configured gameplay commands in help/HUD. Do not guess universal glyph compatibility from a controller's name.

## Complete session and focus behavior

**Entry:** after assets/profile initialization, focus the recommended Start/Continue action without activating it. A visible saved-flight action remains separately selectable and still verifies through the existing restoration pipeline. First pad input should select the device; release, then Confirm performs the focused action. Offer Settings and Flight deck from this screen. An unsupported mapping gets a readable status and a tested setup path rather than being silently called “Keyboard / touch.”

**Flight deck and menus:** navigate the actual enabled DOM controls using a scoped adapter. Skip `[hidden]`, hidden ancestors, disabled controls and inert subtrees. Lists follow visual/DOM order; gallery and mission grids use explicit row/column navigation and recompute after responsive reflow. Scroll the chosen control into its nearest scroll container, keeping its focus ring visible. Provide a linear navigation option for users who prefer it. Pointer and keyboard focus remain authoritative when used; a connected idle stick must not pull focus back every frame.

**Selects and sliders:** Confirm enters a clearly labeled editor with the old value retained. D-pad steps through enabled options or the slider's declared step/range; Confirm commits once and invokes the existing input/change behavior; Back restores the prior value. Starting class, world and campaign changes may call `prepare()`, so browsing an option must not restart the attempt. Checkboxes and Mission brief disclosures toggle once. Numeric/text inputs need a controller-accessible bounded keypad/keyboard if claimed supported; gallery campaign filters and pagination must work without mandatory text search. Never require the OS's native select popup for basic campaign/class selection.

**Pause and hangar:** pressing Menu focuses Resume, with Settings, Flight deck, Collection and Back available. Hangar selects the actual active craft, preserves the existing starting-class distinction, and uses the existing switch request on confirmation. Cancelling leaves the flight paused. Applying a switch keeps current core rejection feedback, ammunition and cooldown semantics; menu navigation cannot refill equipment. Resume consumes its Confirm gesture and does not turn it into an ability or buffered direction.

**Finish and collection:** the existing celebration can be skipped with an explicit focused action; the same press must not also advance the next mission. Results expose picture, retry and continuation. Completing the final map enters the genuine completed-campaign overview. Opening a gallery picture remembers campaign filter, page and logical picture key; Back returns there. If an import/Undo removed that key, focus the nearest remaining item or an empty-state Back action. Picture animation, audio and saving remain separate from navigation.

**Long operations:** display progress and a focusable cancellation action only when the operation allows it. During irreversible backup adoption, retain a visible busy status and ignore Back according to the coordinator contract. Do not move focus to background controls while a modal is busy. After success/error/Undo, resolve focus against the new DOM; a stale node must never receive a queued Confirm.

**Couch and Replay Theater:** one joined controller owns setup/menu navigation; both players retain their assigned slots in flight, and either can pause. Ownership transfer must be explicit. Replay Theater uses the same control semantics for buttons, speed and seeking; seek cancels obsolete work and returns paused. Browser file dialogs, JSON typing and OS export sheets are separately described host workflows, not a prerequisite for playing an installed campaign or watching bundled replays.

## Remapping and dead-zone policy

Add a bounded, versioned controller preference alongside keyboard bindings, with defaults when older backups omit it. Validate the whole candidate before applying; reject dangerous keys, duplicate conflicting bindings, non-finite thresholds, invalid axis indices and unsupported schema versions. Preserve the profile writer/backup locks and session-only warning behavior. Old frozen releases need not understand a newly extended profile: retain explicit forward copy/full-backup transfer rather than overwriting their storage.

Map gameplay actions independently from stable menu navigation so changing Ability cannot trap the player outside Settings. Capture is explicit, cancellable with a persistent Back button, waits for neutral, and does not save the activation that opened capture. Include left/right stick selection, per-axis inversion, D-pad-only movement, and a live neutral/dead-zone preview. Defer nonstandard-device mapping claims until a guided raw-button setup and a physical test exist; no WebHID requirement is needed for the standard-pad path.

Initial tuning proposal: retain the current **0.35** activation threshold, expose **0.10–0.60**, and use a lower release threshold (activation minus **0.08**, bounded at **0.02**) to reduce chatter. Prefer the current cardinal direction around diagonal ties, then a documented deterministic tie-break. These are proposed UI/input constants, not hardware measurements. D-pad remains an immediate digital alternative. Optional boost-toggle/latched steering must always have a single-press Stop and clear on pause, disconnect, remap and focus loss.

Menu repeats should use elapsed time, not frame count: proposed first repeat **350 ms**, subsequent repeats **120 ms**, at most one step per rendered frame, with no catch-up burst after a stall. Confirm, Back, tabs, actions and destructive operations never repeat. Keep movement itself immediate at the existing fixed simulation step. Replays record the resulting normalized commands, so dead zones, glyphs and binding choices need not become new physics or score-board identities; the existing steering policy and rules identity still apply.

## First implementation slice and priorities

**P0 — one installed solo campaign, end to end.** Implement the shared standard-pad sampler, stable solo assignment and explicit scope router first. Add visible focus/Confirm/Back and an edit/commit adapter for the existing campaign/class/steering selects. Wire ready, saved-flight, pause, hangar, results, celebration skip and collection return through current handlers. Fix the two-pad replacement pause before adding more mappings. Exercise one actual base campaign completion and a Homeward hangar route in both turn modes. Keep existing defaults and storage schema for this slice; expose no dead-zone or remapping UI before its persistence contract exists.

Acceptance for that slice is rows 1–8, 11, 13–16 above, plus all existing regressions. A successful simulated journey means the UI path is implemented; physical and browser-activation outcomes remain separately reported. This is the highest-value first deliverable, not yet the full controller accessibility claim.

**P1 — configuration and companion pages.** Add the validated preference migration, remapping, calibration/toggle settings, couch menu ownership and Replay Theater navigation. Complete the remaining matrix and physical target-device sessions. Defer haptics, automatic brand detection and arbitrary nonstandard hardware support; they are not needed to close the current start/menu/hangar/gallery gaps.
