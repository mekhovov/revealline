# Published presentation host

`game/presentation/host.mjs` reads the code-owned `./compiled/runtime.json` beside itself. That file is the compiler's `revealline-compiled-presentation.v1` resolved snapshot, not a full editable `.rltheme` document. The host validates its exact fields, references, bounded asset records, tokens and hash/MIME-derived relative asset paths before requesting any asset. Redirects, other origins, query strings, traversal, truncated bodies, oversized responses, incorrect hashes and disagreeing decoded dimensions fail the candidate load.

The loader permits HTTP(S), the registered desktop `revealline://app` origin and the registered iOS `capacitor://localhost` origin. Native URL ownership compares both protocol and host because custom schemes may expose a null `URL.origin`. Files and arbitrary custom schemes remain unavailable.

Visible original images and their cropped frames share a 16-megapixel decoded allocation budget, checked before their bytes are requested. This supplements the compressed manifest and asset byte bounds. Cancelling a pending codec releases already prepared images immediately; late decoded objects are released when their codec returns.

The host exposes `load({signal})`, `current()`, `apply(element)`, `readPicture(slotId,{snapshot,signal})` and `close()`. Construction does no IO. Loading prepares one complete candidate, including real image and font decoding, before replacing the accepted snapshot. Failure retains the previous snapshot. A new load cancels an older request; late codec results remain owned and are disposed. Close cancels requests, restores owned CSS values and decorative attributes, unregisters its font faces and releases its bitmaps and object URLs. No Studio database, player database, campaign, profile, replay or save is read or written by this loader.

The accepted snapshot provides `image(slotId)` with the cropped image and normalized frame geometry, `cssImage(slotId)`, approved canvas palette and font families, and its immutable source identity. Interface image variables use `--fk-asset-<slot-with-hyphens>`; nine-slice variants add `--fk-slice-...` and `--fk-slice-width-...`. Only compiler-bound visual families and fonts load. Audio retains the existing soundtrack transport. Picture slots are excluded from generic visual loading.

The player app applies CSS to `document.documentElement`, allowing the existing body `data-text-size="large"` preference to override inherited theme text sizes. `BoardPainter.setPresentation(snapshot)` adopts the FPV actor, terrain and pickup slots during rendering. Current registered class body IDs select compact art on phone/microtile views and detailed art otherwise. Explicit manual body and role overrides stay first, including their existing rigs. Other world canvases retain their own artwork. Source presets and physics sizes are unchanged. Custom motor anchors use the existing procedural renderer; source transparency and normalized pivots are honored without moving contact rings. Canvas status text receives the published numeric/UI font families.

The generic renderer never substitutes reveal pictures. Its existing chain remains: the flight media host's exact decoded image and fit, the authored/manual background override, then the original procedural picture. `release-pictures.mjs` maps only the code-owned exact FPV owners in `CURRENT_PICTURES` to compiled picture bindings. The original is requested only when a new attempt or fresh chapter installation needs it. It must be a full PNG/JPEG frame within the existing 4 MiB and 1920 × 1080 still-media limits; its presentation uses `contain` and `nearest`. A hash-derived immutable asset and owner/hash-derived presentation are appended through the existing fully verified still-media preparation and generation CAS. All retained originals and archived owners remain in that ledger, so existing collection, media export/import and backup flows retain the new picture after the release changes or becomes unavailable.

For ordinary new attempts, explicit assignments win. Default selection appends any missing original history without publishing an assignment, then the existing flight resolver captures an exact pin. Supplied pins, explicit legacy choices, old unpinned restored attempts and training bypass default selection. Existing first-earned collection and replay behavior remains unchanged. The app's commit guard requires its current writer and chapter/backup authority; cancellation before commit leaves no new pin, while cancellation after durable commit can leave harmless unused immutable history.

The fixed `scene.reveal.legacy` and `scene.reveal.wide` bindings provide shared FPV originals when an exact code-owned owner has no file binding. Their complete image dimensions must match that owner's declared 768 × 576 or 1152 × 576 dimensions exactly. An exact owner image always wins; other dimensions and other worlds never select a generic image. These shared defaults use the same durable new-attempt and fresh-install pin transactions and retain all manual, saved and earned priority rules.

Imported pack backgrounds keep manual priority too. `current-picture-baselines.mjs` contains only the56 registered FPV source fingerprints, generated from the trusted source inventory by `node scripts/generate-picture-baselines.mjs --write` and checked with `--check`. An embedded background must retain its exact MIME, size, dimensions, hash and fitting mode before a new release default can be selected. A changed or removed embedded original remains the pack's chosen artwork. External editions have no embedded image and follow their exact installed assignments.

Mission thumbnails use `acquireEarnedPicture`, the same exact receipt resolver as Collection. They use the first-earned seed and pin, preserve receipt-free legacy rows, and show unavailable when that original cannot be read. They never substitute today's assignment or a newly published release picture. Changing the mission/world list or closing the host cancels pending acquisition and releases late images; updating a thumbnail preserves its original focusable mission button.

A fresh successful external chapter install may assign its newly installed exact FPV owners to release originals after the recoverable source installation has completed. That separate atomic update requires the install result's exact media generation and every unchanged authored assignment. The installed source originals remain retained. Recovery, existing installations and imported assignments are never inferred to be fresh. If the extra preparation fails or is interrupted, the installed source chapter remains playable with its original artwork; there is no retroactive migration or new install-journal format.

`presentation-host.test.mjs` exercises actual compiler output with injected image/font boundaries, strict path/byte rejection, atomic failure, cancellation and resource ownership. `presentation-renderer.test.mjs` checks actual drawing commands, declared pivots, independent override priority and unchanged authoritative checkpoints. `release-pictures.test.mjs` exercises durable pin capture, exact original transfer, archived-owner retention, manual/legacy priority, failed bytes, cancellation and CAS. The fresh-install case in `external-chapter-app.test.mjs` drives the actual native source screen through installation and choosing its release picture while retaining every authored original. These source tests use explicit codec fixtures; browser decode, visual review and deployed release verification remain separate release checks.
