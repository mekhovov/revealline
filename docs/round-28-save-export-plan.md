## Confirmed problem and existing boundaries

Round26 browser testing reproduced normal Ready showing a saved flight that could be loaded, while **Export attempt** reported “Start an unfinished campaign flight to save it.” Complete backup included the stored checkpoint correctly. This predates First Flight and is recorded in [its guide](first-flight.md) and the [Round27 candidate](round-27-candidate-backlog.md).

The current [library panel](../game/ui/library-panel.mjs) calls `api.suspend()` unconditionally for `#export-session`. The [app](../game/app.mjs) callback calls `pause(true)` and `snapshotAttempt()`, which requires a started, unfinished, nonpractice run with a recorder. `savedAttempt()` separately parses the stored slot for display/load, swallowing missing, malformed and unavailable storage into null. It must not become the validation authority for exporting stored data.

`pause(true)` can autosave a current flight. Opening Library already calls it before the Export button is used. Preserve that existing live-flight behavior in this bounded change; do not promise the stored slot was unchanged before opening Library from a running game. The new **stored-source branch** is read-only. `persistAttempt()` returning a session is not proof of durable saving, and exporting must not depend on its success.

## Small helper and host contract

Add a browser-independent `game/attempt-export.mjs` with this proposed API:

```js
export async function prepareAttemptExport(candidate, options = {}) {}
// options: { campaign?, signal?, onProgress? }
// Promise<{ session, context: 'installed-campaign' | 'replay-only' }>
```

The helper receives only a candidate snapshot and optional trusted campaign context; it never reads/writes storage, calls a download, changes UI, adopts a restored run or grants rewards. Validate its finite options before extracting them; `signal` and `onProgress` are host-supplied capabilities, not portable JSON fields. Use the existing [session](../game/sessions.mjs) and [replay](../game/replay.mjs) validators:

1. `snapshotSession(candidate)` makes an owned, bounded `xonix-session.v1` envelope before awaiting. Reject malformed metadata, accessors/unsupported object values, oversize content and unsupported version pairs through existing boundaries. Do not hand-roll a weaker replay check.
2. When the installed campaign is available, validate its owned snapshot and derive its real `campaignKey`. Call `restoreSession` with that exact context and cancellation/progress options, but **discard the returned run/recorder**. The exported value is the original owned session envelope, never a resuspended reconstructed run. Thus `savedAt`, run ID, input-release markers and replay checkpoint remain identical.
3. When no exact matching campaign context is available, allow a rescue file after `verifyReplayAsync` matches the complete self-contained recording/checkpoint and its actual state is `running` or `respawning`. This covers an absent pack or historical rules revision, and a session-only tab whose stored content could not be adopted; it does not declare that content absent from disk. Mark this result `replay-only`: envelope and replay are verified, but correspondence to an installed campaign is not. Loading still requires the exact matching campaign/roster. Do not assert that an arbitrary envelope campaign key is established by the replay alone.
4. Reject a replay mismatch or actual terminal state regardless of its claimed summary. Check cancellation after the verifier's final callback as well as during yielding. Do not request mastery observation or create a mastery certificate for export.

Add an app-owned `prepareAttemptFile({signal,onProgress})` callback for the panel. It selects the source from the table and returns `{session, source: 'current'|'stored', context, assertCurrent}` after its stale-state checks. The final function is a host capability, never a field in the portable file; the panel calls it synchronously immediately before publishing JSON and requesting a download. A finite `createAttemptFilePreparer` in `game/attempt-file.mjs` owns the source selection, cancellation and adapter checks so its real behavior can be tested without starting Phaser. The app supplies current-state reads, its existing live snapshot, exact campaign resolution, raw slot/backup-marker/journal reads and a short lock callback. It exposes `source()`, `prepare()` and `invalidate()`; it is specific to this one export action.

For stored export, read the **raw** `sessionKey` value directly with explicit absent/read-error handling. Check its UTF-8 size against the existing **2 MiB local-slot limit** before parsing; the helper still applies the larger portable session/replay limits. Preserve the original raw slot bytes. Do not normalize/write them back. For current export, use the existing snapshot path and portable limit, allowing a complete recording too large for local storage to be exported. Do not impose the 2 MiB local limit on file exports.

Resolve campaign context from the actual normalized runtime catalog by the session's full key, with the existing finite dated-challenge resolver and exact key comparison. A currently selected different campaign must not be used instead. No exact available context uses the explicit replay-only path; malformed available rules or a same-key mismatch are errors, not an excuse to downgrade validation silently. The lightweight shipped pack-navigation catalog contains names and IDs, not the actual rules/roster, and is never sufficient verification context.

## Staleness, cancellation and persistence

Capture the operation generation, source selection, run/recorder references and run ID for current export, or raw slot bytes for stored export. Own the selected campaign snapshot. Before publishing JSON or invoking download, reject cancelled, closed/destroyed, newly selected/started/restored, profile-replaced or content-changed operations. Current export must also remain paused with an authoritative checkpoint and exported recording equal to the selected post-release snapshot: matching object references alone cannot detect a resume/re-pause or new release marker during an await. Record the snapshot once; final checks use read-only checkpoint/recording projection, not another `suspendSession()` or changed `savedAt`. For a stored source, reread and require the raw slot to match the initial bytes; never switch to a newer checkpoint halfway through preparation. Errors preserve any previously prepared copy-area content.

Reuse the app's backup-operation boundary: do not prepare a stored file from an active/interrupted backup transaction. Use the existing short `${libraryKey}.backup-lock` Web Lock when available for snapshot/recheck, and inspect the same-named durable local-storage marker plus the IndexedDB journal without writing either. The short operation lock is distinct from the long-lived `${libraryKey}.writer` lease: a read-only session-only tab can use the former without claiming the latter. Release the operation lock during replay verification and before any native/browser download UI. If Web Locks are unavailable, retain explicit marker/journal and raw-slot rechecks without claiming a cross-store atomic snapshot. An unreadable player library alone must not be rewritten or “repaired” as part of exporting an otherwise valid independent session. Report an unavailable transaction-state read rather than pretending it was checked; never call startup recovery as part of export.

Add one finite **Cancel export** control only while verification is pending. Keep it enabled when the panel disables competing controls; avoid applying the current blanket `task()` disabled list to Cancel itself. Escape/remapped Back during this specific operation cancels preparation without closing into flight or resuming it; other protected Library operations retain their current cancellation behavior. Clear the operation on pagehide, close, profile replacement, course entry or a superseding attempt. Late completion cannot fill the copy area or request a download. Repeated activation while busy starts only one preparation.

Do not broaden the read-only guarantee: current export keeps ordinary live pause/autosave behavior, including earlier Library-entry autosave and lifecycle hooks. The selected owned snapshot remains fixed even if a later ordinary pause updates local storage. Stored-source Ready/results have no live attempt to autosave, and this branch never calls a mutating snapshot or adopts verification state. A future change making _all_ export paths free of ordinary autosave would require a separate reviewed lifecycle policy.

The short lock covers capture and final journal/raw-slot reads; it is released during replay verification and before the download adapter. The final synchronous `assertCurrent()` rechecks cancellation, host identities and the current replay or stored raw slot/marker after the awaiting caller resumes. It does not claim a cross-store transaction beyond the cooperative lock. An application transition invalidates the preparation even when a run is resumed and paused without advancing a tick. The [Web Locks draft](https://www.w3.org/TR/web-locks/) specifies that the request promise settles after release; the [HTML storage standard](https://html.spec.whatwg.org/multipage/webstorage.html#the-localstorage-attribute) allows storage access to fail. These sources were checked on 12 September 2026; blocked or unreadable transaction-state checks must fail explicitly, without recovery writes.

After verification, populate the copy area before calling the existing `downloadJSON`/`exportJSONFile` adapter. Suggested status: “Saved checkpoint prepared: [map], [saved date]. [adapter message]” or “Current unfinished flight prepared. [adapter message]”. Append “The matching campaign and rules revision must be available before this file can be loaded here” for replay-only rescue. JSON whitespace may differ in the downloaded file; every session field/replay input/checkpoint must be equal, and stored raw bytes remain unchanged.

Keep browser wording **Download requested**, not “saved successfully.” The [HTML download standard](https://html.spec.whatwg.org/multipage/links.html#downloading-resources) makes `download` an author indication and leaves handling to the user agent; it is not proof that a file reached disk. The [existing platform adapter](../game/platform.mjs) already preserves copyable JSON, returns native cancellation/outcome messages, bounds filenames/bytes and schedules object-URL release. Retain that path rather than adding a file-picker API, permissions flow, network upload or timer-based success claim. Cancellation after the native/browser save UI opens belongs to that adapter/UI; do not claim to revoke an already-requested download. This recommendation was checked against the primary standard on 12 September 2026.

## Separate pack/level launch integration

The isolated selector change adds `activatePack`, `ensureBundledPack`, `replacePackLibrary`, `selectLevel` and startup `pack/campaign/level/play` query handling to the same app host. Export never calls these functions, fetches/installs bundled content, changes the URL or interprets `play=1` as saved-flight authority. A selected pack/level is presentation and launch context; the session's full campaign key remains the export-verification identity. After an explicit deep-link launch has actually started, the normal current-flight rule applies; before it starts, a mere query/selection is not a current attempt.

When those changes are integrated, an in-progress content selection/install must block starting export, and beginning such a selection must invalidate any pending export **before** asynchronous pack fetch/decode/storage. Recheck after adoption too. Route invalidation through the existing `selectEntry`/`prepare` and profile/pack replacement boundaries rather than duplicating picker behavior. Cancellation must consume the pending operation's Back/Escape without launching the selected level. A launch queued for a later animation frame must not bypass an open Library operation or turn its Ready export into a silently different source; test that boundary in the integrated host. Preserve the selectors' separate install/write authorization and storage errors.

The pure export verifier can be implemented independently, but app changes overlap the selector commit and should be integrated after its host diff is settled. This plan neither approves that branch's overall behavior nor expands the save fix into a review/rewrite of pack navigation.

## Meaningful acceptance tests

Use actual legal existing recordings; preserve all historical proof/checkpoint files.

- Both steering modes and both supported simulation/replay pairs: export a valid stored live-cut and recovery checkpoint, compare the complete envelope to the input, and reverify/restore the exported file. `savedAt`, run ID, input segments, release boundaries and authoritative checkpoint stay exact.
- Current paused/running/recovery selection takes precedence over an older stored checkpoint; recording exhaustion never silently exports the older file as current. Ready and terminal select only the stored checkpoint. Practice/course reject without touching normal storage.
- Bad raw JSON, empty/oversized slot, storage read failure, malformed metadata, mismatched checkpoint/summary, terminal recording and wrong installed context fail with no storage writes or game adoption. Missing pack permits only a truthful replay-only file; importing it remains blocked until the exact pack is installed.
- A stored source changed during a yielded verification, final-progress abort, new attempt, profile/pack replacement, dialog close and pagehide cannot publish stale JSON or call download. Ready export performs zero storage setters/removers. Current behavior tests distinguish legitimate existing release/autosave from export authority; do not assert an impossible pre-Library no-write guarantee.
- A same-object current run resumed and paused again during verification is rejected; a cancelled First Flight handoff can export its current paused recording without clearing the handoff save hold. Missing adopted content permits only replay-verified rescue; an available exact context that fails rule verification never falls back.
- With the selector work integrated, selection/install already pending prevents export; a selection beginning during verification cancels it before publication; a different selected pack/level never changes the stored envelope; export performs no pack fetch/install or launch. An actual started `play=1` run selects current export, while a deferred launch cannot execute through the pending Library operation.
