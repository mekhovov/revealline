# Earlier profiles: controller navigation during startup

**v0.60.4 source candidate, not a released phase.** This page describes the composed display, startup, deferred Back, ready-action and explicit Back history-return corrections. The [integrated evidence record](verification/cross-mode/p03-recovery-reading/README.md) distinguishes original failures, 89/89 precursor cohorts, the 92/92 history-return successor and scoped local browser observations from pending final-source/public and physical-input gates.

Earlier profiles keeps **Back to game** and **Reload recovery** usable while release information is loading, timed out or failed. The shared controller navigation adapter starts independently of the version/catalog request. One router owns the page through retries and readiness; retrying does not require a fresh controller join.

Reload replaces the current startup read, cancels its deadline and rejects its late result. It does not discover profiles or invoke any profile repair/write. After a successful startup, Reload is hidden and the ordinary explicit Find/Review workflow remains. If Reload is the focused action as it retires, focus moves to Find only while that same startup is current and the page remains foreground. Newer focus and background completion prevent this handoff; foreground return does not schedule another focus request.

Back invalidates the startup generation and stops navigation immediately before leaving. Once data controls are available, the existing view still closes its read-only reader before Back leaves. A hidden/unfocused page does not consume controller input; a held command cannot become a new action on return. Cached departure stops sampling and closes the current read/view; a persisted return restarts the existing read lifecycle with one navigation loop. Terminal departure destroys the navigation owner and cannot be revived by a late response or pageshow.

This correction composes after [shared Recovery reading preferences](recovery-display-readability.md), which changes only presentation. It does not add restore/migration, automatic Find, profile writes, new reader capabilities or device-specific controls.

## Explicit Back and cached history return

Successful Back can navigate to the game while the browser retains the Recovery document for reuse. An independent review found that the preceding candidate permanently closed its navigation owner before that decision, leaving Recovery inert if the browser restored it from cache. The earlier stale-Back regression covered departure while cleanup was still pending; it did not cover completed Back followed by a persisted departure and return. Its 89 passing cases did not establish this missing boundary.

Explicit Back now marks a transient departure, stops polling and clears held input while preserving the single navigation owner. Only terminal `pagehide` destroys it. A persisted return clears the departure state, starts a fresh read generation and requires a neutral controller before a new command. Old reads, deferred Back callbacks and terminally disposed pages cannot restart or navigate. Closing the read-only reader before legitimate Back remains required; returning does not restore a closed prepared-download session or discover profiles automatically.

The successor passes the same six complete affected files: **92/92 on Node 20.19.5 and 92/92 on Node 22.22.2**, sequentially at 1024 MiB with 95 unchanged inputs / 1,155,888 bytes. The preceding host fails two of the whole 16-case startup file (14 pass / 2 fail). Those modeled events establish implementation behavior, not actual browser cache admission or physical controller acceptance. The earlier native ready-action observations retain their own exact host bytes. The separate native history retest described below passed; final composed-source/public qualification remains required.
