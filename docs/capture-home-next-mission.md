# Capture Home: explained next mission

This bounded F10 slice adds one localized explanation beside the existing named
Start/Continue action on the default Capture Journey (`whole-spatial-v25`). It
adds no button, launch authority, progression rule, saved preference or lesson
mastery record. Missions/Browse all and the existing optional First Flight entry
remain available.

The host's existing Journey destination calculation remains authoritative. A
read-only projection explains that exact owned destination:

- First mission: it starts this Journey, without assuming the player is new.
- Selected mission: it continues the exact scoped cursor.
- Retry: only the currently accepted terminal loss for that same mission can
  justify a retry explanation. No skill diagnosis is inferred.
- Recorded next: the host's real successor follows a recorded completion. A
  historical receipt is not described as mastery of the current edition.

Actual in-memory/saved Resume and save recovery take priority. Unknown/stale
owners and an already-cleared final destination produce no fabricated successor.
The explanation does not rank the unified library, inspect images, unlock
content, prepare assets, start a mission or write progress. Existing guarded
Start/Continue handlers still own activation. Its accessible description follows
the existing visible action and is removed when guidance is suppressed.

Home open, localization and existing saved-flight/progress refresh owners update
the explanation without taking focus. The existing Home text style is reused;
there is no new font-size policy or numeric accessibility claim. Other modes,
Legacy, imported editions, previews, practice and isolated lessons are outside
this host slice.

F10 remains partial overall. Cross-mode and contextual lesson recommendations
remain deferred to F25 and its shared-demo dependency D. The current First Flight
visit state is not durable lesson mastery; no nonexistent Learn routes or
cross-session last-defeat history are invented.

Verification uses complete pure and actual Solo host files. Native public input
earns the opening win and a terminal self-crossing loss; normal saved-flight
verification and the real selector remain in charge. Authored image requests use
the same actual-file fetch boundary as existing authored Journey tests. PNG bytes,
hash/identity admission and simulation remain real; DOM, decoding and rendering
are finite test boundaries. The original failed missing-explanation case and
subsequent fixture/staging diagnostics are retained separately. A one-tick reverse
did not guarantee a turn; the observed post-respawn grace also stops a new cut at
the safe edge. The final public route waits for that existing protection before
its next fresh press, without changing the core, fixtures or timeout policy.

Actual browser screen review, full repository lint and uninterrupted source
validation remain separate pending gates. These checks do not qualify compact
layout, hardware, offline/PWA behavior or physical rendering.
