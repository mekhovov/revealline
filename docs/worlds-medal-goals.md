# Worlds medal goals

F23d explains the next medal inside the existing verified Worlds result details.
The current elapsed time, contact count, stars, score, section comparisons,
practice choices and action rows retain their owners. The new paragraph uses the
current accepted result, never a previous personal best.

Worlds medals require both a time limit and a contact limit. The explanation
states the next target, the exact time reduction and any excess contacts. If
time already qualifies, it says so rather than asking the player to fly faster
to compensate for contacts. Contacts affect the existing score separately;
this feature does not invent a time penalty. Gold closes the medal ladder.

`worldMedalGoal` reads the existing evaluator's returned targets and compares
integer ticks at 50 Hz. Equality qualifies; one tick over is a positive 0.02 s.
There is no Capture EPS or rounded-up Time Attack comparison. Missing,
inconsistent or ineligible facts produce no guidance. The projected facts are
frozen scalars; neither projection nor translation changes rules or records.
The existing targets remain provisional, mode-specific playtest targets, not
newly calibrated competition standards.

The host adds guidance only after its existing recording verification succeeds
and the flight token remains current. This covers the full Worlds result paths
that already award these medals, including eligible School and retained Academy
courses opened through Worlds. Authoring preview, recorded playback, section
practice, free flight, mode practice, unfinished flights and Regional flights
retain their existing exclusions. Standalone Academy's lesson result is a
different owner and gains no new medal ladder.

English/Ukrainian changes update the same paragraph through the native language
owner. Starting another flight, closing or disposing the host releases its view
reference. No action subtree is replaced to refresh the guidance. The canonical
helper is projected into `world-reaction-runtime.mjs` through the existing
generator, with no new executable package slot.

Verification includes three legal native flights and replay checks for Gold,
Silver and Bronze; exact time/contact boundary comparisons with the native
evaluator; unavailable/inconsistent cases; and a real host/model/record-store
journey earning Gold then Silver on an authored finite test course. The latter
checks that current Silver is explained while prior Gold remains stored, no
guidance appears before verification, live EN/UK retains state/records/action
identity/focus, and native Retry prepares a fresh disarmed attempt. Preview
completion remains unscored. Fixture DOM/renderers and scalar boundary cases are
not public-catalogue, browser, acoustic or physical-device qualification; actual
compact result review is recorded separately for the frozen candidate.
