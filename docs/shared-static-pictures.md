# Static Solo / Versus picture parity candidate

The current [P05-A composition](p08-static-p05-composition.md) preserves the later P03 navigation and shared display hosts. The original evidence below remains scoped to its earlier source.

This P08-A preparation applies the existing fresh Solo picture-selection rules to the fifteen shipped static Versus maps: twelve First Signal maps with four themes each, plus three FPV Pressure Lines maps. The 51 map/theme combinations are an identity inventory, not a claim that every theme now receives new artwork. The existing release resolver selects registered FPV art; other themes and historical procedural content retain their authored behavior. Team presentation, installed-chapter redesign and new art production remain separate.

Versus first checks the exact current still assignment for the map, theme, level revision and full campaign/class identity. An explicit user assignment wins. Otherwise it uses the existing release baseline matcher and resolver used for a fresh Solo flight. A changed authored original is not silently replaced with a current default. This path does not rewrite Solo saved-flight or first-earned Collection pins, copy originals into the library, award progress, or install assignments.

Both Versus boards receive the same decoded picture object, fit and sampling. A setup change creates a new attempt and prepares its choice before enabling Start. A picture Retry retains the untouched attempt and its selected original; it does not reset simulation state or choose a newer assignment. Start rechecks the accepted authority before beginning the round. Pause and display preferences retain the prepared picture and existing continuation.

The new lease reads existing shared media metadata and selected original bytes. It reuses the managed store's established schema initialization/upgrade on open, but never commits media content, assignment, history or progress records. A valid empty library permits normal release resolution. When IndexedDB is unavailable, the notice discloses that saved picture choices could not be checked. A present store's open, blocked or corrupt-metadata failure refuses Start rather than assuming there is no assignment.

The whole optional cosmetic release snapshot may be unavailable. In that case the existing visible release-load notice and explicit authored fallback remain; this candidate does not broaden Solo's fallback policy or block procedural/training content. Once an image is actually selected, failed read, hash, dimensions or full decoding refuses Start visibly. Retry cannot silently substitute a different image. Whether all future releases should require a complete cosmetic snapshot remains a separate P08 acceptance decision.

Each pending operation has its own cancellation fence. A new selection cannot publish an older completion. A replacement is accepted before its predecessor's owned image lease is released. Leaving the preparation screen cancels pending work without starting the round; terminal page disposal releases only the owner's URLs, image bindings and pending reads. A persisted page suspension retains the prepared resources. Uploaded originals and immutable source art are not deleted or edited.

When a focused Retry or asynchronous Start confirmation disables its own action, that operation transfers focus to the visible Cancel action. Ready/error focus can return only while the operation still owns focus. Deliberate navigation, foreground loss, scope changes and stale completion must not take focus back. This is a local preparation handoff; it does not engage controller mode or change the round's simulation. Suspend, blur and controller loss also expire the pending Start/Next intent. The same picture preparation may finish ready after return, but only a new explicit Start may begin play.

## Reference guidance and remaining visual checks

Primary guidance checked on 2026-09-15 supports three boundaries:

- Both boards use the selected picture's same nearest sampling. Disabling canvas image smoothing preserves pixel sharpness when enlarging pixel art; actual native fit and readability still need inspection. [MDN: imageSmoothingEnabled](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/imageSmoothingEnabled).
- Release each owned object URL when its image is no longer used. The tests check replacement, cancellation and disposal ownership; this does not authorize revoking another host's borrowed original. [MDN: revokeObjectURL](https://developer.mozilla.org/en-US/docs/Web/API/URL/revokeObjectURL_static).
- Future visual acceptance must check essential actor cues and focus graphics against bright, dark and partially revealed pictures. WCAG's non-text contrast criterion calls for 3:1 against adjacent colors for required component/state and meaningful graphical information; it does not apply that threshold to every decorative pixel. Applying that guidance to particular game cues needs a scoped review. No full contrast audit has been performed for this candidate. [W3C: Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html).
