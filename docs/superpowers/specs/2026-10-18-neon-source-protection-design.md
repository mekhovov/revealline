# Neon gallery source-protection correction

Status: draft for independent and user review; no implementation authorized by
this document alone.

## Purpose and frozen starting point

Unblock PR1453 without weakening access protection or appearance-first-paint
assertions. Current PR head is d59259372fa51351db672c8a73573ea102f80fb3;
current main is fe1bb1cecbfcead7edaad24e802242d62b4e3b99. Refresh both before
implementation. Retain all password localization/focus changes and all authored
gallery resources. Earlier two-HTML-only correction was reverted because it
failed two integration assertions; do not repeat that correction in isolation.

## Current contradiction

The two gallery generators produce unprotected source HTML. The source-access
inventory requires protection before page scripts execute. Applying the existing
protectPageHTML projection inserts its standard security visibility style before
held appearance startup. The current Neon appearance assertion treats every
inline style as ordinary appearance CSS, so that exact security style violates
both seed-first and legacy-layer assertions. Source protection, generator/source
equality and ordinary appearance ordering must hold together.

## Options and recommendation

1. Recommended: both existing synchronous gallery builders produce the existing
   standard protected projection. The appearance assertion recognizes exactly
   one standard security visibility style in the canonical gate, while retaining
   every ordinary resource ordering and legacy-layer assertion.
2. Keep the verified rollback and leave the source inconsistency unresolved.
   Safe as a temporary hold, but does not unblock the full correction.
3. Exempt all styles, gate-looking markup or these pages from tests. Rejected:
   this would hide ordering/protection regressions rather than fix them.

## Generator and configuration ownership

Keep existing positional arguments and synchronous string return contracts for
buildNeonArtworkGallery and buildNeonMosaicGallery. Keep generation in the
existing two scripts; do not introduce a second protection implementation.
Apply unchanged protectPageHTML with each exact repository-relative page path
and canonical game/index.html access metadata.

Resolve configuration synchronously at builder invocation, not module import.
An optional final configuration-source argument may support isolated fixtures;
ordinary existing calls default to the canonical import-relative game/index.html
source through readFileSync. A missing/incomplete canonical configuration fails
closed. No embedded verifier copy, credential logging, network access, storage
mutation or asynchronous return is introduced. Existing callers must be fully
enumerated before editing, including tests and build/authoring scripts; if any
caller requires a filesystem-free pure function, stop and revise this ownership
choice rather than silently changing that contract.

Only the two generated gallery index.html files are regenerated. Removing the
canonical generated gate and normalizing only its documented script-holding,
canonical charset relocation and locked-root attribute projection must recover
the original authored document semantically: image/link targets, scripts,
inline authored bodies, article order and content remain unchanged. Compare
authored script bodies and resource target/order inventories exactly; do not
use broad whitespace normalization to hide authored changes.
Protection must be idempotent and generated bytes must equal checked-in source.

## Exact appearance/security boundary

Do not change runtime theme-bootstrap or access-gate behavior. Adjust only the
source assertion's classification of the existing generated visibility style.
Recognize it by the exact current protectPageHTML output, not substring or
selector resemblance. Require a unique, structurally valid canonical gate block,
locked root, shared metadata, gate stylesheet/script placement, held executable
page scripts and the exact visibility-style bytes. The recognized style must
occupy its canonical position inside that block. No ordinary resource may be
smuggled into the block or excluded from appearance ordering.

All other inline styles still begin with @layer legacy and follow the held
appearance seed. All ordinary scripts and stylesheets retain seed-order checks.
The access-gate script remains the only active pre-unlock executable script.
Malformed, repeated or security-looking noncanonical blocks fail; do not repair
or ignore malformed input in the assertion.

Expected code scope: two generator scripts, two generated gallery pages and
