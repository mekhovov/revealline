# Sentinel spatial successor — shortcut repair

Scope: explicit copy-on-write geometry/placement successors for Twin Receivers
and Relay Perimeter. No changes to the engine, capture contract, boss recipe,
control policy, warning lengths, release window, lives, earned-coverage target,
other published/historical editions or soundtrack. Solo/paired-board Versus only;
no Team claim or automatic enrollment. Continue under the user's existing approval.

## Evidence and choice

The498-case pressure audit reproduces9.96–10.06second Twin Receivers clears and
12.15–13.75second Relay Perimeter clears across all three presets/two steering
policies. In Twin's Standard route, a small near-core loop at5.75seconds captures
99.68% and both shields, leaving seven field cells. The legal isolated-core release
then completes at9.96seconds. In Relay Perimeter, the initial return takes0.65seconds,
the eastern receiver falls with a73.99% capture at5.75seconds, and both remaining
shields fall in one short closure at7.85seconds. Core release follows at12.15seconds.

Chosen: deeper offset shield galleries and fewer convenient near-core starting
returns, with useful outer approaches and existing frontier/ground threats.
Rejected for this slice: speed-only escalation (does not remove the shortcut),
and multi-anchor boss engines/new compulsory phases (broader rule/schema changes).
Do not remove the legal isolation rule or extend transition waits to manufacture
longer clears. Optimal play can remain faster than the human pacing aspiration.

## Two distinct route decisions

Twin Receivers: a remote starting landing approaches a bifurcated receiver court.
Open wall baffles separate the upper/lower galleries while keeping their field
connected to the same Sentinel. Decide which approach to secure first and where
to close a cut that preserves a useful route to the other receiver. Put no starting
foundation directly alongside the core. Preserve the two-shield objective and
existing frontier/roamer roles; move their starts only when revised geometry needs
valid topology/clearance. The optional mastery remains separate receiver captures.

Relay Perimeter: stagger the long starting returns into separated platforms and
use asymmetric baffles around three receiver approaches. The western shield still
opens a permanent non-scoring connector, but the connector must be a useful route
improvement rather than an immediate tiny-core enclosure. Retain three shields,
the same frontier/roamer roles and a voluntary choice of receiver order. Optional
mastery must actually traverse the opened connector before the last shield.

Exact coordinates are greybox iteration output, not copied reference geometry.
Each candidate must start with one retained field component, no unintended remote
fill, legal spawn, usable departures/returns, valid frontier attachment and no
unavoidable opening pressure. Walls never count as return surfaces. Connectors
remain reserved permanent foundation cells with a stable coverage denominator.

## Verification and acceptance

1. Reproduce the old shortcuts unchanged as historical controls. Compile both new
   maps across all presets/Solo/Versus, check topology and lossless10second spawn
   observations. Old source/fixtures must remain exact and unmodified.
2. Replay every recorded old shortcut against the new editions and record actual
   outcomes. A still-trivial shortcut is a reason to revise, not weaken the check.
3. Search new legal-input routes (straight and bent cuts as needed), freshly replay
   them and run equal independent races for both steering policies/all presets.
   Record shield closure grouping, field cells at transition, release cause/cut
   length, connector traversal, early pressure and clear time. No injected state.
4. Require representative played routes to exercise distinct receiver approaches
   and the exposed stage. Test a useful traversed connector route in Relay. This
   does not introduce an engine rule forbidding multi-shield captures or isolation.
5. Investigate any sub15second searched clear; do not claim repair on the basis of
   a slower chosen route while retaining a known fast one. Target ordinary human
   play45–150seconds without arbitrary waits or low-risk quota cleanup. Search
   failure is not proof of impossibility; route length is not proof of enjoyment.
6. Node20/22 compiler/encounter/replay/route regressions, exact-source Studio/native
   play observation, and broader timing/device/human evidence recorded separately.
   If only one candidate passes, keep the other explicitly unaccepted; do not
   silently replace it or report the whole pair balanced.
7. Review and hand the scoped successor packet to the release owner for allocated
   PR/version/Pages test promotion. Preserve the frozen release and user worktree.

Implementation order: factory/topology; bounded route search and iterative spatial
repair; pinned route/race regressions; explicit Studio preview; native observation
and evidence/remaining ledger; release handoff. Human acceptance is still required.
