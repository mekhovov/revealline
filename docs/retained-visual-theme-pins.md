# Retained compiled visual themes

A successful, live `prepareVisualThemeLease` now exposes `pin()`. It produces `revealline-visual-theme-pin.v1`: exact accepted content context, catalogue selection ID/revision, and measured compiled source/theme/collection/manifest hash. A released lease cannot mint another pin. This owns the compiled actor/HUD/terrain/effects collection. It is not a complete saved attempt, picture/story record, asset archive or proof that lazy picture/audio dependencies are present.

`snapshotVisualThemePin` bounds, validates and deeply freezes object/JSON input. `validateVisualThemePinForContent(pin, actualContent)` compares the actual context supplied by the accepted Legacy/Team/Journey adapter. It never infers ownership from level names or rewrites execution keys. Standard authored identity is shared across each adapter's supported difficulty presets; mode, project, pack, campaign, level revision and content hashes remain exact. Historical Team numeric revisions retain their type.

`prepareRetainedVisualThemeLease({pin, catalogue, content, requiredSlots}, options)` ignores fresh-attempt preferences and resolves only the stored selection. An unavailable exact revision or unsupported context returns an explicit catalogue outcome without loading a host. A same-reference catalogue rewrite cannot override the saved presentation: all exact references/hash must agree before acquisition. A successful restore then fetches/verifies/decodes again through a new host and transfers the usual explicit lease.

The parser alone proves only a well-formed declaration. Restoration still needs the accepted content owner, reviewed immutable catalogue history, original compiled bytes and asset validation. Never register an uploaded pin as trusted catalogue history. Missing files require recovery; there is no latest-revision fallback. Code-owned current renderer requirements supply `requiredSlots`, never the uploaded pin.

This slice changes no historical session/picture/story parser and persists nothing. Host adoption must add an explicitly versioned outer attempt/session envelope containing this compiled pin alongside its existing exact picture/story/audio authorities. Old attempts must keep their existing readers and visuals; never silently mint a current full theme for a historical save. Backup/export/offline and missing-resource preflight must include all transitive pinned assets before claiming complete recovery.

Tests cover actual compiler bytes, serialization and immutable ownership, retained restore, changed content and mode, forged same-reference catalogue metadata, unavailable revisions, byte drift while another host remains usable, cancellation, hostile input and all three Journey modes/presets through the real compiler adapters. An additional historical Team case proves numeric revision preservation. Mocked image decoding is not real-browser, visual-quality, physical-input or public-release evidence.
