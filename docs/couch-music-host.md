# Couch music host integration (P02-B)

Team and Versus now compose the shared music library, player, session policy and library panel through `attachCouchMusicHost`. Settings → Audio exposes Play, Pause, Previous, Next, session music volume, Music library, live preparation/error status and library retry. Master mute/volume remain origin-wide; music starts at 0.55 for each visit. Neither mode writes Solo progress or its audio profile. Versus enables its effects engine independently of music Pause or library readiness; Team gameplay cues remain visual.

The adapter loads validated v4 shared-library bytes silently before offering playback. No storage completion autoplays. Start, Retry and Resume respect an explicit music Pause, including Pause before the first Start. Foreground restoration restores only prior listening intent; gameplay still requires its own explicit Resume. Native playback promises remain authoritative. Failed assignment messages replace stale preparation text, so a terminal failure cannot appear to be waiting indefinitely. Music readiness does not block starting a game.

The host owns a single frame pump, gameplay pause, controller root and the exact Settings visit. The library is the top navigation scope until it closes. Ordinary closure returns to its Audio opener; hidden, obsolete and terminal visits do not manufacture foreground focus. Busy library operations transfer an action that becomes disabled to Cancel, then restore a usable action or Close on completion. Newer focus and hidden-page ownership take precedence. The music owner closes the panel, session, player and managed-store facades on terminal departure; Team closes its owned Soundscape and Versus closes the Soundscape it supplied. Persisted page hiding only suspends transport.

Versus derives compatible assignment keys from accepted campaign metadata, including installed campaign base identity. It does not parse presentation labels or an installed-map key. Team prepares a validated canonical pack/level context once per picture selection and adopts it only for the accepted attempt; stale preparation cannot replace a newer context. Theme/global playlists remain available during preparation. Music fields never enter historical Team pack objects or simulation identity.

Published Team music uses a music-only binding: it installs no Solo gameplay/UI cue listeners. Team gameplay effects remain a separate qualification scope. Manual playlist choices keep their established precedence over published or authored automatic music.

## Verification and delivery boundaries

The host tests use actual page markup and host/input/navigation/player/storage modules with finite DOM, controller, media, AudioContext and IndexedDB boundaries. They cover exact nested return, Pause before Start, master mute, session-only gain, actual prepared MP3 bytes shared with Solo storage, foreground restoration, controller Back, engine disposal and music-only published bindings. Native dialog Escape defaults are explicitly modeled because the finite DOM does not implement browser cancellation.

Native-browser review separately exercises keyboard entry and return in both modes, Team muted Play and Pause through Start, and Audio controls at 390×844 and 844×390. A native MP3 fixture import, audition, atomic save and silent cross-mode load also passed; post-save keyboard focus was corrected and rechecked natively. Those checks do not establish physical touch/controller behavior or an actual listening review. Complete release gates, public/offline verification, physical inputs, extended browser media-permission edge cases and listening remain requirements on the final integrated release. An isolated integration packet is not a deployed release.

Production-builder tests require ordinary files. The bounded qualification fixture borrows exact unchanged source/art by read-only hardlinks, checks input inode/size/hash before and after, and writes no builder output into those inputs. Initial symlink refusals remain in the evidence; no validation guard or test is skipped.
