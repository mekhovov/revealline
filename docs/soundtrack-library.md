# Soundtrack library foundation

This source increment provides versioned music metadata, preserved MP3 import, separate transactional storage, complete binary soundtrack transfers, and a separately integrated session player. It does not yet attach uploaded music to the game, add an admin screen, produce the planned original albums, or establish browser playback/offline acceptance. The existing five original synthesized recipes remain unchanged.

## Records and selection

[The model](../game/soundtrack.mjs) exposes `resolveAudioTrack`, `resolveSoundtrackLibrary`, `emptySoundtrackLibrary`, `resolveSoundtrackSelection`, and `soundtrackOrder`. Resolvers copy bounded plain data without invoking accessors and return owned frozen records. Unknown fields/versions, missing references, duplicate IDs, conflicting metadata for one hash, and attempts to replace reserved `builtin.*` identities fail.

`revealline-soundtrack.v1` contains custom `tracks`, custom `playlists`, `assignments`, and `selection: { playlistId }`. The immutable builtin collection has five synth tracks and six playlists: `builtin.all` plus one single-recipe playlist for each style (`builtin.genre.synthwave`, `.chiptune`, `.rock`, `.metal`, and `.ambient`). The limit is **128 total tracks and 32 total playlists**, including those builtins (at most 123 custom tracks and 26 custom playlists); a playlist has 1–128 entries. Repeated entries are allowed. Builtin-only, uploaded-only, and mixed playlists use the same ordered track-ID list, with `order: ordered|shuffle` and `repeat: all|one|off`. Repeat is a transport instruction; this foundation does not play a queue.

Each custom `revealline-audio-track.v1` record includes a stable ID, `kind: mp3`, title, artist, exact asset SHA-256/byte count, frame-derived duration/sample format, and provenance. Track binaries are separate native Blobs. No file URL, base64 body, HTML, remote fetch address, or executable callback belongs in metadata. Provenance has `kind: original|licensed|personal`, `credit`, `license`, and `source`; licensed entries require a nonempty license description. These are authored declarations, not an automated rights determination. Keep masters, permission records and credits for release material; a local personal upload is not automatically selected for public distribution.

Explicit `selection.playlistId` wins over authored assignments. A null selection resolves the exact map key, campaign key, theme ID, global assignment, then `builtin.all`, in that order. Assignments have `{ scope, key, playlistId }`; the global key is null. This is independent of game difficulty, replay identity, and saved progression. `soundtrackOrder` uses injected presentation randomness, retains repeated entries and avoids repeating the previous track first when another choice exists. It never consumes the simulation RNG. An eventual persistent player must apply automatic context changes at song boundaries and explicit user selections immediately.

## MP3 import boundary

[The MP3 module](../game/mp3.mjs) separates `inspectMP3(blob, { signal })` from actual import. Structural inspection preserves and hashes the original bytes, checks every consecutive MPEG Layer III frame boundary, and derives duration without trusting a filename, MIME label, ID3 title, or imported duration. It supports constant/variable bitrate MPEG 1, 2 and 2.5 streams with a constant sample format, an optional leading ID3v2.2/2.3/2.4 tag, and trailing ID3v1. A leading tag has a 1 MiB limit. Free-format frames, format switches, reserved headers, junk/truncated data, ID3 footer-tagged files, and other trailing tag formats are rejected; originals are never silently repaired or transcoded.

An MP3 is limited to **32 MiB and 720 frame-derived seconds**. `prepareMP3Import(blob, { id, title, artist, rights }, { signal, probeMedia })` additionally requires a media probe. The default `probeMP3Media` uses one temporary audio element, checks `audio/mpeg` support, waits for metadata and first decoded data, and validates finite duration. It does not call `play()` or decode an album into PCM. It removes listeners, unloads the element and revokes its object URL on success, error, cancellation or timeout. A host can inject the equivalent real browser probe; Node tests explicitly inject a structural test seam. Header validation alone never means playable audio. First decoded data also does not certify uninterrupted decoding of every later frame.

Browser duration may differ slightly because of MP3 padding/decoder reporting. The probe must be within the greater of 0.5 seconds or 1% of the frame-derived duration, and cannot exceed 12 minutes; the canonical record keeps the frame-derived value. Playback failures still need observable handling in the eventual player. Browser codec support and media metadata are separate concerns. [MDN audio codecs](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Audio_codecs), [MDN loadedmetadata](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/loadedmetadata_event).

## Atomic storage and complete transfers

[The bundle module](../game/soundtrack-bundle.mjs) provides:

- `prepareSoundtrackLibrary(library, assets, { signal, probeMedia })`: validate all metadata and every distinct original, run the required media probes, and return an opaque prepared capability.
- `exportSoundtrackBundle(library, assets, { signal })`: verify exact hashes/frame facts and return a complete binary Blob. No probe is required to export already preserved bytes.
- `importSoundtrackBundle(blob, { signal, probeMedia })`: validate the complete container and prepare every referenced original before any storage change.

Assets are dense `{ sha256, blob }` entries. Shared originals transfer once. Missing, extra, duplicated or corrupt assets fail the whole operation; no partial backup is labelled complete. The binary `revealline-soundtrack-bundle.v1` format is eight ASCII magic bytes `RLSTB1\r\n`, a four-byte big-endian UTF-8 manifest length, the canonical JSON manifest, then raw originals in ascending SHA-256 order. The manifest contains `format`, `library`, and `{ sha256, bytes }` entries; offsets follow from exact lengths. Trailing or truncated payloads fail. The manifest limit is 512 KiB plus 32 KiB for the envelope/table. Payloads remain Blob slices; only the manifest and one bounded MP3 at a time need byte inspection.

[The store](../game/soundtrack-store.mjs) exposes `createSoundtrackStore({ indexedDB, estimate })` with `read({ signal })`, `commit(prepared, { expectedGeneration, signal, otherManagedBytes })`, and `close()`. It uses the separate `revealline-soundtrack-v1` IndexedDB database with `metadata` and hash-addressed `audio` stores. `read` returns `{ generation, library, assets }`; a missing binary does not destroy its metadata, but complete export then fails. `commit` accepts only a fully prepared capability, checks the expected generation again inside the write transaction, and commits metadata, new originals and obsolete-original deletion together. Cancellation accepted by the transaction, or a write/quota error, aborts all those changes. If cancellation arrives after native commit, the completion event reports the committed result; the UI must not claim that this late request rolled it back. IndexedDB defines abort as reverting transaction changes. [MDN transaction abort](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/abort).

The managed bound is **256 MiB for committed bytes plus staging**, including old/new metadata and the host-supplied `otherManagedBytes`. That parameter defaults to zero for an otherwise empty managed-media collection; an integrating media manager must supply other managed content usage. Existing same-hash originals are verified and reused without another binary put. Corrupt originals count as replacements and require staging headroom. Browser quota estimates are advisory; a transaction may still fail. The logical byte budget is not a promise about browser heap, compression, disk spooling or physical free space.

Optional chapter/theme bundles target **64 MiB**. A complete soundtrack bundle may be larger but cannot exceed **256 MiB including its manifest**. Replacing a nearly full collection can require removing content explicitly first; this API never deletes old data to make room before a verified replacement commits. It never creates a hidden partial backup. Existing profile/pack/save JSON formats and their separate budgets remain unchanged. A future UI/native binary-download adapter must distinguish this soundtrack file from existing complete game JSON backup. Managed storage alone does not certify service-worker offline readiness, persistence after browser eviction, or cross-device transfer.

## Verification and integration handoff

Run the focused source tests with:

```sh
node --test game/test/mp3.test.mjs game/test/soundtrack.test.mjs game/test/soundtrack-store.test.mjs
```

The tests cover strict ownership/references and preset limits, assignment precedence, shuffle boundaries, exact-byte bundle round trips, malformed/truncated media, required probe failures and cleanup, atomic rollback, stale generation, quota/staging headroom, same-hash reuse, and corrupt/missing originals. The finite IndexedDB and audio-element harnesses model those API contracts; they are not real browser storage/playback or mobile acceptance. The [coded-silence fixture](../game/test/fixtures/audio/README.md) has separately recorded CoreAudio decode evidence and is not finished music.

## Persistent player integration

[The session player](../game/ui/soundtrack-player.mjs) exports `createSoundtrackPlayer({ soundscape, audioElement, readAsset, onChange, random, URLImpl, fadeMs })`. Supply a persistent `Soundscape`, exactly one HTML audio element, and `readAsset(sha256, { signal })` returning that original Blob. The default explicit-selection fade is 120 ms, bounded to 250 ms; tests can use zero. The player rechecks loaded bytes before creating its object URL and streams through the media element instead of decoding an album to PCM.

- `setLibrary(library)` preserves the currently owned track and URL through metadata edits, then adopts edited queues at the next boundary. A changed stored selection is also adopted at that boundary; an unrelated metadata edit preserves an existing session choice.
- `setContext({ mapKey, campaignKey, themeId })` queues automatic assignment changes. `setAuthoredTrack(recipe|null)` supplies an owned, validated ephemeral fallback for existing scenario/pack music. Explicit and scoped playlist assignments take precedence. Without either, the authored recipe loops; without a recipe, `builtin.all` applies. This fallback is not serialized into the soundtrack library or gameplay identity.
- `selectPlaylist(id|null)` applies an explicit choice with a short music-only fade, preserving whether the player intended to play. Use `play()` for an explicit Play selected action; selecting a playlist while paused does not start it. Save a persistent choice separately in `library.selection.playlistId`.
- `play`, `pause`, `next`, `previous`, `seek(seconds)` and `setVolume(0..1)` control only music. Previous restarts a track after three seconds, otherwise selects the prior entry. Natural completion honors repeat one/all/off; Next advances despite repeat one. A broken track ID is attempted once before moving on, with a finite builtin fallback and an observable notice. A new explicit retry/selection clears the failed-ID set. Browser autoplay denial yields `blocked` and requires another Play action.
- `update(active, theme, state)` wraps the one Soundscape scheduler call. Do not also call `soundscape.update` from another loop. Ordinary gameplay pause/results pass their current state without calling transport pause, so music continues. Gameplay `soundscape.reset()` still resets only SFX in persistent mode.
- `suspend` silences music and the SFX context for a full host lifecycle interruption. `resume` restores the prior listening intent and can still be denied by browser policy. `dispose` cancels pending loads, removes media handlers, unloads/revokes its URL and relinquishes the song-end hook; the host retains ownership of Soundscape disposal.

`snapshot()` is owned data with `status`, actual `playing`, intended `desired`, current `track`, playlist/queue and pending playlist, explicit `selection`, assignment `source`, `volume`, error/notice and position/duration seconds. `desired` remains true during loading, browser blocking and lifecycle suspension; use it when a separate audition temporarily pauses/restores music. `setIntent(boolean)` restores that remembered intent only while transport is inactive and never starts audio; a hidden-page audition can restore intent for the host’s later permitted resume. Status is one of idle/loading/playing/paused/blocked/ended/error/suspended/disposed. The change callback receives action/media updates and bounded whole-second synth-position updates.

The player owns the legacy Soundscape `music` fader. Its volume control writes that fader; MP3 output is `master × music`, while SFX remains `master × sfx`. Route later settings changes through `player.setVolume` instead of independently overwriting the music fader. Master and SFX settings remain separate. With a player attached, authored gameplay changes go through `setAuthoredTrack`, not direct Soundscape track/style replacement.

The opt-in Soundscape hooks are `setSongEndHandler`, `pauseMusic`, `resumeMusic`, `musicPosition`, and `seekMusic`. No external end handler preserves the existing legacy/P1 loop behavior. With a handler, the scheduler stops at the audible 512-step boundary instead of reporting completion from its look-ahead window; music-only pause holds its clock and leaves SFX available. Existing audio tests retain that compatibility coverage.

Run `node --test game/test/soundtrack-player.test.mjs game/test/audio.test.mjs` for queue, authored-fallback, scheduler, interruption and compatibility checks. These tests use the actual Soundscape with finite audio/media adapters, including a complete synth rendition through its normal scheduler. They do not establish browser playback, background-tab behavior, audio quality or physical-device acceptance. Test native UI import, real decoding/playback, cancellation, browser restart, optional-media availability, complete download/import and native adapters before claiming those paths work.
