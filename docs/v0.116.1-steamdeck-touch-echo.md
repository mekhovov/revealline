# v0.116.1 Steam Deck touch-derived Confirm repair

Repair baseline: accepted public v0.115.1 source `6f13bd14496e3b1a6b929c78638b45ba07a7c753`; release integration baseline: frozen v0.116.0 source `5d6c0ec3e6995cd0485fe5065ff5ea2bf82e0cdc`.
The first reported failing public build was v0.106.0. The exact last working release is unknown.

## Failure and historical boundary

Solo controller navigation has activated the focused DOM control with `HTMLElement.click()` since
commit `107886d8` (first released in v0.5.0). The v0.98 navigation work retained that activation,
v0.105 rearranged the home presentation, and v0.107 added pause actions without changing the
Confirm mechanism.

The first duplicate-Confirm guard shipped in v0.108.0. Every guard revision through v0.115.1
treated `pointerType` touch/pen and `sourceCapabilities.firesTouchEvents` as unconditional native
touch, even while the assigned Gamepad Confirm button was physically held. The matching unit test
required those events to pass through. This left the exact reported sequence open: Gamepad A
activates on press, then Steam Input's touch-classified trusted click activates again on release.

Valve documents that legacy Steam Input bindings can emulate mouse, keyboard and gamepad input:
<https://partner.steamgames.com/doc/features/steam_controller/legacy_mode>. Chrome documents
`firesTouchEvents` as identifying mouse compatibility events derived from touch-like input:
<https://developer.chrome.com/blog/inputdevicecapabilities>. Pointer Events permits compatibility
events to be grouped after `pointerup`, while `click` remains a separate activation event:
<https://www.w3.org/TR/pointerevents3/#compatibility-mapping-with-mouse-events>.

## Repair

The guard now owns every primary pointer representation for the complete controller Confirm
lifecycle: mouse, touch, pen, touch-derived compatibility events and trusted click-only releases.
It tracks the owned pointer through cancel/release so the native event cannot clear controller
navigation before its duplicate click. A trusted native activation that genuinely arrives first is
recorded regardless of pointer classification; the later programmatic controller click is then
suppressed so exactly one activation wins. A new direct touchscreen or pen gesture takes ownership as soon as A is physically released, while Chrome compatibility events identified by `firesTouchEvents` remain guarded. With no controller Confirm ownership, touchscreen, pen,
mouse, keyboard, accessibility activation and modified/non-primary input retain their native path.

## Verification boundary

Focused tests cover both event orders, long holds, delayed releases, pointer cancellation, custom
bindings, disconnect/lifecycle behavior, standalone touch, home Sound, Settings, More, Start
mission, and every primary Pause action including Resume, Restart, Missions, Help, Settings, Sound,
Mission info and Home. Controller navigation help remains collapsed and absent from active gameplay.

Automated and desktop-browser checks do not reproduce the Steam Deck's physical event stream. Final
acceptance requires Chrome launched as a Game Mode shortcut with a Gamepad layout: tap and hold A on
the listed actions, then verify the physical touchscreen remains usable after the gesture.
