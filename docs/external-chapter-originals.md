# Exact-original chapter installation pilot

This isolated source slice adds `revealline-external-chapter.v1`: one lightweight, ordinary `xonix-pack.v5` gameplay file plus a separately authenticated `.rlmedia` file. A bounded `revealline-external-chapter-index.v1` retains the installed descriptors after the recovery journal clears. It introduces no pack v6, database, cap increase, derivative, resampling, default content, app/host UI, release or automatic migration. The original embedded packs/readers and saved/earned-picture formats remain unchanged.

The concrete [Pressure Pictures pilot](../authoring/library/external-chapter-pilot/README.md) reuses three existing layouts and all three exact original PNG byte streams under distinct pack/campaign/map identities. It is an explicitly new source edition, not an upgrade to the installed embedded edition. Actual input tests execute its twelve Standard/Gentle and immediate/grid-center routes, with exact managed-picture pins, serialized suspended prefixes, full replay and resumed suffixes. These checks do not qualify a real browser, physical controls, visual quality or human difficulty.

## Three authenticated inputs

`prepareExternalChapter(descriptor, {pack, media}, {decodeImage, signal})` snapshots the bounded descriptor and native payload Blobs before asynchronous work. The descriptor pins complete gameplay/media bytes and SHA-256, source-pack provenance, authored campaign identity and exactly three full poster mappings. Source-pack fields describe compilation provenance; installation does not authenticate authorship or licensing. The compiler separately requires the exact recorded source-pack hash.

The gameplay payload must be a separate three-map, one-theme Classic v5 edition with empty `visualOverrides`/`levelVisuals`, no dependency and no embedded picture. The ordinary pack validator remains authoritative for rules, roster, identities and existing budgets. Complete `.rlmedia` parsing verifies every original hash, header and decode. The retained owner is re-prepared against the exact resolved gameplay campaign, including materialized defaults, rather than trusting a campaign-name match. Each asset/presentation/assignment must match its full level/revision/theme pin, byte facts and contain/nearest layout. No extras, missing originals, altered mappings, or implicit current-assignment fallback qualify. Only the module's prepared capability can be installed or recovered.

The pilot's additional limits are deliberately narrow: descriptor 16 KiB, lightweight gameplay payload 1 MiB, exactly three posters. Existing per-image 4 MiB, 1920×1080 poster, media metadata 2 MiB, 256 MiB committed-plus-staging, 512 physical originals, four leases and 15-minute expiry remain enforced by existing modules. Existing pack 24 MiB / installed library 48 MiB / twelve-pack bounds remain unchanged. A prepared lightweight payload is not proof that an occupied store has staging headroom.

## Existing databases and explicit host capabilities

`createExternalChapterPointerStore` opens only the existing `revealline-assets-v1` database at version 1 and its existing `assets` store. It binds one exact `dev`, `release-N.N.N` or `release-vN.N.N` profile/packs channel using the existing bounded version spelling. It preserves the literal `v` and refuses mismatched profile/packs variants. The new index key is `${profileKey}.external-chapter-index.v1`. Its at-most-twelve descriptors consume the same 48 MiB installed budget together with pack JSON, and cannot claim missing or changed installed gameplay bytes. The new journal key is `${profileKey}.external-chapter-journal.v1`; existing backup journal and lock keys remain separate. A native readwrite transaction compares the complete prior pointer, descriptor index and journal, then publishes the changed pack pointer, descriptor index and journal phase together. A failed write rolls the whole transaction back. It never writes profile, suspended flight, Collection, media or unrelated asset keys.

`createExternalChapterInstaller` borrows the **same compatible managed manager** used for current audio/still domains; it creates only a borrowing still adapter and never owns/closes the supplied manager. A future shared story-v4 manager can supply this unchanged still interface. This slice does not choose, open or adopt a different media schema. The caller supplies its actual held profile-writer lease, Web Locks, localStorage reader and complete registered base-catalog entries. Missing capabilities, a released writer, occupied backup lock, backup marker or pending backup journal refuse the operation. Model tests use actual `claimProfileWriter` with a finite Web Locks boundary.

The coordinator validates the whole future pack library and resolved base/installed catalog before the first journal write. Existing pack/campaign identity replacement is refused. Existing historical media with the new identity is not assumed absent merely because its pack is absent: every required resulting full poster assignment is checked after the existing preserve merge. A conflicting retained choice refuses rather than being replaced. Unrelated pack bytes, assignments, original history and shared media remain retained.

## Publication and recovery

These databases cannot share one physical transaction. The implementation provides a **journaled, cooperative publication protocol**, not global atomicity against arbitrary archived or nonparticipating writers.

| Durable state                                                                                                 | Required recovery evidence                                                   | Action                                                                            |
| ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Original pack pointer; journal `prepared`; original media generation/hash                                     | Exact reviewed descriptor/payloads and re-derived before/after library/media | Reserve existing shared staging budget, CAS-commit media, continue                |
| Original pack pointer; journal `prepared` or `media-committed`; exact new media generation/hash               | Verify all actual original bytes/header/decode and required poster bindings  | Finish media marker and publish pointer, index and `published` journal atomically |
| Exact new pointer; journal `published`; exact new media generation/hash                                       | Revalidate actual media and full pointer/journal                             | Clear this journal only; report installed                                         |
| Any foreign pointer, generation, metadata, corrupt/missing original, malformed phase or mismatched descriptor | No guessed interpretation                                                    | Refuse and retain journal plus originals for explicit review                      |

The journal contains an operation UUID, exact profile keys, source descriptor, complete old/new raw pack pointers and descriptor indexes, and media before/after hashes plus generation. Recovery derives the next library again from the old pointer and exact prepared edition; a journal is never sufficient authority to install an arbitrary after-pointer. JSON bounds apply before use.

Media commits first through the real manager reservation and generation CAS. The pointer/journal is checked again immediately before that commit. A full media read verifies actual originals before pointer publication and again before clearing the journal. Every pointer transition compares exact current records inside its native transaction and checks current writer/backup-marker/abort state. An interruption or cancelled result retains the journal; already committed originals remain counted and available. No recovery path deletes originals or blindly rolls back another writer. Reservations are released best-effort or expire under existing limits. Reported quota refusal preserves the old media/pointer and leaves a resumable prepared journal.

A successful final transaction remains success if cancellation arrives after that transaction has committed. A cancelled earlier phase reports no completed install. There is no automatic cleanup of an ambiguous operation and no automatic resume following Reload. Recovery explicitly requires the same authenticated payloads.

**Required future host gate:** inspect this journal before exposing the optional edition, at startup, pack reconciliation/`canAdopt`, launch/Choose and every relevant backup/restore path. The existing page-local pack coordinator alone does not provide this gate. Future host integration must route pointer writes through this CAS protocol and reconcile only after successful completion. It must preserve an unrelated paused run and keep Choose separate. This slice does not wire any of those consumers; importing its small gameplay JSON directly through an old pack importer cannot restore its original artwork.

Different profile channels can have different writer leases while sharing media. A media writer can act between cross-database checks, or legitimately change availability after a completed install. A detected change keeps the journal for review; no global immutable-publication claim is made. Actual host/browser multi-tab qualification remains required before adoption.

## Existing-user migration and backups remain separate

The pilot never removes/replaces an embedded edition, frees its library slot, converts legacy picture choices, edits old saves/earned records or redirects old campaign identities. Side-by-side installation of a new identity does not migrate the old identity. Existing-user migration must first define a versioned retained-source record containing authenticated complete old pack JSON and exact artwork mappings, counted in the existing managed budget, plus an old-source resolver that survives restart/removal. An actual old unfinished save and earned A must continue to resolve A after new assignment B. If retention or resolution cannot fit or be proven, keep the embedded edition.

Current game JSON, `.rlmedia` and `.rlsound` exports retain their existing scopes. The install descriptor and gameplay JSON are not a complete originals backup. The compiler emits a complete paired `.rlmedia` for this chapter, but coordinated profile/media backup and recovery across the new journal are **not wired**. Native picker/download, real fresh-origin recovery, old save/Collection preservation, shared story-v4 adoption, server-stopped new-tab playback and all-five capacity acceptance are follow-up gates. No claim of shipped installation or freed user storage follows from these source tests.
