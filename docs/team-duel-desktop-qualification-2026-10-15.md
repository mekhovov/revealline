**Measurements and their limits.** An explicit control arms a thirty-second sample. Recording begins only after the operator starts or resumes real foreground play. Pausing, finishing, changing missions, losing focus, hiding the page or navigating discards the active sample; an unused arm expires after sixty seconds. The deadline rechecks these conditions even when a timeout runs before the next animation frame. The observer does not accept a menu sample as active play.

Each completed sample retains:

- Actual animation-frame intervals: median, p95, p99, maximum, and counts above 33.34 ms and 50 ms. These measure browser scheduling, not isolated CPU rendering or GPU execution.
- Browser-reported long tasks when supported; unsupported counters remain unavailable.
- JavaScript heap counters before and after when the browser provides them, with the actual user agent, logical CPU count, viewport, pixel ratio and page URL.
- Canvas dimensions and a four-byte-per-pixel backing estimate, visible DOM-image dimensions and their pixel estimate, and image resource-body bytes. These are distinct quantities; compressed image bodies are not decoded memory.
- Gameplay-key counts for each seat, separated by native trusted and untrusted events, plus bounded half-second HUD observations. No arbitrary text or text-entry keys are recorded.
- Navigation, paint, resource and ready-menu observations. Ready timing ends after two consecutive animation-frame observations; it is not physical input latency or isolated asset-decode duration.

Discarded or expired samples also retain read-only outer/embedded document focus and visibility, active-control identities, access/tool readiness, Start/Resume and dialog flags, and up to 32 focus/activation events. Failed Start timing preserves whether its activation was native/trusted and the focus state at that exact event. This distinguishes a visible but unfocused embedded browser from a running field without bypassing either game's foreground guard. A targeted regression verifies that an unlocked, ready, visible host with an enabled Start but `document.hasFocus() === false` records zero active frames and a discarded sample.

A native Team readiness diagnostic found an observer false negative: desktop CSS uses `display: contents` on `#coop-play`, so that wrapper has no layout box even while its canvas is visible and both pilots are playing. The observer now checks the actual canvas while retaining hidden/inert ancestor, enabled Pause and absent-overlay checks. The fixture models the real no-box wrapper and rejects a hidden canvas, inert ancestor and paused overlay. The original expired diagnostic is not counted as a performance sample or a runtime failure.

Complete decoded-image, decoded-audio and GPU memory are **not exposed by these browser counters**. The receipt says so explicitly. Off-DOM textures, internal copies, compositor surfaces and driver allocations are not silently treated as zero. The observer adds a small amount of frame polling and bounded DOM-reading overhead; the report makes no cross-device or sustained FPS certification claim.

**Native observation procedure.** Serve the ordinary source tree and open `/docs/verification/journey-performance.html`. Choose Team or Versus, one of the three named finales, and “Next 30 seconds of foreground play”; then choose “Load review game.” Use the normal access flow and keep English selected for the current Duel status-label guard. Wait for native setup to be ready. In Duel, `library-intent=select` reveals the requested library row but deliberately does not adopt a new runtime until that row's explicit Play action. Confirm the actual field title/objective before sampling; a requested URL alone does not establish the played mission. If preparing a row starts the game, pause it before arming. Choose “Observe 30 seconds,” then Start/Resume in the embedded game and operate both players normally. Preserve the complete JSON log and a screenshot of the visible native field. A discarded sample is evidence of interruption, not a passing measurement.

Keep compilation, package builds and other heavy activity stopped while timing. Use the same browser, viewport, effects settings, artwork and input sequence for any baseline comparison. Repeat anomalous samples after resolving their identified cause; do not remove slow frames merely because they are inconvenient. A fresh browser navigation is not proof of an OS-level cold cache. Source-candidate measurements are not a substitute for the final public/offline distribution checks owned by R8.

For desktop lifecycle observation, press each player's movement controls, pause, resume, move focus to another tab, return, and verify explicit Resume remains required. Check that neither seat inherits a held direction after the boundary. Repeat after a paused Help/settings visit and verify visible keyboard focus reaches the intended return action. Browser-host fixtures test corresponding state and input boundaries; they do not establish actual hardware or assistive-technology behavior.
