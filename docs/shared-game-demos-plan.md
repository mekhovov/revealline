## Agreed scope retained

One common demo framework covers Solo, Snake Solo, SIM, and FPV Survival at standard authored setups, including each supported SIM flight mode. It preserves complete real performances, current-mode entry after 60 eligible idle seconds, balanced random **Watch all modes**, isolated practice, ordinary guarded Ready launch, and player persistence/preferences. Team/Versus, Raid, prototypes, free flight, editors, custom combinations, and new personal-recording collection outside Solo remain excluded. Public deployment remains a separate step.

## Confirmed gaps and concerns

1. **Deadline enforcement — acceptance blocker.** A timer callback can be delayed by synchronous work. The current helper may accept the result before the overdue callback runs; the director has the same aggregate-budget risk and must count synchronous retirement. The retained reproduction accepted a result after about 25.5 ms despite a 5 ms budget. Implement monotonic elapsed-time checks before attempts/adoption and retire overdue results. The proposed five deterministic cases were evaluated in memory only; no repository fix or repository test run exists yet.
2. **Qualification harness cleanup — unfinished reliability fix.** Browser setup sits outside the main cleanup guard. Failed body/screenshot diagnostics can hide the original failure; a failed report write can prevent browser closure. Add atomic report replacement, independent cleanup, bounded diagnostics, and fault-injected tests. The proposal is documented but unapplied. Temporary agent-store copies did not survive the environment reset, so both patches must be reconstructed from the retained design rather than assumed to exist on disk.
3. **Survival loading — unresolved cause.** Four distinct sources reached 15–16 second preparation deadlines during the partial rotation. They recovered, with no observed page errors, but the cause is unconfirmed. A two-scene isolated probe completed in 3.5–3.9 seconds and did not reproduce the issue. Catalog playback timings exclude complete renderer startup. Add bounded stage/candidate timing, reproduce through the shared host, and verify recovery stays within the total budget. Do not attribute this conclusively to disk pressure or competing jobs. A bounded recovered failure is not automatically a release failure, but repeated starvation, budget violations, or leaked owners are.
4. **Replay diagnostic precision — original-plan gap.** Sparse hashes provide a first bad checkpoint, not the exact first divergent tick. Exact diagnosis needs a trusted per-tick reference for the same recording/runtime variant or an offline reference-engine comparison. Binary search alone is insufficient if states later reconverge. Keep exact-tick diagnosis as unfinished scope; do not silently substitute checkpoint precision. Snake's current wording also overstates what is known. Preserve the existing five-second checkpoints and full verifier while designing the additional diagnostic path and checking its data/package costs.
5. **Endurance — missing acceptance evidence.** The 89.2-minute run exited during observed disk-full conditions; its exact termination cause was not captured. It used the pre-correction host/CSS and has no final cleanup/storage result. Old partial runs cannot be summed or topped up to meet two hours. Start a new uninterrupted run after the final runtime is frozen.
6. **Integration and publication — unfinished delivery.** The work is not rebased onto current main, committed, pushed, or attached to a PR. A clean textual preview does not replace tests. Preserve the generated `flight-fullscreen.mjs` changes: its `addHomeActions`/navigation projection is required by this feature, not unrelated work to exclude.
7. **Storage and execution stability — current risk.** Space is available again but changed substantially during this review. Confirm adequate headroom before heavy work, monitor it during the soak, and preserve an incomplete report on interruption. Do not delete other worktrees or user files to create capacity.
8. **Human/device review — external dependency.** No unfamiliar reviewer or physical controller/radio/mobile/audio observations are recorded. Headless keyboard tests, narrow viewports, and synthetic input cannot satisfy those checks. Availability and scheduling are unknown.

The standalone SIM download intentionally omits the shared demo bridge/corpus to retain its existing package limits; its demo actions stay hidden and ordinary flight remains available. This distribution limitation is documented and tested. It should remain explicit in release notes.
