## What GPT can contribute later

The current [OpenAI audio guide](https://developers.openai.com/api/docs/guides/audio) documents conversational voice, transcription, translation and speech generation. The [model catalogue](https://developers.openai.com/api/docs/models/all) describes the audio models as voice/audio products; neither page establishes a dedicated, production-ready full-song music-generation workflow. This is a documentation finding, not a claim that a text model cannot help write a score. No paid API, external generation service, model weights or sample library was used for this investigation.

GPT-authored notes and synthesis code are not equivalent to a professionally arranged recording. The user’s report is a musical rejection; no measured transport drift has been established from that feedback alone.

If original work resumes, use one inspectable score and one tempo/meter map in a real sequencer. Start with an eight-bar drum-and-bass groove; approve its accents and rests before adding a single lead. Keep counterlines subordinate, audit chord changes and note lengths together, and use section-level variations rather than independent competing loops. Audition that small arrangement before extending it. Full-song production requires a musician’s arrangement review, believable guitar articulation for metal, and Ukrainian musical review where relevant.

[BeepBox](https://www.beepbox.co/) offers compact browser-based instrumental sketching and an offline edition. [OpenMPT](https://openmpt.org/features) offers tracker composition and plugin support, with documented [audio export](https://wiki.openmpt.org/Manual%3A_Saving_and_exporting). These are possible future authoring routes, not installed tools or a promised quality fix. Do not resume rendering merely because a different tool is available.
